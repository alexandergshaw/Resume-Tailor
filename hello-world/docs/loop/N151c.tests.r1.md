## In-memory supabase insert fake — CONFIRMED + EXTENDED

The T5/T7 integration needs a `generated_resumes` INSERT (append) + `position_id` filter + a
working storage upload so `docx_path` is set. The shared `test/helpers/supabaseFake.js`
(`makeStatefulSupabase`) already modelled insert/update/select/.eq/.order/.limit (so append +
position_id read + newest-first ordering all work), but its storage modelled **download only** —
`saveGeneratedResume`'s `.upload(path, bytes)` then `.update({docx_path})` sequence would have been
silently swallowed. I EXTENDED the fake's storage (the brief authorises this) with `upload`/`remove`
backed by a single mutable object map that `download` reads from, plus a `storedBytes(path)` reader
so a test can decode the stored .docx a regen wrote. Purely additive; the fake's own 68-test suite
still passes, and the N151a/b `templateMarkToActive.integration.test.js` still passes against it.
The local `makeMemoryClient` in the N151a/b test has no `.limit`, so it could NOT drive
`fetchDocumentVersions` — `makeStatefulSupabase` is the right instrument and is what the integration
file uses.

### Intents
- **docxBytes** — the shared `bytesToBase64` round-trips a multi-chunk (>0x8000) array against an
  INDEPENDENT decoder (Node base64, not the sibling `base64ToBytes`); + a source-text ADOPTION guard
  that `coverDocxStore` imports it and no longer defines it (CT-13).
- **templateLibraryStore.bytesById** — `getTemplateBytesById` returns an OWNED template's bytes; a
  foreign/absent/empty/kind-mismatch id → null. Owner-guard teeth: a user-2 id returns null for user-1.
- **route.bytesById** — `GET ?kind=&id=&bytes=1` returns docx bytes with a wordprocessingml
  Content-Type (not JSON); null→404; userId from session not query; the `?kind=` metadata GET is
  unchanged and never reaches the by-id read (branch-ordering guard).
- **templateLibraryClient.fetchFile** — `fetchLibraryTemplateFile` returns a docx File on a
  wordprocessingml 200, null on non-docx/non-200/empty/throw. Trust teeth: a non-docx 200 → null.
- **regenerateIntoTemplate** (UNIT, injected deps) — the chosen template's FORMATTING (a run font,
  never a content string) reaches the persisted docxB64 with all content lines; the RESUME/COVER
  scope payload is correct; the §C-2 content formula (`result || lines.join`) is non-empty for an
  empty-result/populated-lines entry; NO `/api/tailor` fetch; the OR-3 guard returns `{error}` and
  does not persist when signed-out or no positionId.
- **regenerateIntoTemplate.integration** (HOOK, real persist/version machinery over the stateful
  fake) — this is BOTH the no-deps DI wire test AND the integration: history grows by EXACTLY 1, the
  older row is untouched, the new row becomes current and carries the chosen template's font in its
  stored bytes; empty-result-still-appends end to end; wrong-scope leaves the other table empty;
  reads the CURRENT entry after a version switch (not a stale closure); OR-3 → no append; selecting
  back is non-destructive + idempotent.
- **switchTemplateControl** (MOUNT, real DocumentPreviewDialog) — the control renders on resume+cover,
  absent on email; is a SIBLING of DialogActions (not inside `.MuiDialogActions-root`), named
  "Switch template…" never "Regenerate" (F12); disabled-with-reason when signed-out or no versions
  (OR-3), enabled otherwise; opens a picker (library list + `.docx` upload input); a library pick →
  `fetchLibraryTemplateFile` → `onRegenerateIntoTemplate(tab, File)`; a `.docx` upload → regen
  directly with nothing POSTed to the library (OR-4); a non-docx upload refused in-control.

  the integration "signed-out → no append" test does not independently kill the OR-3-guard mutant
  (persist's guard masks it). The MODULE `T8-UNIT` tests are what pin the OR-3 `{error}` return for
  the signed-out case. Both instruments are kept; this is instrument overlap, disclosed.
- **5 green-on-HEAD tests** are intentional controls/guards, not coverage:
  route metadata-unchanged + skip-by-id + 401 (backward-compat), and the mount email-absence +
  census-count guard (F13). The mount email-absence and census-count guards pass **vacuously on
  HEAD** (the control is absent everywhere) and only gain power post-impl; they are the regression
  guards for "absent on email" and "outside the action bar". Disclosed per the standing rule.
- **Docx VISUAL fidelity** (does template X's font/section render correctly around poured content) is
  browser-gated → OWNER CHECK (design §7). The tests assert a FORMATTING marker survives + all
  content lines appear, with the engine font as the negative control; a failed render is INVALID,
  not a pass.
- **Client trust-any-200 and route branch-ordering mutants** were proven satisfiable (green on the

  structured as the §F silent-failure instruments (non-docx → null; bytes branch returns docx not
  JSON).
- **BL-A** (live `generated_resumes.docx_path` / `resumes` bucket / `resume_templates`) is still
