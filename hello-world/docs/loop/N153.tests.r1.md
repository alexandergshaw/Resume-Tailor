## Production symbols the implementer MUST create (exact)

- **NEW `lib/copilot/prefetchQueue.js`** exporting `PREFETCH_CONCURRENCY` (=== 3),
  `createPrefetchQueue({ concurrency })` and the shared singleton `copilotPrefetchQueue`. The queue
  object exposes `enqueue(key, run)`, `activeCount()`, `pendingCount()`. Concurrency-bounded;
  queue-layer dedupe on `key` (waiting OR in flight), released when the task settles; `enqueue`
  ignores a falsy key or non-function run; a rejected task must not escape.
- **NEW `app/copilot/useWarmOnMount.js`** exporting `useWarmOnMount(warmKey, warmFn)` — fires `warmFn`
  once per distinct non-empty `warmKey`, reading the latest `warmFn` via a ref so a re-render (store
  write) never re-fires it; firing effect dep array is exactly `[warmKey]`; a null/empty key is a no-op.
- **`useAnswerExpansions` api** gains `keyFor(line) -> string|null` and `prefetch(line) -> void`
  (routes through `copilotPrefetchQueue.enqueue`, calls `beginExpansion({key,request}, fetchExpansion)`;
  never sets `open`). `toggle`/`retry` keep calling `beginExpansion` DIRECTLY (queue bypass).
- **`useTechTermDetails` api** gains `keyFor(term)`/`prefetch(term)` (mirror, no outcome reporting),
  plus `loggedRef` + `reportWhenSettled`; the detail-outcome log moves from the old `pending.then`
  issue-gate to the candidate's FIRST user-open, deduped per key (ruling L1).
- **`ExpansionPanel.js`**: above the early returns, `useWarmOnMount(keyFor(line), () => prefetch(line))`
  via the resolved api (optional-access, so stand-in apis without the methods are a no-op).
- **`AnswerAids.js` `TechTermChip`**: same warm hook at the top of the component.
- **`app/api/copilot/answer/expand/route.js`** and **`.../tech-term-detail/route.js`**: remove the
  limiter — `createRateLimiter` decl, the bound step, `RATE_LIMITED_MESSAGE`, and the now-unused
  `createRateLimiter`/`identify`/`rateLimitHeaders` imports.

**exportReachability note for the implementer:** both NEW modules need a shipping (prod) importer
in-wave. `prefetchQueue.js` is imported by the two scope hooks; `useWarmOnMount.js` by `ExpansionPanel.js`
and `AnswerAids.js`. No test imports either without a prod importer, so the sweep stays green — but the
implementer must land the prod wiring in the same wave or the census reds.

## RULED test changes (beyond the brief's named list) — a design finding

The design §11 listed **`app/copilot/AnswerLines.expansion.test.js` as CHECKED-SAFE**. That is WRONG for
its Section G ("through the real hook"), which mounts the REAL `ExpansionScope` and contains an explicit
`"does not prefetch: a rendered answer issues zero requests"` assertion — the exact "no fetch on render"
case the brief warned about, which the feature directly inverts. I adopted Section G as a ruled change
(authorized by the brief's unknown-resolution clause and the cap/prefetch owner rulings). Similarly the
design listed `AnswerAids.collapsible.test.js` as ADOPTED but did not note its A7 fetch-count; I handled
it. **The 4b checker/implementer should note §11's CHECKED-SAFE row for AnswerLines.expansion.test.js is
inaccurate.**
