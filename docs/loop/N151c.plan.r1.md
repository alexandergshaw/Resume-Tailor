## B. The design's one hand-rolled step is REPLACED by a stronger reuse

Design §2 step 3 says to call `resolveDocumentBlob({text, lines, edited:true, formattingTemplate})`
directly. The repo already has the single byte-path choke point that does exactly this for BOTH
scopes with the correct per-scope field names and edited/textChanged logic:

- **`buildPreviewBlob(entry, scope, { formattingTemplate })`** (`previewBlob.js:146-149`) →
  `previewBlobArgs(entry, scope, { formattingTemplate })` (`:92-141`). The resume branch reads
  `result`/`resultLines`/`docxB64`/`docxPath`; the cover branch reads
  `coverLetterResult?`/`coverLetterResultLines`/`coverLetterDocxB64`/`coverLetterDocxPath`
  (`:97-140`), and only adds `formattingTemplate` to the args when truthy (`:117`, `:139`).

**Decision (mechanism, mine):** `renderContentIntoTemplate` calls `buildPreviewBlob(entry, scope,
{ formattingTemplate: templateFile })`, NOT a bare `resolveDocumentBlob`. Rationale: one byte path
(the wiring test at `useDocumentPreview.wiring.test.js:131-137` deliberately pins that
`resolveDocumentBlob(` lives ONLY in `previewBlob.js`, not the hook); and `previewBlobArgs` already
encodes the subtle resume `defaultText = result || lines.join("\n")` vs cover formulas that a
hand-roll would get wrong. This is strictly less code and less risk than the design's step 3.

## C. Contradictions / open mechanism choices routed to this seat — RESOLVED

1. **Position id source for the persist.** Design §2 step 7 says `positionIdRef.current`; the
   resubmit block it reuses (§F5) does a fresh `positions.select("id").eq("external_id",…)` lookup
   (`:716-721`). **Choice: use `positionIdRef.current`** (set at `:141` by `refreshDocumentVersions`,
   which runs on modal open). It is the exact value the OR-3 gate checks, so the gate and the write
   agree by construction; it avoids a redundant round-trip and a race where a fresh lookup disagrees
   with the gate. Proven present: `selectDocumentVersion` already reads `positionIdRef.current`
   (`:265`) for the same reason.

2. **Persist `content` formula.** `scopeText(entry,"resume")` returns `entry?.result || ""`
   (`previewBlob.js:64`) — if a loaded entry had an empty `result` but populated `resultLines`,
   using `scopeText` would hand `persistGeneratedDocuments` an empty `content`, and
   `saveGeneratedResume` skips the insert when `!resume.content` (`persistGeneration.js:56`) → **a
   silent no-append**. **Choice: build persist `content` with the `result || lines.join("\n")`
   formula** (resume) / `coverLetterResult || coverLetterResultLines.join("\n")` (cover) —
   `previewBlobArgs`' own `defaultText` (`previewBlob.js:129`). `contentLines` = the scope's current
   lines array. (This is a module-internal helper, §D.)

3. **OR-3 reactive disable signal vs the load-bearing gate.** `positionIdRef` is a ref (not
   reactive), so the dialog cannot disable off it directly. **Choice: two layers.**
   - *Load-bearing (headless, non-silent):* `regenerateActiveIntoTemplate` itself returns
     `{ error }` without persisting when `!currentUser?.id || !positionIdRef.current`. This is the
     guarantee against a silent no-append and it is node-testable (T8-UNIT).
   - *UI affordance (OR-3 disabled-with-reason):* the dialog disables the control on the reactive
     proxy `Boolean(currentUser?.id) && Boolean(documentVersions?.[tab]?.length)`. When signed-out
     or no position, `refreshDocumentVersions` returns early (`:142`) and `documentVersions[scope]`
     stays empty, so the proxy is false exactly when the handler guard would refuse. Blind spot
     (documented, benign): a position with zero generated rows disables the control — but then there
     is nothing to reformat, so disabling is correct. `currentUser` is already threaded to the Mount.

## D. The line-budget sizing (CT-12 — the hard constraint)

Hook is **921**; ceiling **<935** → **13 lines of headroom**. A naive inline wrapper (guard +
`buildPreviewBlob` + encode + display `updateTailoringJob` + `setPreviewReloadKey` + persist +
refresh) is ~28-35 lines and **breaches**.

**Chosen shape (keeps the hook thin AND resubmit untouched):** put the entire orchestration in
`lib/document/regenerateIntoTemplate.js` as an **injected-deps** function, so the hook adds only a
thin binding wrapper.

Module export:
```
// lib/document/regenerateIntoTemplate.js  (NEW, pure of React; node-testable with mocks)
export async function regenerateActiveIntoTemplate({
  scope, entry, templateFile, jobId, positionId,
  userId, supabase,
  updateTailoringJob, setPreviewReloadKey, persistGeneratedDocuments,
  refreshDocumentVersions, versionsRequestId, sourceResumePath,
}) -> Promise<{ ok: true } | { error: string }>
```
Internally, in order (design §2 steps 3-7): guard (`userId && positionId` else `{error}`) →
`const docxB64 = await renderContentIntoTemplate({ scope, entry, templateFile })` →
if `!docxB64` return `{error}` → `updateTailoringJob(jobId, (e) => ({ ...e, ...regenDisplayPatch(scope, docxB64) }))`
→ `setPreviewReloadKey((k)=>k+1)` → `await persistGeneratedDocuments(supabase, { userId, positionId,
[scope==="cover"?"coverLetter":"resume"]: regenPersistPayload(scope, entry, docxB64),
sourceResumePath })` → `await refreshDocumentVersions(jobId, [scope], versionsRequestId, positionId)`
→ `{ ok: true }`.

Module-internal helpers (all pure, all in the new module; import `withEditedScope`, `scopeText`
from `previewBlob.js` which exports them — `:40,49,59`):
- `renderContentIntoTemplate({ scope, entry, templateFile })` → `buildPreviewBlob(entry, scope,
  { formattingTemplate: templateFile })` then `bytesToBase64(new Uint8Array(await blob.arrayBuffer()))`;
  returns `""` when no blob/content.
- `regenDisplayPatch(scope, docxB64)` → resume: `{ docxB64, docxPath: "", resumePreviewHtml:
  undefined, edited: withEditedScope(entry,"resume",false), status:"done" }`; cover: the
  `coverLetter*` field set (`coverLetterDocxB64`, `coverLetterDocxPath:""`,
  `coverLetterPreviewHtml:undefined`, `edited: withEditedScope(entry,"cover",false)`). Mirrors
  resubmit's writes at `:652-663` (cover) / `:679-691` (resume) **minus** the engine fields.
- `regenPersistPayload(scope, entry, docxB64)` → `{ content, contentLines, docxB64 }` using §C-2's
  formula.

Hook wrapper (the ONLY hook edit — ~6-8 lines) reads the LATEST entry via
`tailoringMapRef.current[resumePreview.jobId]` (not the stale `tailoringMap` closure — resubmit does
this at `:818`), binds its own `updateTailoringJob`/`setPreviewReloadKey`/`persistGeneratedDocuments`/
`refreshDocumentVersions`/`versionsRequestIdRef.current`/`positionIdRef.current`/`createClient()`/
`currentUser.id`, calls the module export, returns its result, and is added to the return object at
`:902-920`.

**Projected count:** 921 + 1 import + ~7 wrapper = **~929 < 935** (≈6 lines margin). If a measured
post-edit `wc -l` lands ≥935 (step 6 instrument), the sanctioned fallback is to extract the resubmit
persist+refresh block (`:705-745`) into a hook-internal helper shared by resubmit and the wrapper
(design §3.2; RETRO R2/N138), which **shrinks** the hook by ~38 lines. The injected-deps shape is
preferred because it needs no edit to the concurrency-sensitive resubmit path.

**NOT doing (out of scope this chunk):**
- No provenance/`formatting_template_id` column and **no migration** (OR-1 DEFER). The regen version
  is distinguished only by its timestamp in `VersionControl` — no "via <template>" label, because
  there is nowhere to read a template name from without the column.
- No auto-add of an uploaded template to the library (OR-4 TRANSIENT). The File flows straight into
  the regen; nothing is stored.
- No "temporarily select X then read active bytes" shortcut (design §3.1 rejected — it mutates the
  user's persistent selection as a side effect of a one-off).
- No change to `resolveDocumentBlob`/`buildDocxFromUploadedTemplate`/`buildPreviewBlob` signatures,
  the four N97 consumption surfaces, or the default/selection routes.
- No edit to the resubmit persist block unless the measured `wc -l` forces the §D fallback.

**Must stay OPEN for a queued follow-up (do not foreclose):**
- **Labeled history / "re-apply template to new content"** — the OR-1 provenance column. S1-S7 must
  leave `saveGeneratedResume`/`fetchDocumentVersions`/`VersionControl` signatures untouched so the
  additive column (nullable `formatting_template_id uuid null → resume_templates(id) ON DELETE SET
  NULL`, stamp `> 20261008010000`) threads cleanly later.
- **"Also save this uploaded template to my library"** opt-in — reuse `registerTemplateFromBytes`
  (N151a, already in the client). The S7 picker's upload path should keep the uploaded `File` in hand
  so a later opt-in control can post it without re-upload.
