## 2. Why the answer drifts into an example (so the directive lands where it can work)

Five pressures, all verified above, all pointing the same way:

1. `POINTS_SYSTEM:97` — "ground the points in [the background]... reference their real companies, projects, metrics" — unconditional on question shape.
2. Descriptor emphasis "concrete examples" in every `general` user prompt (`interviewTypes.js:39`).
3. Pages instruction — name the project, prefer its detail (`:302-309`, `:448-455`).
4. **Answer mode, `general`/`leadership`/`behavioral` formats: "Shape it as a STAR narrative" regardless of the question** (`:366-369`). This is a literal instruction to narrate a past story and is the strongest single push in answer mode for the default format.
5. Nothing anywhere tells the model that a question asking "how would you / what is your view / why this role" is answered by stating the approach/position/reason first. (The `technical` and fallback shapes do say so — "state the approach first", "lead with the point, then the concrete evidence" — `:371`, `:376` — and the gated role-term line says "Lead with the role-relevant capability ... substantiate it ... in the points that follow", `:320-325`, `:463-468`. **What this chunk addresses and what it deliberately does not (decision D-1, §8):** the directive goes in the two SYSTEM constants, as the owner and backlog scope it. Pressure 4 lives in a USER-prompt builder; touching it changes `FROZEN_ANSWER_PROMPT_NO_PAGES` and the pinned `answerShapeInstruction(GENERAL)` behavior, which the backlog says to leave alone ("do NOT change ... the STAR/behavioral behavior beyond adding the direct-answer framing"). So `ANSWER_SYSTEM` carries one explicit precedence sentence (§3.2) instead, and Option B (§8) is pre-written but NOT in scope.

## 3. The directive — EXACT text, ready to paste

Design choices, then the strings.

* **Both system prompts, not one.** Live mode (points) and practice mode (answer) draw drift from the same sources (pressures 1-3, 5) and the route selects between the constants at three call sites. A directive in one leaves the other mode unchanged.
* **A NEW array element in each, inserted immediately BEFORE the existing STAR element.** Nothing else in either array is edited — the `:97` grounding paragraph, the `:98`/`:128` STAR sentences, the `cues` element and the glance/skimmable element stay byte-identical. Consequences: the frozen oracle diff is a pure one-string insertion; `questionVocabulary.js:34` and its test comments stay true; the behavioral carve-out sits directly beside the STAR rule it exempts, so the pair (non-behavioral rule, behavioral rule) reads as one decision.
* **Positive phrasing only** (see §5 — three existing detectors constrain the wording).
* **Modal wording for the substantive answer** ("the approach the candidate WOULD take", "the position they WOULD argue for") so the direct answer is a stated position, never a claim of past work.

## 4. The behavioral carve-out — mechanism

* **How behavioral is distinguished: by the question's own shape, in the prompt's existing language, with no new classifier.** The exemption clause reuses the exact phrase both STAR sentences already use (`"tell me about a time..."`, `behavioral question`) and adds the functional test `asks for a specific past experience`. The route has no input classifier and none is needed (`type` is output-only, `route.js:123,302,774,899`).
* **What "exempt" means.** For an exempt question the directive's rule does not apply, so nothing about the existing behavior changes: STAR labels still come from the untouched STAR element; the "prefer a concrete story from YOUR OWN PROJECT PAGES" sentence at `:97` is untouched and still scoped to "tell me about a time..."; `cues` still carry the STAR label (cues element untouched).
* **Why the clause says "specific past experience", not just "behavioral".** A question like "Describe a complex Workday report you designed" has no "tell me about a time" in it but asks for a specific past thing; the functional wording exempts it, and the `:97` gap-handling (frame the closest thing, one clause on what they'd pick up, never open with the gap) then governs. A question like "How would you validate report accuracy in Workday?" asks for an approach, so the directive applies.
* **Classification is the model's judgment**, same as the existing STAR rule today. It is not decidable in jsdom (AC-N134-10, owner/real-env).
* **Borderline set, ruled so the checker does not re-litigate:** "Tell me about yourself" / "Walk me through your resume" ask for a self-summary, not one specific experience, so the directive applies (lead with who the candidate is and what they are strongest at, then support). Either treatment is acceptable provided no experience is invented; the AC does not hinge on it.

## 5. Guard-interaction analysis — no erosion, verified by execution

### 5.1 Guard 1 (the question is NAME / vocabulary, never EVIDENCE)

* The directive does not add or touch the licence-shaped sentence. `ANSWER_SYSTEM:126` (evidence register + vocabulary register) is untouched and still the second element.
* The directive's last sentence RESTATES the evidence rule in the same element as the position instruction: "what the candidate has done still comes only from the material provided below, and never from the question" (answer) / "still comes only from the background" (points). So "answer directly" cannot be read as a licence to assert unsupported experience — the cheapest compliance with "lead with the answer" for a question naming an uncovered system (assert "I built it") is exactly what that sentence forbids.
* The direct-answer slot is worded modally ("the approach the candidate WOULD take", "the position they WOULD argue for") so filling it never requires a past-tense claim.
* `LICENCE_PATTERNS` (`fabricationGuard.test.js:75-80`) return `[]` on both new constants (executed, §9).

### 5.2 Guard 2 (never OPEN with what the candidate hasn't done; paired with a truth condition) — and the reconciliation

"Lead with the answer" and "never open with the gap" do not conflict, because they constrain different things: the first point is a SUBSTANTIVE position (an approach, a stance, a reason), which is neither a disclaimer nor a claim of experience. The gap, when it exists, still lives mid-answer exactly where `:97` puts it ("in that same one clause, never as the opening line"). Worked shapes (illustrative of the intended structure, not model output):

| Question | Applies? | Point 1 (direct answer) | Support | Gap handling (unchanged `:97`) |
|---|---|---|---|---|
| "How would you keep custom Workday reports accurate?" (names a system the background lacks) | yes | "I'd validate at the source and reconcile totals against the system of record before anything is shared." — an approach, modal, in the interviewer's own vocabulary | closest REAL work from the background, e.g. a reconciliation the candidate actually did | one clause mid-answer: what they would pick up on Workday specifically; never the opening |
| "Why this role?" | yes | the reason | candidate's real trajectory; employer claims only from VERIFIED COMPANY FACTS per the existing rule (`:263-269`, `:277-280`) | n/a |
| "What's your philosophy on code review?" | yes | the position | one real example as support | n/a |
| "Tell me about a time you led a migration." | NO (exempt) | STAR story from the best matching page (`:97`) | — | `:97` as today |
| "Describe a complex Workday report you designed." | NO (asks a specific past thing) | closest real work, framed in the interviewer's name for it (`:97`) | — | one clause, never first |

**Important honesty note about detector coverage.** The existing guard-2 regex (`POSITION_RULE`, `fabricationGuard.test.js:87`) matches negative position rules ("never/do not/avoid ... open/begin/start/lead"). This directive is POSITIVE phrasing, so `POSITION_RULE` does not match it, and the existing guard tests therefore pass on it TRIVIALLY. That is not evidence the hazard is closed. The hazard the rejected-draft history actually teaches is: any rule about WHERE the answer starts needs a rule about WHAT MUST BE TRUE, because the cheapest compliance defeats the position rule by asserting experience. This directive mandates an opening, so it carries its truth condition inside the same element (last sentence of each text). The guard tests cannot see that sentence, so AC-N134-4 pins it directly and AC-N134-10 probes it in the real environment on the uncovered-system case.

### 5.3 Guard 3 (no mandate to name the term regardless of truth)

The directive mandates that the first point be the direct answer — not that it name or contain any term, and it uses no "must". `MANDATE_PATTERNS` (`:98-103`) return `[]` on both constants, including the pattern that bans "always lead/open/begin/start with" (the directive says "Leading with the answer", not "always lead with").

### 5.4 Three wording traps in the EXISTING tests that this design had to route around (all measured)

These are real constraints on any rewording; a later "improvement" that ignores them goes red:

1. **`ANSWER_SYSTEM` must contain NO `TRUTH_CONDITION` match.** `fabricationGuard.test.js:195-202` proves the guard "would catch a position rule on ANSWER_SYSTEM too" by APPENDING the rejected position-only rule to the real ANSWER_SYSTEM and expecting `positionRuleWithoutTruthCondition(...) === true`. If ANSWER_SYSTEM already contains a sentence of the shape `never (state|claim|assert|suggest) ... does not support`, that expectation turns false. So the truth tie in the answer text is worded "still comes only from the material provided below, and never from the question" (no `never claim ... does not support` shape).
2. **`POINTS_SYSTEM` must contain EXACTLY ONE `TRUTH_CONDITION` match.** `:182` strips the FIRST match with a non-global `.replace(TRUTH_CONDITION, "")` and expects the guard to fire; a second match survives the strip and the test goes red. The existing `Never state or imply that the candidate performed work the background does not support.` is that one match; the new points text does not add another.
3. **`ANSWER_SYSTEM` must contain NO `POSITION_RULE` match.** It has none today (that is why `:176` is vacuously true for it, per the file's own item-8 comment). A negative phrasing such as "do not start with an example" would add one with no truth condition and trip `:175-176`.

Executed proof that these constraints are real, not theoretical: §9, mutants M1-M4.

### 5.5 Verdict

No erosion of guards 1, 2 or 3: all 23 existing guard cases pass UNMODIFIED against the new constants (executed), the one-element insertion leaves every existing sentence — including `:97`'s whole grounding paragraph, the four named openings, and the truth condition — byte-identical, and the new element adds its own truth condition. Residual risk is behavioral, not textual (§8, R-2), and belongs to the owner probe.

## 8. Decisions, residual risks, out-of-scope observations

* **D-1 (OWNER/ORCHESTRATOR RULING, not blocking r1): Option B — neutralize the STAR-for-everything shape line at the source.** Evidence it is a real cause: §1 (`general` takes the STAR branch for every question; the repo pins it). * **R-1.** The directive only helps if the model reads a system-level instruction as outranking a more specific user-prompt line. Nothing in this repo can measure that. Hence D-1 and AC-N134-10.
* **R-2.** The truth-tie sentence is the only textual defense against "lead with the answer" being satisfied by asserting experience; the existing guard tests cannot see it (§5.2). It is pinned by AC-N134-4 and probed by AC-N134-10 on the uncovered-system case.
* **R-3 (accepted).** A first-person stated approach ("I'd validate at the source...") is the candidate's drafted position, not evidence. That is normal coaching practice and is why the directive is modal; it is not an experience claim and is outside the experience guards by their own definition ("an employer, a project, a metric, a credential, a tool they operated", `answerPrompts.js:126`).
* **O-1 (out of scope, observation).** Pressure 2 (the descriptor's "concrete examples" emphasis, `interviewTypes.js:39`) is shared with practice-question generation and critique; changing it is a separate design.
* **O-2 (out of scope, observation).** The expand route (`EXPANSION_SYSTEM`, `expand/route.js:241`) and the ask box (`ASK_SYSTEM`, `askPrompt.js:37`) have their own prompts and are not touched. The embedded engine (`answerLocal.js`, `sampleAnswerLocal.js`) is deterministic and has no LLM prompt, so the directive does not apply to it; its output shape is whatever it is today.
