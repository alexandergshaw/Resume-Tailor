## 1. RED-on-HEAD honesty (read before the criteria)

Because N157 is an entirely new feature, **almost every criterion below is RED on HEAD for the
trivial reason that its target does not exist** — the migration-shape test finds no table, the unit
test cannot import a module that is not written, the component test finds no component. That is
*vacuous-until-exists* red, and it buys nothing on its own. I mark each criterion with one of:

- **RED(behavioral)** — the criterion encodes a property that can fail *even after the feature is
  built the obvious way*. These are the ones worth the downstream seats' attention. The paradigm
  case is SAFETY-GROUND (§3): a client that runs `extract → isGrounded` and *skips* `resolve`
  compiles, passes a naive test, ships, and returns zero corroborated evidence forever — exactly
  the [[gemini-grounding-redirects]] trap. The breaking fixture must make that mistake go red.
- **RED(vacuous)** — red only because the target is absent; becomes trivially green the moment the
  obvious code lands. Still listed because the downstream seats need the target named, but it is
  **not** evidence of coverage. Where a criterion is RED(vacuous), the TDD seat (4b) must add the
  mutation/negative control that converts it to behavioral, named in the criterion.
- **GUARD(non-regression)** — protects an *existing* behavior from this chunk (e.g. the practice
  mode stays byte-identical when the new surface is absent). Green on HEAD by construction; it reds
  only if the chunk breaks something.

No criterion here is "a file contains string X." Where a sweep/census is the right instrument
(e.g. the fence adoption sweep) it is called out as an instrument with its own canary.

## 2. Decomposition into sub-capabilities and a proposed sequence

Four sub-capabilities. Each is independently testable; the orchestrator should treat these as the
candidate sub-chunk boundaries.

- **SC-A — Research pipeline.** Grounded web research of "what this interview will be like"
  (company / role / stage), producing a corroborated **evidence set** (claims each pinned to a
  resolved publisher URL) plus a refusal-honest empty result. Server-only; reuses the
  `companyFactsSource` corroboration order.
- **SC-B — Plan model + persistence.** A pure plan **schema/contract** (modules → topics → items,
  each item carrying a `new`/`review` kind, an optional `remediation` flag, and a provenance
  pointer back to SC-A evidence), plus per-user / per-application storage (new table, migration,
  RLS) and the walkthrough **progress** state.
- **SC-C — Interactive walkthrough UI.** The new practice-surface sub-surface (tab or mode — owner
  decision §7): renders a plan, walks the user through it step by step, spaced/interactive, mobile
  first. Its own component tree (NOT inside PracticeClient — §5).
- **SC-D — Customization controls.** Remediation on/off, new-vs-old ratio, and the rest of the knob
  set (§7 D-3), wired to plan generation and to the walkthrough scheduler.

**Proposed sequence (dependency-ordered; 1b/orchestrator may refine):**

1. **SC-B-schema first** (pure contract module + fixtures, no IO). Everything else builds to it; it
   is the cheapest thing to freeze and the one most expensive to get wrong. No dependencies.
2. **SC-A** and **SC-B-persistence** concurrently. SC-A depends only on existing grounding modules;
   SC-B-persistence depends only on SC-B-schema. Disjoint file sets ([[disjoint-subagents]]).
3. **Plan generation** (evidence → plan) — depends on SC-A (evidence shape) **and** SC-B-schema.
   This is where model-content QUALITY lives → owner/Gemini-env (§3 QUALITY, §7 D-2).
4. **SC-C shell** — the new surface rendering a *fixture* plan, with its own progress state and the
   mobile pass. Depends on SC-B-schema only, so it can land before plan generation is good.
5. **SC-D + spaced/interactive scheduling + progress persistence** — depends on SC-B and SC-C.

**Flag for the orchestrator:** this is a BIG feature; expect ≥3–5 sub-chunks. SC-A, SC-C and SC-D
each plausibly warrant their own AC/plan/TDD cycle. The schema (step 1) should be a tiny, fast
first sub-chunk precisely so the contract is checked before any seat builds on a guess.

## 3. Cross-cutting criteria (bind EVERY sub-chunk that touches the named surface)

### SAFETY-GROUND — grounded evidence never shows a redirect host, and corroboration is not bypassable
- **AC-N157-S1 [node-unit] RED(behavioral).** SC-A's research client, given a model response whose
  `groundingChunks[].web.uri` is a `vertexaisearch.cloud.google.com/...` redirect and whose claimed
  source URL is the real publisher URL, keeps a claim **only** via the order
  `extractGroundingSources → resolveGroundedSources → isGroundedUrl`. **Breaking fixture:** a test
  that stubs `resolveGrounded` to the identity (i.e. the resolve step removed) MUST go red — the
  claim must be dropped when resolve is skipped. Mirror of `companyFactsSource.js:128-177`.
  *Instrument exists* (the pattern + `companyFactsSource.wire.test.js` style); must be written for
  the new client.
- **AC-N157-S2 [node-unit] RED(behavioral). Failure direction:** the unsafe output is showing an
  unverified/redirect link **as** a verified source. Any URL the walkthrough or plan renders to the
  user as an evidence citation MUST be a resolved publisher URL that `isGroundedUrl`-matches the
  resolved grounding set; a raw `vertexaisearch` host MUST NOT be renderable as a live citation.
  (This is the `reconcileCitations` failure recorded in [[gemini-grounding-redirects]] — a link
  reading `acme.com` that 404s. The safe direction is: drop the citation, never show a dead/faked
  one.) **Breaking fixture:** a plan/evidence record carrying a redirect-host URL must render with
  the citation suppressed, not as an anchor.
- **AC-N157-S3 [node-unit] RED(behavioral).** Empty or missing grounding ⇒ **no evidence**, never
  "trusted by default" (`isGroundedUrl` returns false on empty; `companyFactsSource` returns `[]`).
  The plan generator MUST be able to produce an honest "could not research this" state rather than
  an unsourced plan. **Breaking fixture:** zero grounding metadata ⇒ evidence set is empty AND the
  resulting plan/UI is flagged unsourced, not silently populated from model priors.
- **AC-N157-S4 [node-unit] RED(vacuous→behavioral via wire test).** If SC-A issues its own grounded
  `generateContent` call, `tools:[{googleSearch:{}}]` lives **inside `config`**, pinned by a wire
  test that stubs `globalThis.fetch` and asserts the bytes, with a negative control pinning the
  top-level form as dropped ([[gemini-tools-nesting]]). If SC-A instead reuses an existing grounded
  entry point (digest / prep), this criterion is **satisfied by reuse** and the AC requires naming
  which entry point and that its wire test still exercises the path taken.

### SAFETY-FENCE — untrusted web/posting content is DATA, never instructions
- **AC-N157-S5 [node-unit] RED(behavioral). Failure direction:** the dangerous build concatenates
  scraped/posting/web text into `config.systemInstruction`. Every LLM prompt in SC-A and SC-C that
  carries scraped posting text, fetched web content, the company/role string, or any user free text
  MUST place it inside the repo's untrusted fence (`lib/llm/untrustedFence.js` /
  `<untrusted-data source=...>` + notice, per `askPrompt.js`), and `config.systemInstruction` MUST
  be a byte-identical constant across two calls with different content. **Breaking fixture:** call
  the prompt builder twice with different untrusted content and assert `systemInstruction` is
  `toBe`-identical; a mutant that interpolates content into the system turn reds.

### PROVENANCE / STATUS honesty (STANDING binding, RETRO R1 / N104–N106)
- **AC-N157-S6 [node-unit] RED(behavioral).** The persisted plan/evidence record carries an
  explicit provenance+completeness field on its own shape: which engine produced it, whether the
  research was `complete` or `partial`, and (for `partial`) which sections/topics are unsourced. No
  consumer (plan view, walkthrough, any summary) may present a `partial`/unsourced plan as a
  complete, researched one. **Breaking fixture:** a `partial` record with an unsourced topic must
  render that topic marked unsourced; a mutant that drops the field or labels partial as complete
  reds. (Directly parallels the existing `interview_prep_packs` `status in
  ('running','ready','partial','failed','unavailable')` + `_ready_is_complete` CHECK.)

### PERSIST — per-user/per-application storage follows the repo's RLS pattern
- **AC-N157-S7 [migration-shape] RED(vacuous).** SC-B adds a **new migration** (the live DB carries
  constraints no migration creates — [[schema-migration-drift]] — so a new table needs its own
  migration file; do not assume anything). The new table(s): primary/foreign keys to
  `auth.users(id)` and (if application-scoped) `public.applications(id) on delete cascade`;
  `enable row level security`; four owner-scoped policies (`select/insert/update/delete using
  (auth.uid() = user_id)`); explicit `grant ... to authenticated` and `grant all ... to
  service_role`; an index on `user_id`. Enforced by a `*.migrationShape.test.js` in the
  `lib/interviewPrep/interviewPrepMigrationShape.test.js` style. **Instrument must be built.**
- **AC-N157-S8 [node-unit] GUARD + RED(behavioral). Failure direction:** a request that reads/writes
  another user's plan must be refused, not served. The store module (SC-B) MUST carry an
  in-statement `auth.uid()` / `user_id` tenant filter on every read and write **in addition to**
  RLS (defence in depth — RLS is the boundary, not the filter; [[schema-migration-drift]]). A test
  driving the store with a mismatched user id gets nothing back / a refusal.
- **AC-N157-S9 [node-unit] RED(behavioral).** Identity/scope props (`applicationId`, `userId`,
  `engine`) are asserted **off the wire / off the store call**, from a test mounting the real
  parent, never a default-parameter `= ""` that turns "nobody passed it" into a well-formed request
  for the wrong thing ([[measurement-instruments]] "parent forwards it" trap). **Breaking fixture:**
  mount the real walkthrough parent and assert the persisted write carries a non-empty
  `applicationId`; a mount that omits the wire reds.

### QUALITY — owner / Gemini-env, explicitly NOT unit-decidable
- **AC-N157-S10 [owner/Gemini-env] NOT unit-decidable.** Research QUALITY ("did it find real,
  specific, correct evidence about this company/role/stage"), plan QUALITY ("is the outline a good
  study plan"), and walkthrough FEEL ("does the spaced/interactive drill actually help") are
  model-content properties this checkout cannot instrument (no `GEMINI_API_KEY`). Per the standing
  owner-content-quality rule ([[measurement-instruments]] RETRO R1 / N135), these MUST be validated
  by an **owner-env probe set** that maps each candidate failure (no grounding tool on the wire;
  grounding present but all claims dropped by corroboration; evidence good but plan generation weak;
  plan good but walkthrough scheduling wrong) to a **distinct owner-observable outcome in one run**.
  No seat may mark a QUALITY criterion green from this checkout. **Do not** let any downstream
  artifact restate a QUALITY property as if unit-decidable.

### APP-vs-CHAT and MINIMIZE-CLICKS (standing directives)
- **AC-N157-S11 [jsdom/structural] RED(behavioral).** The feature must justify being in-app vs a raw
  chat via a property a chat cannot replicate: the plan is **persisted and resumable** (SC-B), it is
  **grounded + corroborated** (SC-A), and it is **scheduled/spaced** across sessions (SC-D). At
  least one of these must be exercised by a REMOVAL ac ([[app-vs-chat]]): a test proving that
  removing persistence (or grounding, or scheduling) changes observable behavior, so the advantage
  is not decorative.
- **AC-N157-S12 [jsdom/geometry] RED(behavioral).** Generating a plan and starting the walkthrough
  from a selected application is reachable in the fewest reasonable actions with good defaults, no
  needless confirmation ([[minimize-clicks]]); the knob set (SC-D) has working defaults so a user
  who sets nothing still gets a usable plan. Click-path cost is a 1c deliverable; the AC requires
  the default path exist and be tested.

- **AC-N157-C5 [jsdom] RED(behavioral).** Walkthrough progress survives a reload if and only if the

- **AC-N157-C6 [jsdom] RED(behavioral).** A privacy/disclosure block naming what leaves the device
