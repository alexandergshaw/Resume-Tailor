## 2. The shared invocation chokepoint (AC-11, I5)

**File:** `hello-world/lib/review/runDocumentReview.js`

```
// Signature
export async function runDocumentReview(request) -> ReviewOutcome
```

**Input contract — `request`:**

| Field | Type | Required | Meaning / sourcing |
|-------|------|----------|--------------------|
| `kind` | `"applicationReady" \| "hypothetical"` | yes | the reviewed document's KIND (AC-3). Drives `draftKind` AND `authorityReference`. |
| `title` | `string` | yes (may be "") | the human name of the subject, shown by the surface so a verdict is never orphaned (AC-2/AC-5). |
| `resultLines` | `string[] \| null` | one of `resultLines`/`text` | the document's lines; passed to `decomposeToSpans(null, resultLines)`. |
| `text` | `string \| null` | one of | used when `resultLines` absent: `decomposeToSpans(text, null)`. |
| `posting` | `{requirements:[{id,text}]} \| null` | no | I1. Absent ⇒ `{requirements:[]}` ⇒ missing-keyword finds nothing (F4) — acceptable (AC §3 I1). |
| `realMaterial` | `{spans:[{id,text,contextKey}]} \| null` | no | I2. Absent ⇒ `{spans:[]}`; authority stays fail-closed because coverage is partial (F2/AC-1). |

**Behaviour (fixed order):**
1. Normalise lines. If the document has NO content span (blank/whitespace, i.e. `decomposeToSpans(...).spans.length === 0`) → return `{status:"empty"}` **before** calling `reviewDocuments` (AC-10). This is the single shared empty gate both surfaces inherit.
2. `authorityReference = kind === "hypothetical" ? "internal-consistency" : "user-material"` (AC-3). `draftKind = kind`.
3. Build `input = {drafts:[{kind, spans, authorityReference}], posting: posting ?? {requirements:[]}, realMaterial: realMaterial ?? {spans:[]}}`.
4. `review = await reviewDocuments(input)` — **no `options.judge`** (AC-9: pure/offline/no key, F1).
5. `verdict = reviewVerdict(review)` (AC-1, F2).
6. `flags = resolveFlagExcerpts(review.flags, spanTexts)` where `spanTexts` is built in-hand from the spans the chokepoint already owns (see §3). Flags are filtered to `flag.draftKind === draftKind` (single-document review; no cross-draft bleed).
7. Return `ReviewOutcome`.

**Output contract — `ReviewOutcome`:**
```
{ status: "empty" }                      // nothing to review (AC-10)
| { status: "reviewed",
    draftKind,                           // -> ReviewFlagsPanel draftKind (F6)
    title,                               // -> the surface names the subject (AC-2/5)
    flags,                               // RESOLVED excerpt/evidenceExcerpt (F6/F7)
    unresolvedQualifications,            // pass-through to the panel
    verdictKind,                         // reviewVerdict(...).kind (AC-1)
    missingChecks }                      // reviewVerdict(...).missingChecks (names unchecked cats via checkLabel)
```

**Why this is structural, not disciplinary (rule 4 / AC-11):** AC-1 (gate clean on `verdictKind`), AC-3 (kind→authorityReference), AC-8 (no local analyzer/minter), AC-9 (no judge), AC-10 (empty gate) are each a rule that could be broken independently in two surfaces. Both surfaces call ONLY `runDocumentReview` and consume ONLY `ReviewOutcome`; neither imports `reviewDocuments`, `decomposeToSpans`, or `reviewVerdict`. A divergence between modal and chat is therefore impossible to introduce without editing this one file, where one unit test covers both.

**Diff-check (load-bearing, applies to any future diff):** grep the two surface components + `DocumentReviewSection` for `from "@/lib/review/reviewDocuments"`, `decomposeToSpans`, `reviewVerdict` — must be 0 outside `runDocumentReview.js` (canary: the grep returns `runDocumentReview.js` and `idealPipeline.js`, so it fires). This is AC-11(b)'s census and AC-8's census, one sweep.

## 3. Excerpt resolution — REUSE, do not clone (AC-7 / AC-8)

`ReviewFlagsPanel` needs `excerpt`/`evidenceExcerpt` TEXT on each flag (F6); `reviewDocuments` emits span IDs only. The one existing resolver is `resolveFlagExcerpts` (F7), private in `idealSurface.js`.

**Decision (recommended):** extract `resolveFlagExcerpts` and the `textTable` helper into a shared pure module `lib/review/resolveFlagExcerpts.js`; import it from BOTH `idealSurface.js` and `runDocumentReview.js`. This keeps ONE resolver (consistent with "consume, don't duplicate") and keeps AC-7's census green (no second blockquote/label renderer — the chokepoint resolves text, it does not re-present).

**Acceptable fallback (if extraction is judged too wide a blast radius this round):** `runDocumentReview` builds `spanTexts` from the spans it already holds (`{[draftKind]: idToText(spans), realMaterial: idToText(realMaterial.spans), posting: idToText(posting.requirements)}`) and calls the EXPORTED `resolveFlagExcerpts`. This still reuses the resolver (only `export` added to `idealSurface.js`), avoids a clone, and is the lower-risk option. **Plan must pick one; cloning the resolver is forbidden (AC-8 spirit).** The chokepoint does NOT need `ideal.spanTexts` — it owns the spans directly, so it supplies its own tables either way.

## 5. The chat current-document selector — the net-new piece (AC-2 / I3)

**File:** `hello-world/lib/review/selectReviewDocument.js` (pure; no React, no IO, no clock).

```
export function selectChatReviewDocument(pinnedContext, tailoringMap) -> ChatReviewDocument | null
```

**Why net-new (F11/F12):** `ChatPanel` holds no document bytes; `chatPinnedContext.content` is UNRELIABLE as the document — page.js overwrites it with a compound `buildJobContextString + "Tailored Resume:\n…"` string (F11), so reviewing `content` would review job-context noise and attribute the verdict to "the résumé" (exactly AC-2's banned "reviews a substitute"). So the selector resolves the ACTUAL document from structured state, never from `content`.

**Net-new field:** `askAiAbout` (chatbot.js) gains an optional `documentScope` arg, stored on `chatPinnedContext.documentScope = {jobId, scope}`. The modal's `onAskAi` (mount) already knows `scope` and `sourceJobId` (F10) and passes `documentScope: {jobId: sourceJobId, scope}`. This is the single structured hook the deterministic selection needs.

**Selection order (deterministic, no recency/clock ambiguity):**
1. `pinnedContext.documentScope` present AND `tailoringMap[jobId]` has that scope's text → that exact document (scope `"hypothetical"` → `kind:"hypothetical"`; else `kind:"applicationReady"`).
2. else `pinnedContext.sourceJobId` present AND `tailoringMap[sourceJobId].result` non-empty → that job's application-ready résumé (`kind:"applicationReady"`). This is the AC-2 "else the latest tailored artifact the conversation references" fallback; in this architecture the conversation references exactly its pinned job, so "most-recent/current" resolves to the pinned subject — a pure function of state, not a clock. **Flag for checker:** if the AC intends cross-job recency over the whole `applications` array, that is a different model; this design reads AC-2's "available to the conversation" as the pinned job and makes the selection a pure, checkable function. See §9.
3. else → `null` (AC-2/AC-10 "nothing to review"; never a substitute).

**Output — `ChatReviewDocument`:** `{kind, title, resultLines, posting, realMaterial}` — exactly the chokepoint's `request` minus the empty gate. `title` is taken from `pinnedContext.label` (the human name `onAskAi` already built, e.g. "Acme · Staff Eng — Resume"), so the surface names the subject (AC-2). `posting`/`realMaterial` are read from `tailoringMap[jobId]` (I1/I2); absent ⇒ null (handled by the chokepoint).

**Diff-check:** the function is pure; a unit test feeds two pinned-context + tailoringMap fixtures (docScope=B, and sourceJobId-only) and one empty (no pinned context) and asserts the returned `title`/`resultLines` identify the right subject or `null`. AC-2's "two artifacts, reviews B, quotes B's line" is this selector returning B's lines + the chokepoint quoting them.

## 7. Empty / absent (AC-10) and clean-gating (AC-1)

- **Empty gate:** `runDocumentReview` returns `{status:"empty"}` when there is no content span (§2 step 1). `DocumentReviewSection` renders a distinct "nothing to review" string for `status==="empty"` — zero flag rows, NO clean/"no weaknesses" copy, no throw (`decomposeToSpans("")` yields `spans:[]`, never throws, F3). Chat `null` document → same "nothing to review".
- **Clean-gating:** `DocumentReviewSection` renders clean/reassuring copy ONLY when `verdictKind === REVIEW_KIND.COMPLETE`. For `partial`, it renders a partial notice naming unchecked categories from `missingChecks` via `checkLabel`/`CHECK_LABELS` (the N105 `coverageLine` precedent, F8), and NO clean copy. The clean branch is gated on `verdictKind`, never on `flags.length === 0` — making the "no weaknesses when flags empty, ignoring coverage" mutant (AC-1's named N106-AC-17 mutant) impossible in the only component that can show the verdict. Diff-check: grep `DocumentReviewSection.js` for `.length === 0`/`.length>0` adjacent to any reassuring literal — must be 0; the clean literal must sit only inside a `verdictKind === REVIEW_KIND.COMPLETE` branch.

## 9. No-Gemini-key path (AC-9)
