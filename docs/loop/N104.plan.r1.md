### Step 1 — `classifyWeaknesses` (pure lib) — **WAVE A** [F1-adjacent: the 3-bucket crux]
**File (new):** `hello-world/lib/review/classifyWeaknesses.js`.
**Contract:**
```
classifyWeaknesses(reviewOutcome) -> { resolvable: Flag[], confirm: Flag[], genuinelyUnqualified: Entry[] }
```
- `unqualifiedReqIds = new Set(reviewOutcome.unresolvedQualifications.map(u => u.requirementId))`.
- For each `flag` in `reviewOutcome.flags`, by `presentFlag(DRAFT_KIND.APPLICATION_READY, flag.category).tier` (P5): `TIER.CONFIRM` (incl. unknown category) → `confirm`; `TIER.IMPROVE` → candidate resolvable, except a `missing-keyword` whose `evidenceRef.spanId ∈ unqualifiedReqIds` is folded into the genuinely-unqualified presentation (NOT resolvable); otherwise → `resolvable`.
- `genuinelyUnqualified = reviewOutcome.unresolvedQualifications`.
- Invariants: the three buckets are pairwise disjoint; the function imports `presentFlag` from `flagPresentation` and defines no category list of its own (census, AC-3b).
- **Keep OPEN:** takes a `ReviewOutcome`, not an entry — reusable by a future level-1-5 (fork a) path. Do not hard-couple to `entry.ideal`.
**Landable:** pure, green offline. Depends on nothing new.

### Step 2 — `compareReviewGaps` (pure lib) — **WAVE A** [F1 defense-in-depth: closure key + guard]
**File (new):** `hello-world/lib/review/compareReviewGaps.js`.
**Contract:**
```
compareReviewGaps({ before, after, resolvable, beforeRequirementIds, afterRequirementIds }) -> ClosureReport
ClosureReport = {
  correspondenceUnavailable: boolean,
  closed:    [{ category, requirementId, term, label }],   // [] when !correspond
  stillOpen: [{ category, requirementId, term, label }],   // [] when !correspond
  countsBefore / countsAfter: { missingKeyword, vague, repetition },
  lineCountBefore / lineCountAfter,
  genuinelyUnqualifiedStillOpen: Entry[],
}
```
- Gap identity (posting-anchored `missing-keyword`): key = `(category, evidenceRef.origin, evidenceRef.spanId /* = requirement id */, term)`. **`term` REQUIRED** — parsed as the substring inside the FIRST `"…"` pair of `flag.message` (P4), normalized (trim, lowercase, collapse whitespace). A message that does not match the `"…"` shape yields NO key and the flag falls to the count-delta path (never a silent merge).
- Draft-anchored (`vague-unsupported`, `repetition`): category **count deltas only**, never a per-line "closed".
- Correspondence guard: `const correspond = setEqual(beforeRequirementIds, afterRequirementIds)`. When `false` → `correspondenceUnavailable: true`, `closed: []`, `stillOpen: []` (count deltas still reported). When `true` → `closed` = resolvable posting key in `before` and absent from `after.flags`; `stillOpen` = present in both.
- No analyzer, no gate (census).
**Landable:** pure, green offline. Depends on nothing new (inputs are supplied by the orchestrator).
