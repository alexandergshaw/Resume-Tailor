### The two mandated canaries, verbatim

- **Content-derived item key (R5).** `studyPlanSchema.test.js` normalizes a plan `[A,B,C]`, then a
  reordered `[C,A,B]`, then an insert-at-front `[intro,A,B,C]`, and asserts item A's / item C's key is
  **identical** across all three (located by content `text`, never by `id`). An index-keyed
  `normalizePlan` gives a shifted item a new key → reds. Positive control: 3 distinct items → 3 distinct
  keys (kills a constant-key impl). Watched: the index mutant killed exactly the reorder + insert tests.
- **Bounded seen delta (R6/M3).** `buildProgressDelta` must emit `seenDelta` with **exactly one key =
  itemId**; the test asserts `Object.keys(seenDelta) === [itemId]`, that it is NOT keyed by topicId/
  moduleId, and that a second card's delta does not re-carry the first (the non-clobber property).
  `isSingleItemSeenDelta` is pinned true for one valid key and **false for a two-key / whole-map / empty /
  null** input (over- and under-fire controls). Watched: the topicId-key mutant and the `length<1` mutant
  both killed.

## What the implementer MUST know

1. **Reference modules are scratchpad-only.** They are a satisfiability sketch, NOT the implementation,
   and they agree with the tests by construction — build from the plan, not from them.
2. **`itemKey` MUST be content-derived** (a stable hash of content, e.g. `topicHint\u0000text`), never an
   array index, and `normalizePlan` must assign `item.id = itemKey(item)` only when the item carries no
   stable id (a caller-supplied id is preserved — there is a test for that).
3. **`buildProgressDelta` emits ONE `seenDelta` entry.** The whole-map clobber is the M3 defect; the
   store (`writeStudyPlanProgress`, SC-B-persist) must pass that single delta to the RPC, never the map.
4. **`status` has NO `default`** on the migration column line (R2). A `default 'ready'` row with empty
   `plan` would violate `study_plans_ready_has_modules`.
5. **The RPC is SECURITY INVOKER** (R4), signature `(p_application_id uuid, p_cursor jsonb, p_seen_delta
   jsonb)` with NO `p_user_id`, body touching only `study_plans`, `WHERE application_id = p_application_id
   AND user_id = auth.uid()`, merge via `|| coalesce(p_seen_delta ...)`.
6. **Exactly 4 owner-scoped RLS policies**, one per command, each `auth.uid() = user_id` — the shape test
   asserts the COUNT is 4 and each clause is owner-scoped (R10 teeth), so a 5th/removed/`using(true)`
   policy reds.
7. **Re-Glob before finalizing the migration** (plan §6 R1): `20261011000000` is latest only as of this
   reading. The shape test's glob pins the exact filename and will red if a second `*_n157_study_plans.sql`
   lands.
8. **Co-land Steps 2/3/6** (plan §3): adding the two shipping modules reds the tree-wide
   `exportReachability.sweep.test.js` until the `UNWIRED_MODULES` 5→7 reconciliation lands in the same push.
   The only correct fix is the two ledger entries + exact-list + `.md` — NOT bumping a pinned count.
