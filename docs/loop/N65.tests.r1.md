## PLAN FINDING (step 4 non-regression claim is wrong)

The plan step 4 says the change is "prompt-copy only … existing chat suite stays green." It is NOT.
`app/api/chat/route.test.js` pins the ENTIRE system prompt in two frozen goldens with **sha256
tripwires** (`:258` `f2c4b8d2…`; `:313` `a194cfe9…`) and, for the five-section golden, a UTF-16
**length assertion** (`:316` `toHaveLength(2_895)`). Both goldens carry the comment "DO NOT
re-capture the literal to make it green." Any SYSTEM_PROMPT edit turns both red by design.

**Step 4 therefore requires a deliberate, reviewed re-pin of a security tripwire:** update both
golden literals, recompute both sha256 hashes, and update the length (2895 → new). In my reference,
the correct new values were: GOLDEN_SYSTEM_INSTRUCTION len 2616 /
`7a52c2637b39c10b80a3dae78db74aeb85761ec98330d4701c8a8047f340c647`; GOLDEN_FIVE_SECTION len 3222 /
`b40ea562b1651920fc041127912ab206408402dc3f44ca43e080f6d4f3f73644` (these depend on the exact
sentence the implementer ships — recompute). This is an IMPLEMENTER action inside step 4, and the
checker/owner should note the security tripwire is being intentionally re-pinned, not papered over.
I did NOT edit `route.test.js` in the working tree (not my file; editing it to pass would be gate
evasion). Flagged for the plan/implementer.
