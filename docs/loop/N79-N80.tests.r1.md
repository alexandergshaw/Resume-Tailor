## The two traps the brief named, handled explicitly

- **S-3 (near-expiry guard).** `getAuthenticatedClient` calls `refreshAccessToken()` ONLY
  inside `tokens.expiry_date - Date.now() < 5*60*1000` (`gmailClient.js:86`). Every U2
  refresh fixture sets `expiry_date: Date.now() + 60_000`, so the guard fires and the
  classifier is actually exercised. A far-future expiry would pass vacuously (the client
  returns without touching the catch). Stated in the file header and here.
- **R-4 (message rewrite) / R-1 field discipline.** U1 fixtures shape a provider rejection
  per R-1 (`response` defined, `data.error` a STRING, `code` the numeric HTTP status). No
  fixture puts "reauth" in `error_description`. Row 2b is the R-4 rewrite shape built by
  hand (message = a JSON blob, `data.error` still `"invalid_grant"`) — it is the ONLY row
  that kills the `err.message`-swap mutant, because for a plain rejection production sets
  `message == the code` and the swap is otherwise invisible (verified: the message-swap
  mutant failed exactly 1 test, row 2b).

## Contradiction flagged up (plan vs brief/design — needs reconciliation)

The plan's **U1 row 5** folds "a non-object throw" into `{reauth_required, unrecognized}`.
The 4b brief and design §2 both mandate gating the network case on `Boolean(err.response)`
**only** — a non-object throw (`"boom"`, `null`, a number) has a falsy `response`, so that
gate routes it to the network bucket (`temporarily_unavailable`), not the unrecognized
one. The two directives disagree on this one edge (near-zero production likelihood — the
library throws a `GaxiosError` or a real `Error`, never a bare string). I did **not**
encode the contested resolution: U1 pins the two clearly-specified fall-through rows
unambiguously (response-present-unknown-code → `reauth_required`; response-absent →
`temporarily_unavailable`) and asserts ONLY totality (`cause ∈ GMAIL_AUTH_CAUSES`, no
throw) for the non-object throw. The realistic "unrecognised persistent failure" AC-3(iv)
exists for — a `GaxiosError` WITH a response but an unknown code (`admin_policy_enforced`)
— IS pinned (row 5). **The AC/plan should reconcile the non-object-throw wording before
the implementer builds; the tests are robust to either resolution.**
