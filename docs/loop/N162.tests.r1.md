## The contract Waves B/C/D build to

- **Store** `app/settings/includeCodingSolution.js`: exports
  `INCLUDE_CODING_SOLUTION_STORAGE_KEY = "copilot-include-coding-solution"`,
  `DEFAULT_INCLUDE_CODING_SOLUTION = false`, `normalizeIncludeCodingSolution`
  (ON only for `"true"`), `readIncludeCodingSolution`, `subscribe`,
  `setIncludeCodingSolution`, `useIncludeCodingSolution` → `{ includeCodingSolution,
  setIncludeCodingSolution }`. Every localStorage access try/catch-guarded.
- **Grounding:** `groundingFor` emits a fifth field
  `includeCodingSolution` via **strict `=== true`** (NOT `normalizeField` — an
  omitted field and an explicit OFF both fold to `false`; only the real boolean
  `true` is ON). `sameGrounding` compares it. `codingFieldsOf` and the admission
  gate at `:122` are UNCHANGED (the `codingSolution` OUTPUT object must never
  join the grounding key — the N161 suite still pins that).
- **State:** `emptySampleAnswer` seeds `includeCodingSolution:false`;
  `needsRedraft(active, profile, interviewType, applicationId, codeLanguage,
  includeCodingSolution, force = false)` — sixth param BEFORE `force`;
  `cachedSampleAnswerFor(entry, question, profile, interviewType, applicationId,
  codeLanguage, includeCodingSolution)` — seventh param, UNDEFAULTED (omitted →
  OFF grounding → miss), passed into `groundingFor` and echoed on the slot.
- **Client:** `draftAnswer` / `draftAnswerStreaming` FORWARD `includeCodingSolution`
  into the POST body (no default). `answerClient` does NOT read the store; the
  hook captures `readIncludeCodingSolution()` ONCE and passes it. OFF (the store
  default) is forwarded as the literal boolean `false`; an omitted arg is
  `undefined` and JSON.stringify drops it (preserves today's byte-identity for
  callers that never pass it).

## What the implementer MUST know

1. **BLAST-RADIUS FINDING — AC gap.** The AC §BLAST RADIUS list (items 1-7) does
   NOT include `sampleAnswerState.test.js`, but inserting `includeCodingSolution`
   as `needsRedraft`'s sixth param (before `force`) and `cachedSampleAnswerFor`'s
   seventh **breaks 4 of its existing non-coding arity tests** (the force-ordering
   block, "serves the cache when all match", "puts codeLanguage BEFORE force", and
   the needsRedraft↔cachedSampleAnswerFor agreement matrix). The design §8 DOES
   fold this file into Wave A ("6th/7th param; the agreement block adds the new
   field"), which authorised the re-statement I made. I re-stated them: fixtures
   now carry `includeCodingSolution`, call sites pass it in the sixth/seventh
   slot, the ordering test now pins force-stays-LAST with codeLanguage AND the
   toggle before it, and the agreement matrix gained a fifth `incMatches`
   dimension. **Flagged for the checker:** confirm this re-statement is faithful
   and that the AC's BLAST RADIUS list should have named this file.
2. **Do not self-default `includeCodingSolution` in `answerClient`** — it must
   forward only. A default would send the key on every legacy call site and
   break `answerClient.test.js`'s existing exact-key-set guard (which I left
   untouched and relied on as a neighbour).
3. **Strict `=== true` at the grounding boundary, not `normalizeField`** — the
   fifth field is a boolean fact, and folding `undefined → ""` would type-mix the
   comparison and make a pre-field entry miss a default-OFF request.
4. The store is **node-decidable** (no jsdom); AC-N162-3 (jsdom two-consumer) and
   AC-N162-4 (jsdom live control) are Wave D, not pinned here.
5. I did NOT touch `lib/sourceScan/exportReachability.*` (per brief) and ran no
   full suite (per brief).
