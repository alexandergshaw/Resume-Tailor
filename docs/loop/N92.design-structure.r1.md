## 1. The shared move primitive (brief item 1) - LOAD-BEARING

**New module: `lib/acceptedFacts/factMove.js`.** Pure, isomorphic (no DOM, no I/O), sibling to
`factInsertion.js`. Both Control A (the manual move handler) and Control C (the insert-time forward
nudge) consume the SAME exported function, so they cannot diverge (AC-A1/A2/C2).

### 1.1 `planMoveFact` - the one primitive both A and C call

```
planMoveFact({ lines, records, id, direction, bounds? })
  -> { lines: string[], records: Record[], edits: Edit[], changed: boolean, reason: string }

  lines     : string[]  the entry's coverLetterResultLines (paragraphs)
  records   : Record[]  the entry's insertedFacts, EACH {id, text, lineIndex, offset, ...rest}
  id        : string    the fact to move
  direction : "forward" | "backward"
  bounds?   : { minLine:number, maxLine:number }  body-only clamp (default: exclude line 0 and any
              trailing closing/signature block; see D2 below). Passed so the caller, not the primitive,
              owns the "what counts as the body" policy.

  Record : { id:string, text:string, lineIndex:number, offset:number, [url], [title], ... }
  Edit   : { lineIndex:number, before:string, after:string }   (for applyCoverDocxEdits)
```

Contract (each clause maps to a criterion):

- **Purity / no-op identity (AC-A1).** Never mutates `lines` or `records`. On any no-op returns the
  SAME `lines` and `records` references, `changed:false`, and a machine `reason` code
  (`"boundary"` | `"stale-locator"` | `"not-found"`).
- **One slot, correct direction (AC-A2/A3).** Moves the fact's whole `text` span past exactly one
  EXTERNAL sentence boundary toward the end (forward) or start (backward) of the body. Crossing a
  paragraph boundary lands the fact at the first/last slot of the adjacent body paragraph, clamped by
  `bounds` so it never enters line 0 (greeting) or the closing/signature block (D2).
- **Atomicity of a multi-sentence fact (AC-A11).** The fact's own `text` is treated as one opaque span;
  its INTERNAL `[.!?]` boundaries are never slots. Achieved by excising the fact first, segmenting the
  CARRIER (the paragraph without the fact), then re-inserting - the internal boundaries never appear to
  the segmenter.
- **Span-local, whitespace-safe (AC-A4) - LOAD-BEARING.** The excise/insert helpers operate ONLY on the
  fact's own span plus exactly one insertion-owned adjoining space. **They MUST NOT call
  `.replace(/\s{2,}/g," ").trim()` on the whole line.** `planRemoveFact` (`factInsertion.js:252`) and
  `insertFactText` (`:66-71`) both apply that line-global normalize; **`planMoveFact` therefore CANNOT
  reuse `planRemoveFact` as its excise step** - doing so silently destroys pre-existing whitespace
  elsewhere in the touched paragraphs and fails the AC-A4 round-trip. `factMove.js` gets its own
  `exciseSpanLocal(line, offset, textLen)` and `insertSpanLocal(carrier, at, text)` that mirror
  `planRemoveFact:243-251`'s "drop exactly one owned space, prefer the one before, fall back to the one
  after" rule but STOP before line 252. The owned-space convention must be symmetric so
  forward-then-backward is byte-identical.
  - **Documented relaxation (AC-A4 permits it):** if the implementer proves true byte-identity is
    infeasible on the existing splice seam, AC-A4 relaxes to "identical modulo the app's existing
    single-space normalization"; the round-trip test asserts the weaker equality and the plan records
    why. Either way the unsafe outcome (silent loss of the candidate's own intentional spacing) is
    called out. I could not prove byte-identity holds for every edge without writing the algebra (see
    Section 9); the contract above is what makes it checkable.
- **Survivor invariant (AC-A5/A7).** Returns the FULL updated `records` array. Every surviving record
  locates its own `text` at its returned `{lineIndex, offset}` (the `relocateSurvivors` invariant,
  `useCompanyResearch.js:615-627`), and the moved fact appears exactly once. Two adjacent facts moved
  past each other both stay valid and in the new relative order.
- **Provenance (AC-A12).** Each record is copied by spread (`{...record, lineIndex, offset}`); only
  `lineIndex`/`offset` change, never `id`/`url`/`title`/`text`. So the source link and one-click remove
  survive a move regardless of which extra fields a record carries. (Note: `planCoverFacts` records only
  `{id,text,lineIndex,offset}` at `:205`, yet the strip reads `fact.url`/`fact.title` and
  `removeInsertedFact` reads `record.url` - the url/title are attached on some other merge path I did not
  fully trace; the spread contract makes the move safe either way.)
- **Stale/hand-edited locator (AC-A8).** Before moving, assert
  `lines[lineIndex].slice(offset, offset+text.length) === text`; if not, no-op with `reason:"stale-locator"`,
  never a guessed relocation against another occurrence (mirrors `planRemoveFact:240-241`).
- **Edits for the splice path (AC-X3).** `edits` carries the up-to-two paragraph rewrites (source loses
  the fact, destination gains it; one edit when the move is within a paragraph) in the shape
  `applyCoverDocxEdits` consumes.

### 1.2 The segmenter (brief item 2, D1) - RULING: build the offset locator, reuse the boundary REGEX

**Do NOT reuse `summarize.js`'s `splitSentences` directly.** Two disqualifiers, both verified:

1. `splitSentences` collapses whitespace up front (`summarize.js:33`, `.replace(/\s+/g," ")`) and
   returns TRIMMED strings, not offsets. A move needs byte offsets into the ORIGINAL, unmodified
   paragraph to splice span-local (AC-A4). Reconstructing from collapsed strings reintroduces exactly
   the line-global normalization AC-A4 forbids.
2. It returns segments, not gap positions; the move needs the inter-sentence GAP offsets in the carrier.

**Ruling:** `factMove.js` exports `sentenceBounds(text) -> number[]` (the char offsets in the RAW string
where each sentence after the first begins), computed by a non-destructive scan
(`matchAll` over the boundary pattern), REUSING the boundary DEFINITION from `summarize.js:36`
(`/(?<=[.!?])\s+(?=[A-Z0-9"'"(])/`) so the two features agree on what a boundary is, but applied without
splitting or collapsing. This is "reuse the definition, build the locator" - justified because the
existing return shape is unusable for a byte-faithful move.

**AC-A10 (segmenter quality) - RULING: harden with an abbreviation guard.** The shared regex mis-splits
`"U.S. Army"` (period + space + capital) - confirmed by the AC and by reading the pattern. Cover letters
routinely carry `U.S.`, `Ph.D.`, `Inc.`, `e.g.`, `i.e.`, `Dr.`, so a phantom slot landing a fact
mid-abbreviation reads as broken to a recruiter (domain risk). `sentenceBounds` therefore applies a
closed, named abbreviation denylist: a candidate boundary is rejected when the token immediately before
the period is in the set. The set is a fixture-driven constant in `factMove.js` covering the AC-A10
classes (honorifics, `U.S.`/`U.K.`, `e.g.`/`i.e.`, `Inc.`/`Corp.`/`Ltd.`; decimals and `$50M.`/`Node.js`
are already handled by the intra-word lookbehind). Any residual class the guard still cannot resolve
(e.g. sentence-final `Inc.` before a capitalized next sentence) is recorded in the plan as an
owner-accepted limitation naming the specific mis-split, per AC-A10 - not left silent.

### 1.3 Export-reachability (pinned ORPHAN_EXPORTS 70, TEST_REFERENCED 365) - heads-up for the plan

`factMove.js`'s new exports each need a production importer in the SAME step (rule from the brief):
- `planMoveFact` -> imported by `useCompanyResearch.js` (Control A) and `factInsertion.js` (Control C).
- `sentenceBounds` -> exported for AC-A10's direct segmenter unit; if it is ONLY test-referenced it
  legitimately bumps TEST_REFERENCED to 366. The plan/implementer must RE-DERIVE the pinned assertions
  at `lib/sourceScan/exportReachability.sweep.test.js:402,688`, exactly as `factInsertion.js`'s header

  (Section 3) move the counts again. Budget this in the plan; it is not a defect.

## 3. Control B - smooth, CONFIRM-BEFORE-PERSIST (brief item 3, D7)

### 3.1 Own module (AC-B8a) - LOAD-BEARING

The smoothing seam lives in its OWN client module, `lib/coverFacts/smoothTransition.js` (mirrors
`lib/chat/salaryEstimateRequest.js`, the user-initiated grounded-LLM precedent). This is what makes
AC-B8a's static guard provable: the unattended paths (`autoInsertFactsForJob`, generation, repaint,
reload, version switch, Control A, Control C) must not import this module. A static import check over
those files proves "the auto path cannot reach smoothing" - impossible if the handler were co-located in
`useCompanyResearch.js`, which also hosts the auto-insert path. It also gives smoothing its own natural
decision-ledger entry (Section 5).

### 3.2 The server route

New `POST /api/cover-fact-smooth` (mirrors `app/api/salary-estimate/route.js`): auth -> validate ->
`wantsEmbedded(engine)` refusal -> scoped grounded/LLM call in a try -> 200 (never 5xx) with a withheld
envelope on failure.

- **Egress scoped (AC-B7) - LOAD-BEARING.** The request payload contains ONLY the three in-scope
  sentences (before / fact / after) plus the fact's recorded text and contract framing - never the whole
  letter, resume, or job description. The three sentences are derived on the CLIENT via `sentenceBounds`
  against the fact's paragraph(s) and are the only body text that crosses the wire.
- **Automated layer-one guards (AC-B3a/B5).** The route (and/or the orchestrator) auto-rejects a
  candidate rewrite that: errors, times out, returns empty, changes text OUTSIDE the three-sentence span
  (scope guard, AC-B1/B2), or introduces a number, date, currency amount, or proper name absent from the
  in-scope material (added-token check, AC-B3a). Rejection -> discard, nothing persisted, honest error,
  negative decision logged.
- **Not auto-catchable (AC-B3b), stated plainly.** Negation/inflation reusing existing tokens is NOT
  claimed to be caught by the automation; the USER's confirm gate is the meaning check (AC-B3c).

### 3.3 The confirm-before-persist seam (AC-B10/B11/B12) - LOAD-BEARING

The pending rewrite is held in TRANSIENT client state and NEVER touches `coverLetterResultLines`, the
accepted-facts store, or any download until the user confirms:

- `smoothTransition.js` returns a candidate `{ beforeSentences, afterSentences, span }` to a pending-state
  holder (local component state in the strip / a small controller in `DocumentPreviewMount.js`), which
  renders the before/after diff.
- **Nothing is written before confirm.** No `setTailoringMap`, no PUT (AC-B10). The letter stays
  byte-identical.
- **On confirm (AC-B12):** the applied change is EXACTLY the previewed "after" (the same object, not
  regenerated). Apply path = build the paragraph edits, update the fact record's span to the smoothed
  text (AC-A5 invariant, via the same relocate logic), then the SAME persistence path as Control A
  (Section 2 steps 3-5) writing `coverVersion`. Provenance preserved (AC-B4).
- **On decline (AC-B11):** discard the pending object; letter byte-identical; nothing persisted; log a
  negative outcome. Distinct from an automated rejection (AC-B5).
- **Post-apply undo (AC-B6):** keep the pre-smoothing `lines` + record snapshot in the pending/undo
  holder; one click re-runs the persistence path with the snapshot, restoring byte-identity and the
  fact's span. The undo persists (survives repaint + download) because it writes `coverVersion` like any
  other change.

### 3.4 Engine dependence (AC-B9, D4)

The control is disabled with a visible, assistive-tech-announced reason when the client engine is
embedded. **Client gate:** `engine === "embedded"` (the idiom already at `DocumentPreviewDialog.js:150`
and `ChatPanel.js:59`) - the always-honored de-escalation. **Server authority:** for gemini/external the
control is enabled and the route is the authority; when the server default forbids escalation
(`RESUME_ENGINE=embedded`), the route returns an `unavailable_embedded`-style refusal that the confirm/
error surface shows honestly (the salary precedent, `salaryEstimateRequest.js:34`). The client cannot see
the server default, so this split is necessary; noted in Section 9 as a bounded residual, not a defect.
Owner call still open (AC Section 6): disable vs a deterministic non-LLM "tidy" fallback; AC default is
disable, which this design implements.

## 5. Decision ledger (brief item 4, AC-X1) - RULING, LOAD-BEARING

Verified mechanics: `decisionCoverage.sweep.test.js:268` asserts `ledgerModules(ledger).sort() toEqual
[...DECISION_SITES].sort()` - a set of MODULE PATHS that call `recordDecision(`. `recordDecision` resolves
the field vocabulary BY ID (`appActivityLog.js:185`, `DECISION_LEDGER.find(e => e.id === id)`). Therefore:

- **Two ledger entries sharing one `module` string is UNREPRESENTABLE** - `ledgerModules` would list that
  module twice while `DECISION_SITES` (a Set) lists it once, breaking the `toEqual`. Confirmed against the
  sweep, not assumed. So a second id under `DocumentPreviewMount.js` (which already owns `fact-auto-insert`)
  is out.

**Ruling - three modules, three entries, each module unique:**

1. **Control A move + Control C nudge -> ONE new entry.** Both record from `app/hooks/useCompanyResearch.js`
   (moveInsertedFact for A; autoInsertFactsForJob for the nudge). Because the sweep binds by module and a
   module may appear only once, **A and C MUST record under the SAME single id** - propose `"fact-position"`.
   New ledger entry:
   `{ module:"app/hooks/useCompanyResearch.js", id:"fact-position",
      label:"Fact positioning (move / forward-nudge)",
      fields:["direction","reason","code","count"], outcomes:["acted","skipped","refused","failed"] }`.
   `direction` enum (forward/backward), `reason`/`code` canned discriminators, `count` for the nudge's
   affected-fact count. Text-free (no letter/company/url/title), closed vocab (X1/N77).
2. **Control B -> its OWN entry**, from its own module (satisfies AC-B8a and X1 together):
   `{ module:"lib/coverFacts/smoothTransition.js", id:"fact-smooth",
      label:"Cover-fact transition smoothing",
      fields:["reason","code"], outcomes:["acted","skipped","refused","failed"] }`.
   Outcomes: confirmed+applied = `acted`; declined = `refused` (code `"declined"`); engine/timeout/empty
   error = `failed`; scope/added-token auto-reject = `refused` (code `"scope"`/`"added-token"`);
   embedded-disabled = `skipped` (code `"embedded"`).
3. **`fact-auto-insert` (`DocumentPreviewMount.js`) is left untouched** - no vocab expansion, no second id.

This keeps the sweep green in both directions: three new/existing decision sites, three unique module
entries. The plan must land each `recordDecision` call in the SAME step as its ledger entry, or the sweep
goes red (the intended forcing function).
