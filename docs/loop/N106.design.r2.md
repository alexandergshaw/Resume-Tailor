## 2. The public contract — full signatures

`reviewDocuments` is `async` (it `await`s the injected judge when present); on the no-judge path it performs **no IO** and resolves synchronously-computed data. Determinism (AC-11) and purity (AC-12) are claimed for the no-judge path and for any fixed-fake-judge path; a live LLM judge is non-deterministic by nature and the AC scopes AC-11 to the no-LLM path.

```
async reviewDocuments(input, options = {}) => Promise<ReviewResult>

input: {
  drafts: Draft[],                                   // 1 or more
  posting: { requirements: Requirement[] },
  realMaterial: { spans: RealSpan[] } | null,        // null unless some draft.authorityReference === "user-material"
}
Draft:       { kind: string,                         // e.g. "hypothetical" | "applicationReady"; opaque to the core, used only as a key
               spans: Span[],
               authorityReference: "user-material" | "internal-consistency" }
Span:        { id: string, text: string, section?: string, contextKey?: string }   // id is APP-MINTED; the core never mints one
RealSpan:    { id: string, text: string, contextKey?: string }
Requirement: { id: string, text: string }

options: {
  judge?: Judge,          // ABSENT ⇒ mechanical-only path. PRESENT + resolves ⇒ full path. PRESENT + throws/times out ⇒ degrades to mechanical-only (§4/§5, F3).
}
Judge: async (judgeRequest) => { flags: Flag[], evaluatedCategories: Category[] }

ReviewResult: {
  flags: Flag[],                                     // stable total order (§8)
  unresolvedQualifications: [{ requirementId, text }],
  coverage: { evaluatedCategories: Category[],       // sorted, ⊆ the 7-enum
              engineMode: "full" | "mechanical-only",
              complete: boolean },
}
Flag: {
  draftKind: string,                                 // === some input draft.kind
  spanId: string,                                    // scalar; ∈ drafts[draftKind].spans[].id  (AC-1)
  category: Category,                                // ∈ the 7-member enum
  evidenceRef?: { origin: "posting" | "real-material" | "draft",
                  draftKind?,                        // present IFF origin === "draft"
                  spanId },                          // scalar; ∈ the named origin's id-set
  message: string,
}
Category ∈ { missing-keyword, vague-unsupported, repetition, unverifiable-metric,
             employer-plausibility, consistency, unsupported-authority }
```

`judgeRequest` (what the core HANDS the judge — §4): the raw `input` PLUS a core-computed `referencePlan` so the judge never re-derives AC-2 and is physically scoped away from `realMaterial` on internal-consistency drafts.

```
judgeRequest: {
  drafts: [{ kind, spans, authorityReference,
             authorityReferenceSpans: Span[],        // core-computed: realMaterial.spans for user-material; [] for internal-consistency
             referenceMode: "real-material" | "internal-coherence" }],
  posting, realMaterial,
}
```

### 3.2 The floor/LLM split — **[r2 FIX F2: states the erratum ruling it follows]**

- **Always mechanical, full contract depth (no LLM):** `missing-keyword`, `repetition`, `unverifiable-metric`, `vague-unsupported`. These four are the only categories that enter `coverage.evaluatedCategories` on the embedded path.
- **Mechanical SKELETON always runs, but NOT at full contract depth:** the date/title contradiction half of `consistency`, and the deterministic reference-split + date/title coherence of `unsupported-authority`. These skeletons CAN emit flags on the embedded path (AC-8/AC-9/AC-13 require it) — **emitting a flag in a category is NOT the same as evaluating that category to full depth**, so `consistency`/`unsupported-authority` are ABSENT from `coverage.evaluatedCategories` on embedded even when they produce a flag.
- **LLM-only (the judge supplies DEPTH):** `employer-plausibility` entirely, and the semantic depth of `unsupported-authority` and `consistency`. A category enters `evaluatedCategories` at full depth ONLY when the judge reports it (§5).

**[r2 FIX F2] This ABSENT reading follows the ORCHESTRATOR ERRATUM (2026-10-04) atop `N106.ac.r2.md`, and AC-8's contrary clause is SUPERSEDED.** The AC r2 carries an internal contradiction the check (F2) surfaced: AC-8's parenthetical says `unsupported-authority` "appears in `evaluatedCategories` on embedded only for its deterministic skeleton," while §0 / AC-3 I2 / I6 say the embedded path evaluates the 4 FLOOR categories ONLY. This is the exact honesty coupling the AC pins: the embedded path is genuinely PARTIAL and says so (`complete:false`), while still returning its useful mechanical findings (including skeleton flags).

## 4. The injected-judgment seam (I5) — shape, invocation, re-validation, FAILURE semantics

**The seam is a function injected through `options.judge`**, not a value computed elsewhere, because the reference-selection responsibility (AC-2) stays INSIDE the core — the judge must receive already-reference-scoped context, which only the core can build. The route decides embedded-vs-full by whether it injects a judge; the core never reads `process.env` or calls `wantsEmbedded` (N5) — keeping the core pure (AC-12) and making `engineMode` a function of the seam, not of hidden env.

**Invocation sequence inside `reviewDocuments` (full path):**
1. Build the span index and run the mechanical floor (§3) → `mechanicalFlags`.
2. Compute `referencePlan` via `selectAuthorityReference` per draft (§7); attach `authorityReferenceSpans`/`referenceMode` to each draft to form `judgeRequest`.
3. **Invoke the judge with failure containment [r2 FIX F3]:**
   ```
   let seamResolved = false, judgeFlagsRaw = [], reportedCats = [];
   if (options.judge) {
     try {
       const r = await options.judge(judgeRequest);        // may also be wrapped in a timeout by the plan
       seamResolved = true;                                 // the seam RETURNED a value (did not throw/reject/time out)
       judgeFlagsRaw = Array.isArray(r?.flags) ? r.flags : [];              // malformed flags ⇒ ∅, never a throw
       reportedCats  = Array.isArray(r?.evaluatedCategories) ? r.evaluatedCategories : [];  // malformed ⇒ ∅ (F3)
     } catch { seamResolved = false; }                      // throw / reject / timeout ⇒ degrade to mechanical-only
   }
   ```
   - **A PRESENT judge that throws / rejects / times out ⇒ `seamResolved = false` ⇒ the whole invocation degrades to mechanical-only** (`engineMode:"mechanical-only"`, `complete:false` — §5). A throw yields NO LLM depth, so labelling the review mechanical-only is HONEST; a throw can never produce overclaim because `seamResolved=false` forces the floor-only coverage.
   - **A PRESENT judge that RESOLVES but returns a malformed/missing `evaluatedCategories` (non-throwing) ⇒ `reportedCats = []`** ("no LLM categories reported"); intersected with `LLM_CATEGORIES` this is still ∅, so `complete:false`. This closes the latent overclaim path: `evaluatedCategories` is NEVER coerced such that a missing/garbage field becomes "all LLM categories."
4. **Re-validate every judge flag** through the SAME `assertContainedFlag` chokepoint (§6): a judge flag whose `spanId`/`evidenceRef.spanId` is not an input id is DROPPED (fail-safe). The judge is a trusted-but-fallible injected dependency; AC-1 must hold regardless of what it returns.
5. **[r2 FIX F4] Restrict judge FLAGS to `LLM_CATEGORIES` (symmetric with the coverage restriction).** Any judge flag whose `category ∉ LLM_CATEGORIES = {employer-plausibility, consistency, unsupported-authority}` is DROPPED. **Decision + justification (F4):** judge flags are restricted to the 3 LLM categories, NOT allowed to carry any of the 7. Rationale: this gives a crisp, diff-checkable OWNERSHIP boundary — the 4 FLOOR categories are the deterministic core's territory ENTIRELY (both their flags and their coverage), and the 3 LLM categories are where the judge adds depth. It makes a wrong thing IMPOSSIBLE rather than merely absent: a nondeterministic judge cannot inject a floor-category flag (e.g. a stray `missing-keyword`) that would pollute a category the deterministic floor is the authoritative full-depth evaluator of. The cost (a hypothetical judge-spotted floor finding is dropped) is minimal and correct — if the floor misses a floor defect, that is a floor-detector improvement, not a reason to admit nondeterministic floor flags. This is symmetric with step-5's existing `evaluatedCategories ∩ LLM_CATEGORIES` restriction, so the plan/TDD has one determinate rule for both flags and coverage. Dedupe (step 6) still matters because the judge's `{consistency, unsupported-authority}` flags overlap the mechanical SKELETON's flags in those same two categories.
6. `reportedLlmCategories = set(reportedCats) ∩ LLM_CATEGORIES`. Merge `mechanicalFlags ++ validatedJudgeFlags` (judge flags already containment-checked AND category-restricted), dedupe exact duplicates, sort (§8). Compute `coverage` via `computeCoverage({ seamResolved, reportedLlmCategories })` (§5).

**Determinism boundary with the LLM (AC-11 / I4).** The core imposes NO call-shape on the judge; the judge is a plain async function. So `geminiJudge.js` (second slice) is free to honor the N105 research constraints — a CHAIN not one composite call, and `responseSchema` XOR `urlContext` on gemini-2.5-flash (`gemini-tools-nesting`, `gemini-grounding-redirects`, N105 research A11/F-2). None leaks into the pure core. Tests inject a FIXED fake judge; that path is fully deterministic and is what the AC-3 `complete:true` positive control and the AC-12 seam-mapping test drive.

**Honesty at the seam (residual, → I5/I6 plan input).** The core trusts `reportedLlmCategories` within the LLM subset — it cannot re-derive whether semantic depth actually ran. The forbidden direction is overclaim (AC-3). Therefore the judge contract carries an obligation the plan must encode in `geminiJudge.js`: **a category is reported in `evaluatedCategories` only on a successful, parse-complete LLM response for it** (ties to N105 research F-5, the missing `finishReason` check) — never on merely attempting the call. The core cannot enforce this; it is the judge's half of the honesty coupling and is named here so the consumer chunk does not ship a judge that overclaims. (The core's F3 handling is the backstop: a judge that throws or omits `evaluatedCategories` cannot overclaim.)

## 5. The `coverage` population rule (I6) — pinned exactly — **[r2 FIX F3]**

`computeCoverage({ seamResolved, reportedLlmCategories })` in `contract.js`:

```
FLOOR_CATEGORIES = { missing-keyword, repetition, unverifiable-metric, vague-unsupported }   // 4
LLM_CATEGORIES   = { employer-plausibility, consistency, unsupported-authority }              // 3  (full-depth homes)

// reportedLlmCategories is ALREADY (judge-reported ∩ LLM_CATEGORIES), and ∅ when the judge was
// absent, threw/timed-out (seamResolved=false), OR returned a malformed/missing evaluatedCategories. (§4, F3)

evaluatedCategories = sort( FLOOR_CATEGORIES  ∪  (seamResolved ? reportedLlmCategories : ∅) )
engineMode          = seamResolved ? "full" : "mechanical-only"
complete            = isSuperset(set(evaluatedCategories), the 7-enum)        // the SINGLE source of truth for complete
```

**`seamResolved` vs the old `hasJudge` (the F3 refinement).** r1 derived `engineMode` from `hasJudge` (judge present). r2 derives it from `seamResolved` (judge present AND `await` resolved without throwing/timing out), a strictly more honest basis:
- **Judge absent** ⇒ `seamResolved=false` ⇒ `mechanical-only`, floor-only, `complete:false`. (Original embedded case.)
- **Judge present but threw/rejected/timed out** ⇒ `seamResolved=false` ⇒ `mechanical-only`, floor-only, `complete:false`. (F3 — a throw degrades honestly; never overclaim.)
- **Judge present and resolved** ⇒ `seamResolved=true` ⇒ `engineMode:"full"`; `evaluatedCategories = FLOOR ∪ reportedLlmCategories`. If the resolved result's `evaluatedCategories` was malformed/missing, `reportedLlmCategories=∅` ⇒ `evaluatedCategories = the 4 floor` ⇒ `complete:false` (F3 — a sloppy judge cannot overclaim), even though `engineMode` is `"full"` (the seam did execute). `complete`, not `engineMode`, is the authoritative honesty signal.

Consequences, each matching an AC clause (or the erratum ruling):
- **Embedded (no judge):** `evaluatedCategories = the 4 floor`; `engineMode = "mechanical-only"`; `complete = false` (4 ⊉ 7). Always. The skeleton categories `consistency`/`unsupported-authority` are NEVER unioned in on this path (erratum ruling, §3.2). (AC-3 I2.)
- **`engineMode === "mechanical-only" ⟹ complete === false`** holds by construction: without a resolved judge, `evaluatedCategories` can never reach the 3 LLM categories. (AC-15 honesty coupling, second conjunct.)
- **`complete === (evaluatedCategories ⊇ 7-enum)`** is literally the definition line (AC-15, first conjunct). `complete:true` is REACHABLE only when a RESOLVED judge reports all 3 LLM categories — the AC-3 positive control drives exactly that with a fixed fake judge. (Not dead/always-false.)
- **Overclaim is impossible via the core:** `complete` is DERIVED from `evaluatedCategories`, never passed in or set by a detector/judge; `evaluatedCategories`'s LLM part is `reportedLlmCategories`, which is ∅ unless a judge RESOLVED and reported a valid array. A judge cannot set `complete:true`; it cannot even force a category in by throwing or by returning garbage. The forbidden fabrication-shipping direction has no code path in the core.

**Checkable on a diff:** `complete` is assigned exactly once, by `isSuperset(...)` inside `computeCoverage`; grep shows no other assignment to `coverage.complete` and no `complete:` literal in any detector or in the judge-merge path. `engineMode` is assigned exactly once, from `seamResolved`. ## 6. Span ownership & the containment chokepoint (AC-1) — impossible, not forbidden

**The app mints span ids; the reviewer never re-chunks and mints no id.** The core builds, once, an index from the input:

```
index = {
  draftSpanIds:  Map<draftKind, Set<spanId>>,     // from drafts[*].spans[*].id
  postingIds:    Set<requirementId>,              // from posting.requirements[*].id
  realMaterialIds: Set<spanId>,                   // from realMaterial?.spans[*].id  (empty set when null)
}
```

**Every flag — mechanical AND judge-supplied — passes through the single chokepoint `assertContainedFlag(flag, index)` before it can enter the output array.** The validator asserts: `spanId` is a scalar string (never an array/union) and `∈ index.draftSpanIds.get(flag.draftKind)`; and if `evidenceRef` is present, `evidenceRef.spanId ∈` the id-set of `evidenceRef.origin` (posting ⇒ `postingIds`; real-material ⇒ `realMaterialIds`; draft ⇒ `draftSpanIds.get(evidenceRef.draftKind)`), and `evidenceRef.draftKind` is present IFF `origin === "draft"`. **A flag that fails is DROPPED, not emitted** (fail-safe: no fabricated/union id can reach a consumer). For judge flags, the chokepoint runs AFTER the F4 category-restriction drop (§4 step 5), but either order is safe since both are drops.

**Why "impossible" (rule 2).** Two structural facts, each diff-checkable:
1. The ONLY writer to the output `flags` array is a single `emit(flag)` that calls `assertContainedFlag` first and returns early on failure. Diff-check: grep `lib/review/` for `flags.push` / spread into the result — the only occurrence is inside `emit`; no detector or the judge-merge pushes directly.
2. No `spanId` is ever CONSTRUCTED by the core — detectors read `.id` off an input span object and pass it through. Diff-check: grep `lib/review/` for string-concatenation into a span id (`+ "+" +`, template literals combining two ids, `.join(`); zero matches. The union-id stub (`"s1+s2"`, AC-1 Stub S) therefore cannot be produced by conformant code and is caught by (1) if a detector tries.

**Cross-draft `evidenceRef` (AC-9):** a `consistency` flag on draft D1 sets `spanId` = one offending span in D1 and `evidenceRef = {origin:"draft", draftKind:D2.kind, spanId:<one span in D2>}`. Both resolve through the chokepoint against their respective draft id-sets. One span vs one span — never a union.

## 7. Per-draft authority reference selection (AC-2) + `realMaterial` null (AC-13)

**`selectAuthorityReference(draft, realMaterial)` is a pure, independently-testable layer** (`lib/review/referenceSelect.js`) — the AC-2 "deterministic reference selection," testable even though the plausibility JUDGMENT within the selected reference may later be LLM-augmented.

```
selectAuthorityReference(draft, realMaterial) => { mode, referenceSpans }
  draft.authorityReference === "user-material"       ⇒ { mode:"real-material",      referenceSpans: realMaterial?.spans ?? [] }
  draft.authorityReference === "internal-consistency"⇒ { mode:"internal-coherence", referenceSpans: draft.spans }
```

- `user-material` ⇒ judged against `realMaterial`. `internal-consistency` ⇒ judged against the draft's OWN spans (posting-plausibility + internal coherence), **never** `realMaterial`.
- This is what makes AC-2 structural even through the judge seam (§4): `judgeRequest` carries each draft's `authorityReferenceSpans` from THIS function, so an internal-consistency draft is physically handed `referenceSpans = draft.spans` for authority — `realMaterial` is never in its authority scope. A coherent-but-strong internal-consistency claim yields zero `unsupported-authority` flags, invariant to `realMaterial` (AC-2 Fixture H, Runs A/B identical).

**`realMaterial` null handling (AC-13), decided here (default per AC I3 = fail-closed-by-flagging):**
- **(a) No `user-material` draft present:** `realMaterial` MAY be null; the authority layer for the (internal-consistency) drafts uses their own spans; the core runs normally, no throw. The null `realMaterial` yields an EMPTY `realMaterialIds` set (§6), so any stray real-material evidenceRef would be dropped, never crash.
- **(b) A `user-material` draft present WITH `realMaterial` null (precondition violation):** `referenceSpans = []`. `detectAuthoritySkeleton` fails closed: every authority/support-requiring claim span on that draft is flagged `unsupported-authority` (no `evidenceRef`, since there is no real-material span to cite; the `message` states no candidate material was available). `coverage.complete` stays `false`. The result is NEVER `flags:[]` with `coverage.complete:true`. (The refuse-with-signal alternative is admissible per AC I3 but the default is flag-maximally; the invariant + direction are fixed here, the FORM is I3.)

**Diff-check (AC-2 mutant):** an impl where `selectAuthorityReference` returns `real-material` for an internal-consistency draft makes Fixture H differ between Runs A and B → red. (AC-13 mutant): an impl returning `flags:[]`/`complete:true` for case (b) reds the AC-13 fixture.

## 8. Determinism & stable total order (AC-11)

The core sorts the final `flags` array by a **content key**, never by input array position:

```
sortKey(flag) = [ flag.draftKind, flag.spanId, flag.category,
                  flag.evidenceRef ? stableStringify(flag.evidenceRef) : "",
                  flag.message ]                 // final tiebreak → TOTAL order
```

`unresolvedQualifications` sorts by `requirementId`; `coverage.evaluatedCategories` sorts by the enum's own fixed order. `stableStringify` serializes object keys in a fixed order so equal content always yields equal strings.

- **Repeat-call equality:** `reviewDocuments(I)` twice is deep-equal on the no-judge path (pure function of inputs, no clock/random — §9).
- **Shuffle invariance:** the sort key is derived from CONTENT, so shuffling `drafts[*].spans` order yields a deep-equal result. The AC-11 instrument drives the AC-3 multi-defect draft (≥4 flags across distinct spans) to make the shuffle non-vacuous.
- **Diff-check / mutant:** an impl emitting in span-iteration order (or from a `Set`/object-key order) reds the shuffle test ONLY because the fixture guarantees ≥2 flags whose content order ≠ input-span order. Grep: the result assembly ends in a `.sort(bySortKey)`; no early `return flags` bypasses it.
