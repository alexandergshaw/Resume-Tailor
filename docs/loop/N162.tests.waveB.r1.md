## Disclosed: AC-N162-11 is a GREEN guard, not a RED (honest accounting)

AC-N162-11 ("malformed coding payload → 200 normal answer, not 502") cannot be
made RED in a route unit test. With ONE fixed mock payload, a divergence would
require the SAME parsed object to have points absent (so HEAD 502s) AND present
(so additive 200s) — impossible. With a both-fields payload (points present +
malformed codingSolution), HEAD already drops the unparseable solution and
returns the points (200), identical to additive. The "502→200 flip" the AC
describes is a PROMPT effect (the additive prompt asks for points), proven in
`answerPrompts.coding.test.js`, not in the route. The route test is kept as a
GREEN guard confirming malformed-degrade on both HEAD and the reference.

## Disclosed: brief vs arch — where the detection gate lives

The brief lists "includeCoding true + non-coding → no coding directive
(detection gates it)" as a prompt test. The arch (§4.1) is explicit that the
BUILDER does not re-derive detection — it honours `includeCoding`; the ROUTE
computes `wantsCoding = flag ∧ detection`. So "detection gates a non-coding
question" is a ROUTE property (`route.coding.test.js` ON+non-coding row), and at
the builder layer I pin the OPPOSITE deliberate contract (the builder appends
whenever told, so a mutant re-adding detection to the builder reddens). This
keeps the real production path faithful and is the only satisfiable reading
(a builder test asserting "no directive" would fail the arch-conformant
reference).
