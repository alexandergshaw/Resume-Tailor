## Findings (ranked)

### F1 (HIGH) — The A-1 → N110 routing ships a LIVE false-coverage claim in slice 1
**Location:** orchestrator routing of A-1 vs `N103.ux.r1.md` §4.2 / N103-UX-6; manifests in the partial notice on any surface where `posting` is absent.

**Concrete failure.** Every mechanical run is PARTIAL, so the partial notice ships in slice 1, and it prints a "Checked: …" line derived from `reviewVerdict(review).checkedChecks` → `coverage.evaluatedCategories`. `computeCoverage` puts the four FLOOR_CATEGORIES (including `missing-keyword`) into `evaluatedCategories` **unconditionally** (`contract.js:150`), independent of whether `posting.requirements` was supplied. So when posting is absent — **ordinary non-Ideal jobs** (design §12.1: `{requirements:[]}`) and **cover letters** (design §4.2: posting deliberately withheld) — the notice reads "Checked: posting keywords, …" when no keyword matching occurred (a vacuous pass over an empty requirement list). That is the exact "looks done, analyzed nothing" / AC-1-class false reassurance the chunk exists to prevent, and it is NEW exposure: N105 never hit it because an Ideal job always carries `postingAnalysis`; N103 extends the notice to surfaces with no posting.

**Why the routing is only half-right.** A-1 bundles two separable guards:
- **A-1b (clean license also requires `inputsComplete`)** — safely deferrable to N110. `reviewVerdict` can never return `complete` on a mechanical run (`contradicted` is always true today), so clean copy is physically unreachable; a false "all clear" cannot ship now. The brief's deferral reasoning is correct for THIS part.
- **A-1a (partial notice must not claim "Checked: posting keywords" when no posting was supplied)** — NOT deferrable. The partial notice ships now and misstates coverage now.

**Proposed fix.** Split A-1. Keep A-1a (N103-UX-6's inputs-withheld handling: when `inputs.posting` is false, move "posting keywords" from Checked to Not-fully-checked and suppress the vacuous-pass claim; likewise omit the keyword check wording for cover letters). Defer only A-1b to N110. The shared helper must return `inputs:{posting,realMaterial}` in N103 so the notice can tell the truth.

### F2 (MEDIUM) — Scope contradiction the plan would inherit
**Location:** `N103.ux.r1.md` §4.1 clean license + ledger line N103-UX-6, vs the A-1 → N110 routing.

The UX artifact already builds A-1 in: §4.1 lists `inputsComplete` as a conjunct of the clean license, and N103-UX-6 is a binding slice-1 ledger line. The routing defers A-1 wholesale. The plan/TDD seat inherits an ambiguous scope (build N103-UX-6 or not). Reconcile explicitly by adopting the F1 split (A-1a in, A-1b out) and restating N103-UX-6 as the A-1a-only requirement. Without this, the TDD seat either writes a zero-value test for an unreachable branch (A-1b) or drops the live A-1a guard.

### F3 (CONFIRM — R-1 re-baseline is SOUND, with one condition)
**Location:** `DocumentPreviewMount.idealBands.test.js:158-174`.

The test captures ordinary counts, re-renders Ideal, asserts `Ideal === ordinary + 1` (a DELTA of one pair). Widening the N95-pair mount condition to include the review strip (UXN-5) makes an ordinary reviewable job legitimately mount the pair too, so the delta becomes 0 and the test reds. Re-baselining is **sound and does not mask a regression**, PROVIDED the new assertion is the ABSOLUTE form the design recommends — "ordinary AND Ideal EACH have exactly one pair; a second (band-local) pair still reds." Proof it keeps power: the named mutant (band adds its own `role=status`/`alert`) → count 2 ≠ 1 → reds; a dropped pair → count 0 ≠ 1 → reds. A weaker "counts are equal" re-baseline would be unsound (0=0 or 2=2 would pass) — the ruling must forbid that form.
**Caveat for 4b/TDD:** verify the review strip actually mounts in the ordinary-render harness, so the new absolute baseline is 1, not 0; the widened `reviewStripMounted` condition must hold for `baseProps({"job-1":{result:"Resume text"}})`. The design's fallback (drop the modal announcement, move focus to the result heading) is a valid escape if the orchestrator refuses the test edit.
