create table if not exists public.application_project_pool (
  application_id uuid primary key references public.applications (id) on delete cascade,
  user_id        uuid not null references auth.users (id) on delete cascade,
  projects       jsonb not null default '[]'::jsonb,
  status         text not null default 'pending',

## E. m3 resolution — REUSE + thin BUILD (the flagged contradiction)

**Canaried grep (root `hello-world/lib`+`app`, canary positive = `application_digests` hit):** no dedicated significant-number/compensation extractor for stripping exists. The deleted `idealProjectPrompt.js` (gone in `5b9d79f` N141) carried one — **not resurrected** (git history read only to understand). But `lib/feed/salary.js` carries a live, pure, well-anchored comp extractor:
- `parseSalary(text) -> { min, max }` (`:76`) — annualized USD, **requires a leading `$`** (so it does not latch onto arbitrary integers), clamps to a sane `$10k–$2M` band, handles `$120k`/`$120,000`/ranges. `resolvePostingSalary(structured, text)` (`:142`) wraps it.

**Decision: REUSE `resolvePostingSalary`/`parseSalary` for the salary/compensation half (the confirmed R-135 case), and BUILD a thin `stripPostingFigures(entry, posting)` collision guard around it** (in S4's `projectExampleGen.js`). The BUILD:
1. `postingSignificantNumbers(posting)` = the normalized `{min,max}` from `resolvePostingSalary(posting.salaryStructured, posting.description)` PLUS a small local scan for currency-prefixed or `>= 4-digit` numbers in the posting text (headcount, large figures). Small bare integers and percentages are NOT collected.
2. For each `entry.bullets[]` string and `title`: normalize its numeric tokens (strip `$`/commas, `k`→×1000) and compare against the set; a collision (equality, within a tight tolerance) → strip that bullet.
3. An entry left with `< 2` usable bullets → dropped (pool) / returned `failed` (on-the-spot).

**Why not pure-reuse:** `parseSalary` returns only ONE band and only `$`-anchored figures — it does not cover headcount or a `$`-less "120-150k" band. The thin BUILD extends coverage to AC-15's full "salary/comp/headcount" without resurrecting the deleted module.
**Why this keeps legitimate figures (AC-15 direction):** "cut deploys from 5 to 1", "pass rate 61% to 78%" are small bare integers / percentages — never collected into the significant-number set, never stripped. The salary band ($120k) is the only collision target. This is exactly the T5 two-direction control.
**Reuse-rule check (read the function + its intent, not the name):** `parseSalary` is pure (no I/O), explicitly documented as safe to import from both pipeline and client, and its `$`-anchor + band-clamp makes it conservative (it will not spuriously treat "5" as comp) — it is NOT the `atsLookup.normalizeCompanyKey` over-collapse trap. Suitable for reuse as-is.
