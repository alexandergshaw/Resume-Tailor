## The defect (restated from the verifier, re-confirmed by execution)

`applyForwardNudge` (lib/acceptedFacts/factInsertion.js:414-435 on HEAD) nudges
`cover.lines` and `cover.record` but leaves `cover.edits` exactly as
`planCoverFacts` produced it (the plain, un-nudged insert). On the SPLICE
strategy -- any letter with real cover docx bytes, the realistic majority case
(`autoInsertFactsForJob`, useCompanyResearch.js:857) -- those stale edits are
spliced into the docx and stored as `coverLetterDocxB64` (:938), while
`coverLetterResultLines` is set to the NUDGED lines (:934). `resolveDocumentBlob`
serves the stored bytes verbatim (the entry is never marked `edited`), so preview
AND download show the fact one slot EARLIER than the visible lines. The shipped
`autoInsertForwardNudge.rc.test.js` used Shape B (no bytes) on purpose -- the
exact carve-out that hid this; AC-C4 authorizes no such carve-out.
