## Scope

**IN:** a new persisted boolean toggle (shared, off by default); its request flag threaded into both answer-request builders and read by the route; the model reversal (normal answer always produced; coding solution additive, gated on toggle∧detection); the additive render at all render sites; re-statement of the N161 suites that encode REPLACE/suppress-points; cache/grounding correctness across a toggle flip.

- The exact on-screen label and pixel placement of the control, and the phone geometry of the control + the now-longer card (owner micro-decisions / env measurement — §SPLIT, §OWNER).

## Failure directions (write the safe direction as the passing one)

- **FD-1 (default safety):** an unreadable/missing/garbage store value, and a never-set store, MUST resolve **OFF**. A test that corrupts localStorage and asserts OFF is the canary. Worse direction = silently ON (coding sections appear for a user who never opted in).
- **FD-2 (the question is always answered):** for ANY question and ANY toggle state, the normal answer MUST be produced and shown. The only thing the toggle/detection may gate is the **additive** coding section. Worse direction = a toggle or detection path that still suppresses the normal answer (the N161 defect this chunk exists to remove).
- **FD-3 (no stale cross-toggle serve):** a cached answer drafted under one toggle state MUST NOT be served when the current toggle state would produce a different answer. Worse direction = toggling ON and revealing the same detected-coding question serves the OFF (code-less) cached answer, or vice-versa.
- **FD-4 (no fabricated code):** the embedded engine MUST NOT emit a `codingSolution` with a `code` field; it emits the honest `codingFallback` marker only, and now additively (beside the normal embedded answer).
