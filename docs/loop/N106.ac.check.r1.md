## F1 — BLOCKER — AC-3's "never clean-looking empty" guarantee is FLOOR-scoped; the embedded path can still return `{flags:[]}` success on a draft that is floor-clean but has a non-floor (LLM-category) defect

Location: AC-3 (§2, lines 86–94), its Negative control (line 91), and the dependency in AC-10 failure direction (line 134) and §1 second-slice admissibility (line 41).

AC-3 forbids a `{flags:[]}` success **only** "for a draft set that CONTAINS at least one mechanical-floor defect." Its negative control (line 91) then labels a draft with *no floor defect* "genuinely clean" and states it "legitimately returns empty." But the mechanical floor is exactly `{missing-keyword, repetition, unverifiable-metric, vague-unsupported}` + date/title-contradiction (§1 line 43); `employer-plausibility` and the semantic DEPTH of `unsupported-authority`/`consistency` are explicitly NOT in it (second slice, §1 line 41, AC-10).

Breaking input: an embedded-path (`wantsEmbedded ⇒ true`, no LLM) call on a draft that passes every floor check but carries an implausible-employer claim (e.g. "led FDA Class-III device submissions" under an employer the posting establishes as a payroll SaaS). The deterministic path cannot compute `employer-plausibility`, finds no floor defect, and returns `{flags:[], unresolvedQualifications:[]}` **as a success value of the frozen shape**. The frozen return (N105 §7, lines 193–207) carries NO coverage/analyzed-categories field, so a consumer (N103 adversarial-review button, N104 weakness summary — both import this same primitive and are not shown to mirror N105's engine-level refusal) renders "reviewed — no weaknesses found." This is precisely the "a review that looks done and finds nothing while nothing was analyzed" failure AC-3's own failure-direction (line 94) calls "the worst outcome" — but AC-3 only prevents it for the floor.

This is load-bearing: AC-10's failure direction (line 134) and §1's second-slice admissibility (line 41, line 189 Blockers) explicitly justify deferring LLM-category DEPTH "ONLY because AC-3 forbids the embedded path from looking clean while unanalyzed." As written AC-3 does NOT forbid that for non-floor categories, so the stated safety basis for the whole second-slice deferral is overstated. This is the worst failure class the brief names (a reviewer that is silently cosmetic on a subset of its categories).

Note this is NOT caught by AC-3's own stubs: stub E fails the floor positive, stub A fails the floor negative — neither exercises a floor-clean + non-floor-defect input. The hole is reachable only by that specific fixture, which no current AC requires.

Fix direction (AC author picks; invariant must be pinned, not the mechanism):
- (a) Strengthen AC-3's forbidden outcome: on the embedded path, whenever the LLM categories are requested-but-unavailable (not merely when a floor defect is absent), the call must NOT return a success value of the frozen shape — it refuses honestly (throw / `wantsEmbedded`-gated absence per I2) so no consumer renders it as a completed clean review; OR
- (b) Add an explicit AC pinning that N103/N104 (like N105 §2) never present the embedded path as a consumer-facing complete review — i.e. the embedded path is never a review surface — and state that cross-artifact assumption here rather than leaving it to each consumer; OR
- (c) If neither, the frozen contract needs a coverage signal, which contradicts "frozen, no coverage field" — surface that tension to the owner.
Add a fixture: floor-clean draft + one non-floor (employer-plausibility) defect on the embedded path → assert NOT a `{flags:[]}` success (refusal or signal). Failable = 1.

## F3 — MINOR — AC-1(b)'s union-fixture power is conditional on the union defect also being a detectable floor category; the AC should assert a flag is produced

Location: AC-1(b) (lines 67–68, 70).

AC-1 explicitly allows over-containment ("declining to flag a genuinely multi-span defect is acceptable"). So if the union fixture's defect elicits no flag, (b)'s assertion "the resulting flag's spanId is exactly one of {s1,s2}" passes vacuously and the union-minting impl escapes. (b) only has power because the chosen defect (+300% split across s1/s2) is an `unverifiable-metric` that AC-6 forces a conformant impl to flag. The AC relies on this implicitly.

Fix: state the dependency and assert the union fixture produces ≥1 flag of a floor category (so (b) is never vacuous); do not let the union fixture use a non-floor defect, which on the embedded path would elicit nothing.
