# N102 — "Answer as me" toggle in the Ask-AI chat — Acceptance Criteria (r1)

AC seat, round 1. Author: loop-ac (Opus). Date 2026-10-05.

Feature (BACKLOG.md:173): a toggle the user flips in the Ask-AI chat so the assistant responds in the
**first person AS THE USER** — drafting a reply/answer/message the user could send or say — instead of
as an assistant advising them. OFF = today's assistant voice. AC must pin: what "as me" means
concretely (first-person, draft-ready, the user's voice); that it is clearly indicated when ON and
reversible; and that it never fabricates facts about the user it was not given.

Independent of N103/N104/N106: those are the adversarial-reviewer features (preview/edit modal + chat
review card). N102 is a chat **persona/voice** switch only. It shares no primitive with them and must
not touch `reviewDocuments` or the review surfaces.

## 1. Facts established THIS round (cite file:line)

All read at working-tree HEAD (f8c704f) this round unless marked CITED.

- **Ask-AI chat surface** is `app/components/ChatPanel.js` (747 lines), driven by `app/hooks/useChat.js`.
  The header already carries an engine indicator Chip ("Offline · no AI") at ChatPanel.js:184-212; the
  composer row (`+ File`, TextField, Send) is at ChatPanel.js:661-742. These are the two natural homes
  for a new control and the visual language to REUSE (Chip / small Button / MUI control).
- **Client request shaping**: `runChatRequest` (lib/chat/chatbot.js:496-806) builds `payload`
  (chatbot.js:609-625) — fields `messages, resumeText, applications, pinnedContext, attachedFiles, tab,
  section, engine` — serializes to `requestBody` (chatbot.js:626) and POSTs to `/api/chat`
  (chatbot.js:698-702). `engine: readEngine()` (chatbot.js:624) is the only per-request mode flag today.
  **There is no voice/persona field.**
- **Server persona (Gemini/LLM path)**: `SYSTEM_PROMPT` is a module **constant**
  (app/api/chat/route.js:23-36). It is assigned verbatim to `systemInstruction`
  (`const systemInstruction = SYSTEM_PROMPT;`, route.js:335) and passed as `config.systemInstruction`
  (route.js:366). Route-comment and promptInjection AC-1 pin that it **never varies with request content**
  (route.js:332-335). The prompt's only truthfulness clauses are salary-specific ("never invent a
  specific pay figure", route.js:31,35) — there is **no general no-invented-personal-facts clause**.
- **Embedded (no-AI) path**: `localChatReply` (lib/chat/localAssistant.js:501-576) is deterministic,
  intent-classified **advice** prose ("A few quick wins: start every bullet with an action verb…",
  localAssistant.js:166). It has **no system prompt and no generative rephrasing** — it cannot honestly
  draft a first-person message. Route selects it via `wantsEmbedded(body.engine)` (route.js:268); every
  non-embedded engine falls to the Gemini path (route.js:283-368). So the chat has exactly two paths:
  embedded (localAssistant) and LLM (Gemini).
- **Persistence precedent**: `app/settings/engine.js` is a `useSyncExternalStore` + `localStorage` store
  (`ENGINE_STORAGE_KEY = "tailorEngine"`, engine.js:10; `readEngine`/`setEngine`/`useEngine`,
  engine.js:40-67), defaulting to a known value when storage is empty/unreadable
  (`normalizeEngine`, engine.js:36-38). The panel size persists the same way
  (`localStorage "chatSize"`, useChat.js:124-141). Chat **messages** are session-only React state
  (useChat.js:99-117). A durable user **preference** like voice fits the engine-store pattern, not the
  session-only message state.
- **Offline instruments exist and read BEHAVIOUR off the wire, not source text**:
  - client: `runChatRequest` with `globalThis.fetch` stubbed; the request body is `fetch.mock.calls`

    `generateContent.mock.calls[0][0]` and `config.systemInstruction` is read off it
    (app/api/chat/route.promptInjection.test.js:45-114). Asserts the actual string sent to Gemini.
  - ChatPanel renders under jsdom (measurement-instruments memory; existing ChatPanel.*.test.js).
- **Known-negative canary (grep over `hello-world/`, this round):** `answerAsMe|asMe|first ?person|
  firstPerson` over the app → **0** hits that are a chat voice toggle. Positive canary: the same sweep's
  `persona` matches exist (`supabase/migrations/20260703000000_tailor_personas.sql`,
  `lib/meeting/meetingPage.js` "first-person") — unrelated, so the search tool is live and the absence
  is real, not a dead search. **Nothing like this toggle exists at HEAD.**

## 2. Scope

**IN (first slice):** the toggle control in the Ask-AI chat; its persisted OFF-default state and clear
ON indication; the request/persona-framing switch on the **LLM (Gemini) chat path**; the bundled
no-fabrication constraint. All offline-testable.

**OUT (this slice), stated so design does not widen and verify does not file as missing:**
- First-person **drafting on the embedded (localAssistant) path** — the template engine cannot generate
  a first-person message honestly. AC-9 governs how embedded must DEGRADE, not produce drafts.
- The **live quality** of Gemini's replies (does it actually speak first-person; does it actually avoid
  fabricating) — owner-env, see AC-10.
- Any change to the reviewer (N103/N104/N106), the tailor engine, the copilot, or salary estimate.
- Multiple named personas / saved voices (that is the separate `tailor_personas` feature; N102 is one
  boolean).

## 4. Acceptance criteria

Legend: **[OFFLINE]** fully checkable with the instruments in §1 and no Gemini key. **[ENV]** owner-env,
not gated in CI. **RED/HEAD** = fails today before any work. **GUARD** = non-regression or
make-wrong-impossible criterion that is not discriminating on HEAD (stated plainly per standing rule 1).

### AC-1 — The toggle exists, is reachable, keyboard-operable, one click [OFFLINE] [RED/HEAD]
A single control in the Ask-AI chat panel (`ChatPanel`) lets the user turn "answer as me" on and off. It
is a real focusable control with an accessible name that says what it does (e.g. "Answer as me"),
operable by pointer AND by keyboard (Enter/Space), and toggling it is **one action** — no wizard, no
confirmation dialog, no nested menu (minimize-clicks).
- Instrument: jsdom render of `ChatPanel`; query by role + accessible name; fire click and keydown.
- RED/HEAD: no such control exists (§1 canary: 0 hits).
- Failure direction: if the control cannot be found by accessible name, or needs more than one action to
  flip, it is defective.

### AC-2 — The ON state is clearly and programmatically indicated [OFFLINE] [RED/HEAD]
When the toggle is ON, the chat shows an unambiguous indication that replies will be drafted in the
user's voice — both visually and programmatically (e.g. `aria-pressed="true"` or equivalent exposed
state on the control, plus a visible active treatment). When OFF, the indication is absent.
- Instrument: jsdom render; assert the exposed on/off state and the visible indicator differ between the
  two states.
- RED/HEAD: no control, no indicator.
- Failure direction: an ON state that is not perceivable (no visible cue) OR not programmatic (invisible
  to AT) is defective; the dangerous case is the user believing they are getting advice while the model
  is actually writing as them, or vice-versa.

### AC-3 — The preference persists and defaults OFF [OFFLINE] [RED/HEAD]
The toggle's value survives at least the session and does not reset between sends or between
closing/reopening the panel. The **fitting store is the engine-store pattern** (a `localStorage`-backed
`useSyncExternalStore`, as in app/settings/engine.js), so it also survives a reload; design may instead
justify session-only React state, but session persistence is the floor. On first use, or when the stored
value is absent/unreadable, it defaults **OFF** (today's assistant voice).
- Instrument: unit test of the store (write ON → read ON; empty/garbage storage → OFF), mirroring
  engine.test.js; plus a render test that reopening the panel preserves the value.
- RED/HEAD: no store/key exists (only "tailorEngine" and "chatSize" exist today).
- Failure direction (safe side is the passing side): the unknown/empty-store state MUST resolve to OFF,
  never ON — a user must never silently start speaking in their own voice without having chosen it.

### AC-4 — Reversible: OFF reproduces today's assistant voice exactly [OFFLINE] (discriminating half RED/HEAD; baseline half GUARD)
Turning the toggle OFF returns the chat to today's behaviour with no residue.
- **Discriminating half [RED/HEAD]:** the request framing produced with the toggle ON is **different**
  from the framing produced with it OFF (otherwise the feature does nothing). Instrument: client
  fetch-spy and/or server wire — ON payload/`systemInstruction` ≠ OFF.
- **Baseline-equality half [GUARD, GREEN on HEAD]:** with the toggle OFF, the client payload and the
  server `systemInstruction` are **byte-identical to today's baseline** (payload fields of chatbot.js:
  609-625; `SYSTEM_PROMPT` of route.js:23-36). This is vacuously true on HEAD because OFF is the only
  state that exists; it becomes a real non-regression guard once ON is built. Stated here so it is not
  counted as discriminating coverage.

### AC-5 — "As me" = first-person, draft-ready, the user's voice (observable framing) [OFFLINE] [RED/HEAD]
With the toggle ON, the framing actually sent to the model instructs it to respond **in the first person
as the user**, producing a message/answer/response the user could send or say verbatim — NOT advice of
the form "you could say…". Concretely:
- client: the request body carries an explicit as-me flag/field (e.g. `answerAsMe: true`) when ON and
  omits/falses it when OFF. Instrument: chatbot.request.test.js fetch-spy on the parsed body.
- server (LLM path): when that flag is set, `config.systemInstruction` on the Gemini wire contains an
  explicit first-person-as-the-user drafting directive that is ABSENT when the flag is unset.
  Instrument: route.promptInjection.test.js wire reader (`generateContent.mock.calls[0][0]`).
- RED/HEAD: no flag in the payload; `systemInstruction` is a request-invariant constant (route.js:335).
- Note: whether Gemini's live reply is actually phrased first-person is **[ENV]** (AC-10).

### AC-6 — HARD SAFETY: the as-me framing forbids fabricating personal facts, and cannot be sent without that constraint [OFFLINE positive assertion + make-wrong-impossible] [RED/HEAD]
The N102 analogue of the repo's truthfulness guardrails. When ON, the framing sent to the model
**explicitly constrains drafting to the facts actually provided** (the conversation, the pinned subject,
the user's uploaded resume / attached files / applications already in request scope) and **explicitly
forbids inventing biographical facts, experience, employers, dates, titles, metrics, or credentials**
about the user.
- Positive assertion [OFFLINE]: on the as-me LLM wire, `systemInstruction` contains the
  no-invented-personal-facts directive. Instrument: route wire reader.
- Make-wrong-impossible [structural, OFFLINE]: the first-person directive and the no-fabrication
  directive are emitted as **one indivisible unit** (a single constant / builder output), so there is no
  code path that turns on first-person voice without also carrying the no-fabrication clause. Instrument:
  a test that drives the as-me branch and asserts BOTH substrings are present together, plus a mutation
  control (removing the no-fab clause from the builder turns the test red). This beats a bare
  "string contains" check: the two cannot be decoupled by a later edit without a red test.
- RED/HEAD: no as-me framing exists, and the only truthfulness clause today is salary-figure-specific
  (route.js:31,35) — there is no general personal-fact constraint anywhere.
- Failure direction (safe side is the passing side): the framing must fail toward refusing to invent. A
  first-person draft that asserts an unprovided credential is the worst outcome; the passing state is the
  one where the constraint is present and bundled.

### AC-7 — Scope: the toggle changes VOICE ONLY, not the chat's inputs or capabilities [OFFLINE] [GUARD, meaningful on the built diff]
Flipping the toggle must not change WHAT context the chat sends or WHAT it can do — only the persona.
With ON vs OFF for the same conversation and state, **every request field except the as-me flag/framing
is identical**: `messages, resumeText, applications, pinnedContext, attachedFiles, tab, section, engine`
(chatbot.js:609-625) are byte-for-byte the same; no context is added or dropped, no cap changes, no new
network call is made.
- Instrument: client fetch-spy diff of the two payloads (equal except the as-me field); server wire diff
  (equal except the bundled framing).
- On HEAD this is vacuous (one state); it is a real, checkable guard once the toggle exists. Not counted
  as discriminating coverage.

### AC-8 — Scope: the persona does not leak into any other surface [OFFLINE sweep] [GUARD]
Only the Ask-AI chat carries as-me framing. No other LLM call site is affected: the tailor engine
(lib/llm/tailorResume.js), the copilot answer route (app/api/copilot/answer), the salary-estimate
request, and the reviewer (N103/N104/N106) send the same prompts as before.
- Instrument: a scoped census (grep) that the as-me framing constant/flag is referenced only by the chat
  request builder (lib/chat/chatbot.js) and the chat route (app/api/chat/route.js), with a canary
  (a known positive: `SYSTEM_PROMPT` is referenced by route.js only). Report both counts.
- Failure direction: any reference from another route/engine is a leak and is defective.

### AC-9 — Embedded path degrades honestly (no first-person drafting, no misrepresentation) [OFFLINE] [RED/HEAD for the interaction]
First-person drafting is OUT of scope on the embedded (no-AI) path (§2). But the embedded path must not
MISREPRESENT its generic advice as the user's first-person draft when the toggle is ON. Required
behaviour (design picks one, AC pins the constraint): when the engine is embedded, either (a) the toggle
is disabled/hidden with a brief reason, or (b) it is inert and the panel clearly indicates "answer as me"
is unavailable offline. Either way, `localChatReply` output is **unchanged by the flag** and is never
presented to the user as something they could send as themselves.
- Instrument: `localAssistant.test.js` — `localChatReply` output is identical with and without any as-me
  signal (the embedded path takes no such input); jsdom render with `engine === "embedded"` asserts the
  toggle's disabled/hidden/inert state and that no "drafted as you" indication appears.
- RED/HEAD: the toggle does not exist, so its embedded handling does not exist.
- Failure direction (safe side is the passing side): embedded output must never carry an ON "as me"
  indicator over generic coaching prose — that would be the fabrication/honesty violation by another door
  (the egress/under-claim trap: over-claiming the user's authorship is the lie).

### AC-10 — Offline vs owner-env boundary is declared (not a test) [DECLARATION]
The following are **[ENV]**, verified by the owner against the live service, NOT gated in CI, and must
not be filed by the verifier as missing coverage: that Gemini's actual reply reads in first person as the
user; and that Gemini actually declines to invent personal facts under the AC-6 framing. Everything else
in AC-1…AC-9 is **[OFFLINE]** per its instrument. The AC-6 framing is the offline proxy for the live
no-fabrication behaviour; the live behaviour itself is env.
