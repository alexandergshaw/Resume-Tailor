## Honest disclosures (loop-tdd rules 1, 4, 5, 10, 15)

- **Meaning is NOT auto-caught (AC-B3b).** `checkAddedTokens` catches added
  numbers/currency/years/proper-names ONLY. A **negation** that reuses existing tokens
  ("Acme **never** opened…") passes the automated guard — pinned as a deliberately GREEN
  control in `guards.test.js`. The confirm gate (B10/B12, exercised end-to-end in the
  mount test) is the meaning check, not the automation. Any future "smart" version of
  `checkAddedTokens` that claimed to catch this would violate the AC.
- **Grounding (brief item 5): smoothing does NOT ground.** It is a pure rewrite, so it
  sends no `google_search` tool — the R-267 tools-nesting trap does not apply and no
  vertexaisearch redirect can appear (there is no search). No wire test is written.
  Instead the route test asserts the request carries **no** `google_search` tool (the one
  grounding hazard that would matter: billing for search / splicing web text into the
  letter) and egress is proven at the payload level (client + route).
- **B8a is VACUOUS at HEAD.** The "unattended paths do not import the seam" assertions
  pass trivially until the module exists; disclosed above and proven load-bearing by M9.
- **B6 (post-apply undo) is NOT covered here.** It is not in this wave's must-have set;
  the confirm surface has no undo affordance in these tests. Flagged as gated follow-on
  work — a later test should mount a confirm-then-undo click restoring byte-identity.
- **Contract pinned by these tests** (a later seat may satisfy it differently, but the
  4b hand-off is): `smoothTransition.js` exports `scopeSentences`, `checkScope`,
  `checkAddedTokens`, `requestSmoothTransition` (produce, never persists),
  `confirmSmoothTransition({persist})` (the ONLY write path, records `acted`),
  `declineSmoothTransition` (records `refused`/`declined`), `SMOOTH_ENDPOINT`. The
  smoothing seam is imported by the **UI/route**, NOT by `useCompanyResearch.js` (so
  B8a's own-module guard holds); the hook only gains a generic `applySmoothedFact` persist
  path that mirrors `moveInsertedFact`. All `recordDecision("fact-smooth", …)` calls live
  in `smoothTransition.js` so the ledger module set stays unique.
- **jsdom (rule 14):** the mount test drives real clicks through `DocumentPreviewMount`
  (MUI Dialog portals to `document.body`, so queries go through `document`), mirroring the
  shipped `moveInsertedFact.rc.test.js` — no `scrollWidth`, no faked events.
