## 1. The fix itself, end to end on the SPLICE path (attack item 1)

**Root fix** (`hello-world/lib/acceptedFacts/factInsertion.js:425-457`,
`applyForwardNudge`): on HEAD-of-round-1 the function returned
`{ ...cover, lines, record: records, nudgedCount }` -- `cover.edits` (the exact
input `applyCoverDocxEdits` splices into the docx, `useCompanyResearch.js:857`)
was left as the plain, un-nudged insert. The fix adds a `beforeByLine` map
(`:434`) seeded from `planCoverFacts`' own edits (each entry's `before` is
already the true pre-insert original), then, for every line a nudge move
touches for the FIRST time in this call (`:441-443`), records that line's
CURRENT value as its `before` -- which, by construction, can only be reached
before anything else has touched that line, so it IS the true original. The
final `edits` array (`:451-454`) reads `after` off the fully-nudged `lines` and
drops any line whose net effect collapsed to a no-op (`before === after`).

## 3. New edges the fix may introduce (attack item 3)

  (no-op, bytes unchanged).** The shipped `factForwardNudge.test.js`
  (`:173-195`) only asserts `cover.lines` is unchanged for this case, never
  `cover.edits` -- a real gap for the splice claim specifically. I wrote and ran

  `cover.edits` is BYTE-IDENTICAL to the un-nudged plan's edits (not merely
  `cover.lines`). **1/1 passed.** Traced why: when `nudgedCount === 0`, the
  return (`factInsertion.js:449`) spreads `...cover` first, so the pre-existing
  `cover.edits` from `planCoverFacts` survives untouched -- correct, since
  `lines` also reverts to the pre-nudge-attempt value for every failed move.

  the shipped `factForwardNudgeSplice.test.js`'s own "AC-C9 + splice" describe
  block (`:244-270`): reconstructs the nudged, ordered, once-each letter for a
  coalesced pair. Ran directly as part of item 1's 11/11 pass.
- **A nudge composed with a placement that already put the fact last.**
  `"current"`/`"teaching"` placements use `position: "end"`
  (`lib/document/coverLetterWeave.js:13-14`) -- the fact starts as the LAST

  (`lib/acceptedFacts/factMove.js:315-329`). No shipped Wave-2-r2 test exercises
  a two-line-touch splice reconstruction (every fixture there uses `"intro"`, a
  same-paragraph single-line move). I wrote and ran a probe
  (`crossParagraphNudgeProbe.test.js`) for this exact composition: the
  reconstruction succeeds and matches the visible nudged letter. Notably, the
  source paragraph's NET edit collapses to a no-op (insert, then immediately
  excise, nets back to the pristine text) and the fix's `before !== after`
  filter (`factInsertion.js:453`) correctly DROPS it -- only the destination
  paragraph's real change survives into the splice input, confirmed by
  asserting no edit exists for the source line. **1/1 passed** (my own first
  draft of this probe asserted the wrong thing here -- a naive two-line diff --
  and I corrected it after seeing the real, and more elegant, no-op-collapse
  behaviour).
