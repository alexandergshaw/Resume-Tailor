## 3. Prefetch + cache architecture

### 3.1 TWO caches in `lib/copilot/answerSessionCache.js` (eviction hole closed structurally)
```js
// POOL (READY): posting-only, question-INDEPENDENT. One key per (user, application).
// Protected from per-question churn by living in its OWN Map.
export const idealProjectPoolCache = createTtlCache({ ttlMs: 30 * 60 * 1000, maxEntries: 200 });

// TAILORED (bonus cache for exact repeats only). Its eviction is correctness- AND ms-NEUTRAL:
// a missing tailored entry just re-generates on the next identical question (seconds, the TAILORED
// budget anyway). So its churn can NEVER evict a pool key and can never break the READY ms promise.
export const idealProjectTailoredCache = createTtlCache({ ttlMs: 30 * 60 * 1000, maxEntries: 200 });
```
**Why two caches, not one shared bound (the check's blocker 5).** r1 put pool and per-question keys in
one 200-entry cache. The pool key is written FIRST in a session, so it is the OLDEST entry and the
FIRST evicted once per-question keys fill the bound — breaking the ms promise mid-session. Splitting
the Maps makes that **impossible**: per-question entries cannot reach the pool Map at all. The pool
cache holds at most one entry per `(user, application)`; a single interview session therefore adds
exactly ONE pool entry no matter how many questions are asked, so a session can never evict its own
pool key, and 200 pool entries = 200 concurrent distinct `(user, application)` sessions on one
instance (the same concurrency reasoning `answerContextCache`'s own comment at `:150-166` already
states — NOT a byte bound). The tailored cache's 200 is **not load-bearing**: eviction there costs only
a re-generation of an exact-repeat question, which is already allowed to take seconds, so the number is
a soft cap to stop unbounded growth, not a latency guarantee. Stated honestly here rather than claimed
to "match existing caches."

**Header invariant (`answerSessionCache.js:33-42`) is satisfied, not bypassed.** That header forbids
caching anything "ranked/scored against THIS question's text," with application-scoped exceptions.
`idealProjectPoolCache` is **question-independent by construction** (built with `question:""`), so it
falls squarely inside the same exception class as `codeLanguageCache` (application-scoped model result).
`idealProjectTailoredCache` IS question-scoped — made safe a different, stronger way: **the question is
part of the key**, so "answer question two with question one's selection" is structurally
unconstructible (a different question is a different key), and its eviction is correctness-neutral.
Both caches get a header paragraph stating this.

### 3.2 New module `lib/copilot/idealProjectResolver.js` (server-only; imports the Gemini client)
Mirrors `answerCodeLanguage.js` exactly (gates-first, void start, explicit peek, one try/catch around
client setup + `.get()`).

```js
import { normalizeQuestion } from "./questions.js";             // REUSED — already exists (questions.js:22)
import { idealProjectPoolCache, idealProjectTailoredCache, settleWithin } from "./answerSessionCache.js";
import { generateIdealProjectExample } from "./answerAids.js";  // existing loader body (answerAids.js:100)
import { wantsEmbedded } from "@/lib/llm/featureEngine";
import { getServerEnv } from "@/lib/config/env";
import { getGeminiClient } from "@/lib/llm/geminiClient";

const MAX_QUESTION_KEY_CHARS = 2000; // == route.js MAX_QUESTION_CHARS; the route caps `question` first

// Pool key: posting-only. Tailored key: posting + collision-safe question key (§7).
export function idealProjectPoolKey(userId, applicationId) {
  return `${userId}::${applicationId}::ip`;
}
export function idealProjectQuestionKey(question) {        // §7 — collision-safe, deterministic
  return normalizeQuestion(question).replace(/[\s?.!,;:—–-]+$/u, "").slice(0, MAX_QUESTION_KEY_CHARS);
}
export function idealProjectTailoredKey(userId, applicationId, question) {
  return `${userId}::${applicationId}::ipq:${idealProjectQuestionKey(question)}`;
}

// READY prime: at most one POOL generation per key per TTL; returns nothing (void start — an await is
// unwritable, the codeLanguage precedent). `question` is "" for the pool, ALWAYS.
export function startIdealProjectResolution({ engine, description, cacheKey }) {
  if (wantsEmbedded(engine)) return;                       // embedded gets no model example, EVER
  if (!String(description || "").trim()) return;           // no posting -> no key written, nothing to ground
  try {
    const { geminiModel } = getServerEnv();
    const client = getGeminiClient();
    idealProjectPoolCache.get(                             // SYNCHRONOUS — loader fires this tick
      cacheKey,
      async () => ({ project: await generateIdealProjectExample({ client, geminiModel, description, question: "" }), resolvedAt: Date.now() }),
      { now: Date.now() },
    );
  } catch { /* no key / sync client-construction failure -> nothing resolved, nothing thrown */ }
}

// Pure. Starts nothing. `project` is an object or null (never a truthy sentinel), so `hit?.project ||
// null` is safe — the `|| fallback` ban that bites codeLanguage's `NONE` does not apply.
export function peekIdealProject(cacheKey) {
  const hit = idealProjectPoolCache.peek(cacheKey);
  return hit?.project || null;
}

// TAILORED: a live per-question call, AWAITED only by its own non-blocking channel. Caches the
// result under the tailored key for exact-repeat instant serve; its eviction is harmless (§3.1).
export async function resolveTailoredIdealProject({ engine, description, question, cacheKey }) {
  if (wantsEmbedded(engine)) return null;                  // embedded: no model, ever
  if (!String(description || "").trim()) return null;
  try {
    const { geminiModel } = getServerEnv();
    const client = getGeminiClient();
    const hit = idealProjectTailoredCache.peek(cacheKey);
    if (hit?.project) return hit.project;                  // exact repeat already resolved
    return await idealProjectTailoredCache.get(            // collapses concurrent identical asks
      cacheKey,
      async () => ({ project: await generateIdealProjectExample({ client, geminiModel, description, question }), resolvedAt: Date.now() }),
      { now: Date.now() },
    ).then((e) => e?.project || null);
  } catch { return null; }
}
```
**Loader caches a resolved `{project:null}` on model failure (NOT a rejection).** `generateIdealProjectExample`
swallows errors and returns null, so `createTtlCache` caches `{project:null}` and will not retry within
the TTL — a deliberate cost bound (at most one pool generation attempt per TTL, same posture as
`answerCodeLanguage.js` caching `NONE`). A transient pool failure therefore shows the deterministic
READY example for up to the TTL; TAILORED still attempts per question, and the deterministic example is
always present, so this is never an empty surface. Flagged as a residual (§13).

## 4. (B) Digit guard — COMP-SHAPED rule (orchestrator ruling) + R-135 proof

**Ruling folded in:** reject a posting number that is **compensation-shaped at ANY magnitude** — a
digit run adjacent to a pay marker. Replace the magnitude heuristic entirely. This is **MANDATORY in
`normalizeIdealProject`**, not optional.

### 4.1 The rule (replaces `idealProjectPrompt.js:209-211`)
```js
// Same number grammar digitRuns uses (idealProjectPrompt.js:132-135), but POSITIONED so adjacency can
// be tested, THEN normalized the same way (separators stripped).
const NUMBER_RE_G = /\d{1,3}(?:[,.\s]\d{3}(?!\d))+|\d+/g;

const COMP_WINDOW = 16;                                   // chars each side scanned for a word marker
const CURRENCY_BEFORE = /[$€£]\s?$/;                      // $, €, £ immediately before the run
const RATE_UNIT_AFTER = /^\s?(?:\/|per\s)\s?(?:hr|hour|yr|year|annum|wk|week|mo|month)\b/i; // $42/hr, per hour
const COMP_WORD = /\b(?:salary|salaries|compensation|stipend|bonus|bonuses|wage|wages|hourly|annually|remuneration|pay|payscale)\b/i;

function compensationShapedNumbers(description) {
  const text = String(description || "");
  const out = [];
  for (const m of text.matchAll(NUMBER_RE_G)) {
    const start = m.index, end = start + m[0].length;
    const before = text.slice(Math.max(0, start - COMP_WINDOW), start);
    const after = text.slice(end, end + COMP_WINDOW);
    const comp = CURRENCY_BEFORE.test(before) || RATE_UNIT_AFTER.test(after) ||
                 COMP_WORD.test(before) || COMP_WORD.test(after);
    if (comp) out.push(m[0].replace(/[,.\s]/g, ""));      // normalize == digitRuns
  }
  return out;
}

// ...replacing idealProjectPrompt.js:209-211:
const postingNumbers = new Set(compensationShapedNumbers(description));
const exampleNumbers = digitRuns(allText.join(" "));
if (exampleNumbers.some((n) => postingNumbers.has(n))) return null;
```
`digitRuns` and every other guard (`:197` first-person, `:198` junk, `:201-204` metric/figure digit,
`:160-191` shape/arity/labels/order/word-bounds) are UNCHANGED — only `:209-211` change.

**"k" is deliberately NOT an independent marker.** A bare trailing "k" is a magnitude suffix on counts
as often as on pay ("5k users" is a count — an incidental integer that MUST pass). `$5k` is caught by
`CURRENCY_BEFORE` instead. This is the faithful reading of "incidental non-comp integers PASS."

| Posting text | Run | Why not comp-shaped | Result |
|---|---|---|---|

The rule is strictly MORE lenient than the old blunt "any posting digit run" (it only rejects the

example that happens to reuse that exact integer is rejected and falls back — correctness-safe (the comp
number is never shown), mild quality cost. Window=16 word-marker reach can, rarely, mark a non-comp
number sitting within 16 chars of `pay`/`bonus` used non-monetarily; `$`-adjacency (the highest-precision
signal) carries all four proof cases, so word markers are additive recall only (§13).

## 7. `normalizeQuestion` / the question key (collision-safe)

**`normalizeQuestion` already exists** (`lib/copilot/questions.js:22-24`): `(text||"").trim().
toLowerCase().replace(/\s+/g," ")`. It is NOT re-invented. The TAILORED key is a dedicated derivation on
top of it (`idealProjectQuestionKey`, §3.2): existing normalization THEN strip trailing punctuation/
dashes/whitespace THEN cap at `MAX_QUESTION_KEY_CHARS` (= the route's `MAX_QUESTION_CHARS`, 2000).

**Why two distinct questions cannot collapse to one TAILORED key:**
- `normalizeQuestion` preserves every interior token and its order (it only lowercases, trims ends, and
  collapses whitespace RUNS to a single space — it never deletes or merges non-space characters).
- The trailing strip removes only TRAILING separators; it cannot merge two interior tokens.
- The cap is 2000, and `route.js:391`/the endpoint cap `question` to `MAX_QUESTION_CHARS` BEFORE it
  reaches this function, so the cap here can only ever re-truncate an already-2000-char string — it is
  never the binding constraint on a real interview question, and two questions differing within 2000
  chars keep distinct keys.
- Worked example: `"Tell me about a time you led a team."` → `"tell me about a time you led a team"`;
  `"Tell me about a time you resolved a conflict?"` → `"tell me about a time you resolved a conflict"` —
  distinct from token 7 on. Questions that differ ONLY in case / surrounding whitespace / trailing
  punctuation collapse to the SAME key BY DESIGN (same question → one tailored example → one cache
  entry), which is correct, not a collision.
- The only theoretical collision — two questions identical through char 2000, differing only past it —
  is unreachable after the route's own 2000-char cap.
