## 0. Answers at a glance

**(b) responseSchema x urlContext/googleSearch in the SAME call.** The design's belief ("mutually exclusive") is **correct for the model this repo is configured to use and wrong as a general statement.**
- On `gemini-2.5-flash` (repo default, `lib/config/env.js:14`) and every non-Gemini-3 model: structured output ALONE is supported and tools ALONE are supported, but Google documents the combination ("Structured outputs with tools") as a **Preview feature "available only to Gemini 3 series models, `gemini-3.1-pro-preview` and `gemini-3.8-flash`"**, covering Google Search, URL Context, Code Execution, File Search and Function Calling (rows B2-B3; page last updated 2026-09-02 UTC; confirmed by three independent fetch routes). So a call carrying `urlContext` must NOT also carry a JSON schema on 2.5 Flash.
- On Gemini 3 the combination is documented as supported, **but through a different request field**: `responseFormat: { text: { mimeType, schema } }` (generateContent) / `response_format` (Interactions) - not `responseMimeType`/`responseSchema`/`responseJsonSchema`. **The pinned SDK 2.6.0 silently DROPS `config.responseFormat` on `models.generateContent`** (measured, row B6): the request goes out with an empty `generationConfig` and no error. So on the pinned SDK the documented Gemini-3 route is reachable only through `client.interactions.create` (top-level `tools` and `response_format`, measured forwarded) or after an SDK bump that is itself unverified (row B8).
- The server's actual behaviour on 2.5 Flash (HTTP 400 vs silently ignoring one of the two) was NOT observed: no API key in this checkout. Do not assert the error text from this ledger.

**(a) single composite call or chain.** Primary sources do not prescribe a call count for a multi-document output; they BOUND the choice, and the bounds point to a **chain** for the configured model: (1) tools+schema in one call is Gemini-3-Preview only (B2); (2) Google's only documented multi-step guidance is decomposition/prompt chaining - "Break down prompts into components" (A1); (3) output size is NOT the constraint - 65,536 output tokens on both 2.5 Flash and 3.8 Flash (A3), so two résumés plus analysis fit comfortably. A single composite structured call is admissible only on the no-tool branch (the route already drops the URL and sends scraped text whenever the scrape succeeds, G5) and its internal ordering is controllable because Google documents output key order = schema key order (A5). Recommended shape: **chain at the orchestration layer** (optional stage 0 URL read as free text when only a URL exists; then schema-constrained stages), matching how today's feed-forward already works.

**(c) model id and call signature.** Repo: `@google/genai` 2.6.0 (latest on npm is 2.27.0, 2026-10-02), single client at `lib/llm/geminiClient.js:12`, model from `getServerEnv().geminiModel`, default `gemini-2.5-flash`, app-wide (not per engine). Google now marks the 2.5 models "limited access" (2026-09-18; not deprecated, no shutdown date) and generateContent as "legacy ... fully supported" with Interactions "recommended for all new projects" (C2, C3). Wire-verified generateContent shape for the pinned SDK is in row C5.

**(d) external engine and two drafts.** The external client forwards only `{posting, workflow, values}` to `/api/v1/resume` - **never `resumeText`** (externalEngine.js `tailorResume({ jobPosting, values })`). It cannot produce an application-ready draft grounded in the user's own material, so the design's D-3/D-4 ("gemini/external implement `tailorIdeal`") is unsupported by the repo evidence (F-1). Document bytes contract: external returns a base64 string or `""`; Gemini returns none (route normalizes to `""`); `null` is the "no artifact" value only for the hiring email. The client's per-scope byte plumbing has exactly one résumé slot, so a second résumé scope falls into the résumé branch of `buildDownloadArgs` and would be served the WRONG document's bytes (F-3).

### Findings that change the design (IDs for the checker)
- **F-1 (blocker for D-3/D-4):** external cannot supply `tailorIdeal` (rows D1-D4).
- **F-2 (trap):** `config.responseFormat` (the docs' own current JS sample) is silently dropped by SDK 2.6.0 (B6).
- **F-3 (trap):** a new docx scope sent through `buildDownloadArgs` unchanged reads `entry.docxB64` - the application-ready's bytes (D6).
- **F-4 (constraint):** tools+schema in one call needs a Gemini-3 model, but `GEMINI_MODEL` is one app-wide string (C4).
- **F-5 (hazard):** the tailor path never reads `finishReason`/`usageMetadata`; a schema-constrained long JSON truncated at `MAX_TOKENS` is invalid JSON and thinking tokens count against the limit (A3, A4).

## 1. Method, instruments, blind spots

- **Docs.** Fetched with the WebFetch tool, which routes each page through a small summarising model. Quotes in this ledger are as returned and NOT byte-verified against the HTML. Every load-bearing quote was obtained at least twice from differently-prompted fetches; the single most load-bearing sentence (B2) was additionally reproduced by a web-search index of the page. - **Docs shape changed.** As of 2026-10 the Google docs are Interactions-first: `https://ai.google.dev/gemini-api/docs/structured-output` documents the Interactions API (`response_format`); the generateContent variants live under `/docs/generate-content/...`. Memory/ledger entries older than 2026-09 describe the old layout.
- **SDK.** Types read directly from the installed 2.6.0 package. Wire shape measured with `globalThis.fetch` stubbed (per `gemini-tools-nesting` memory: stubbing `httpOptions.fetch` does not stub). Controls in the probe: C0 no-config (no-op control), C1 canary (nested `tools` must appear), C2 negative control (top-level `tools` must be absent); all three behaved as expected, every probe issued exactly 1 stubbed request (request count 1 per probe, zero real traffic).
- **Repo greps.** Search root `hello-world/` excluding `node_modules`, `.next`, `coverage` (Grep tool, ripgrep). Each negative below names the pattern; blind spot: dynamically built config keys and anything outside `hello-world/`.
- **No live call.** `Gemini_LLM_API_Key`, `GEMINI_API_KEY`, `GOOGLE_API_KEY` are all unset in the process environment (boolean checks only; `.env.local` exists and was deliberately not read). Server-side behaviour is therefore doc-only throughout.
