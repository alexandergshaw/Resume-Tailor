## 0. Summary (the binding decisions of this plan)

1. **The marathon is wider than the four named controls, and the biggest single item is a paragraph.** At 375px, live, the page above the first answer bullet is roughly 900-1080px with a typical 250px pinned strip (estimate, section 1.3). The largest reducible block is `shareInstructions` (about 116-156px including margin), a PRE-session instruction that is still on screen all session and says the questions are "detected on the right" (there is no right column on a phone). The control row the design singled out is NOT a big height win (section 1.3: 108px compact vs 112-138px today).
2. **N144b-live core = four xs-and-live-only edits plus one headroom extraction, all conditional renders, none a reorder:**
   - M1 do not render the `shareInstructions` paragraph while live at `xs`.
   - M2 in `SessionControls`, at `xs` and live, keep Stop, status pill, clock and Auto-draft inline and tuck Copy, Clear and Download session log behind ONE `CollapsibleAid` (reuse). This is a mistap-safety and clutter win, not a scroll win: `Clear` wipes the transcript, every detected question and the confirm gate with no confirmation and no undo (`useLiveSession` `clearAll`), and today it sits 12px from Copy and Download.
   - M3 do not render the `TabHeader` description while live at `xs` (title stays, so heading order is untouched).
   - M7 give the warning `Alert`'s dismiss button the 44px touch floor (`TOUCH_ICON_SX`); today it is MUI's default small IconButton.
   - S0 (first, behaviour-preserving) extract `railContent` and `onCueActivate` out of `CopilotClient.js` into `app/copilot/LiveRail.js`, because `CopilotClient.js` is at 945 of 950 lines.
3. **No reorder is proposed in this slice.** Every candidate for moving below the answer fails on a stated ground (ManualQuestion: the Add result renders in the dashboard ABOVE it; SessionSetup: the in-person recording notice must stay on screen all session, BUG-4; Stop: it is the urgent control). The mechanism for an owner-ordered reorder is specified anyway (section 5.4): a keyed array branch, the `PracticeClient` question/dashboard precedent, with a node-identity test. Never CSS `order`.
4. **Riders (each its own commit, owner may veto):** A1 do not render `ModeSwitch` while live at `xs` (it is `disabled={live}`, a dead 60px row); A3 clamp the NON-silent hearing-strip text to two lines at `xs` so its height stops changing with every interim word (the silent sentence stays unclamped, F-05).
5. **Owner-gated, not in the core:** A2 (tuck ManualQuestion into the same disclosure; needs a ruling to raise a landed `mount.length < 600` bound), A4 (one-line setup summary), and Tier C (dashboard-first order). Section 11.
6. **Reuse, no new token.** `CollapsibleAid` (props frozen, used as-is), `createChoiceStore` + `normalizeAidChoice` from `lib/copilot/aidDisclosure.js`, `TOUCH_TARGET_SX` / `TOUCH_ICON_SX` from `app/theme/mobileSx`. No edit to `mobileSx.js`, `CollapsibleAid.js`, `useLiveColumnHeight.js` or the wrapper `sx`.
7. **Two landed-test budgets are nearly spent and are the plan's real constraints:** `CopilotClient.extraction.test.js` "is at most 950 lines" (5 lines of headroom) and `SessionControls.extraction.test.js` "[control] the mount slice really is the mount" (`mount.length < 600`; measured 545, `compact={isMobile}` takes it to about 578). Section 5.
8. **Honest limit.** Core + riders remove an estimated 220-350px of about 900-1080 (roughly 20-35%). That is real but is not "the answer is on the first screen". Whether that is enough is a geometry question for the owner's phone; section 10 is the pass and section 11 OD-B1 is the decision it feeds. N144b-practice (b2) is a separate chunk (section 7).

### 1.4 Click and thumb budget (frequency-weighted, the reason for the tuck)

The answer is read once per question (many times per interview). Copy, Clear and Download are used after the interview, when the row is back to inline (idle shows everything). Making a rare action cost one extra tap in exchange for removing an adjacent destructive target during a live session is the right trade under minimize-clicks. A stray tap on Clear mid-interview today loses every detected question and answer with no confirmation. (The same hazard exists on desktop; that is a separate backlog item, section 11 OD-B3.)

### 2.3 Considered and rejected for this slice (with the evidence)

- **R1 - ManualQuestion below the dashboard (design B2).** The Add flow's RESULT renders in the dashboard (and the confirm gate's `WaitingList`) ABOVE the field. Below the dashboard, `WaitingList`, `HistoryList` and `DeliveryPanel` the field is the last thing on the page; the person scrolls down, types, taps Add, then scrolls back up to see the answer. Saves 60px per question, costs a long scroll-and-return on the one flow that uses it. Also: collapsing it behind its own header saves 0px (header 44px = field row 44px).
- **R2 - SessionSetup below the dashboard.** Its in-person recording notice is deliberately outside the Collapse so it is on screen for the whole session (BUG-4; AC-H6 BUG-H4: auto-hiding it is the same failure by another route). Interview type and posting can change mid-interview by design (SessionSetup comments, contract 6 redraft).
- **R3 - SpeakerBar into a strip.** It is already one wrapping row of at most label + two chips, in-person only. A strip is not shorter, and putting it in the pinned strip spends the 60% sticky budget (`useStickyTop` / `STRIP_MAX_SHARE`).
- **R4 - a fixed bottom Stop bar (thumb zone).** Fights the iOS URL bar and keyboard, and `PHONE_PANE_SX`'s own comment records the `vh` trap (large-viewport height clips when the URL bar is expanded). Not now; revisit only after G0.
- **R5 - dashboard-first (Tier C).** Would save about 450px (everything between the strip and the dashboard) but moves Stop and the recording notice below the answer. Either duplicate Stop into the pinned strip (about +52px against a budget with about 108px spare, `AskAiBox.js` header) or accept Stop far from the top. Owner decision, section 11. Mechanism pre-specified in 5.4.
- **R6 - tabs or an exclusive accordion for the controls.** The controls are not alternatives to each other; independent disclosure is the shipped N144a pattern.
- **R7 - hiding Auto-draft.** It decides whether answers appear; a person who suspects "nothing is drafting" must find it in one glance.

## 3. UX detail

### 3.1 State table (`SessionControls`, xs means below 600px)

| State | xs | sm+ |
|---|---|---|
| idle / never started | full inline row (Start session, pill, Auto-draft, Copy, Clear, Download, caption). Auto-draft is a pre-start choice, Download/Copy matter after Stop. | unchanged |
| connecting | `live` is true: compact row | unchanged |
| live | compact row 1 + disclosure header (collapsed by default) | unchanged |
| error (status "error", `live` false) | full inline row with Start as the retry; the Alert above carries the error | unchanged |
| stopped after a session | full inline row: Download and Copy are right where the person needs them | unchanged |

### 3.2 The disclosure

- Header: the shipped `CollapsibleAid` (native button, one tab stop, Enter/Space, `aria-expanded`, `aria-controls`, 44px at xs, static accessible name, body UNMOUNTED when collapsed). Default label `Copy, clear and download` (one constant; the name states what is inside, including the destructive item, instead of a vague "More"). Wording is the owner's and N144c's; the default is mine.
- Body: a wrapping row of the same three buttons in the same order, then the same "Available once the session has recorded something." caption with the same `id="live-download-log-reason"` and the same `aria-describedby` on Download. The buttons are the SAME JSX as the inline row (defined once as a local fragment inside `SessionControls`, placed in one of two spots), so a duplicated control row cannot exist (the failure `SessionControls.extraction.test.js` header names).
- Persistence: remembered through `createChoiceStore`, key `copilot-session-actions`, `defaultValue: null`, `crossWindow: true`, hydrated at module scope exactly as `AnswerAids.js` `createAidCollapseStore` does. `null` = not chosen = collapsed at xs. Nothing is written on mount; a tap writes the opposite of what is on screen. A person who opens it once keeps it open on later phone sessions (OD-B2 names the alternative, reset on Start).
- Only reachable (rendered) when `compact && live`; at sm+ the store is never read, so desktop is byte-identical.
- No transition, no Tooltip, no `aria-label`, no heading, no live region (CollapsibleAid's own contract).

### 3.3 Focus and identity

The Start/Stop button must be the SAME DOM node across idle and live at xs (the person has just pressed it; losing focus to `<body>` is WCAG 2.4.3). The existing component already keeps that (one `Button` in the same Stack slot, `live ? Stop : Start`). The compact branch keeps it by construction: Stack stays the first child of the returned fragment; Stop/pill/clock/spacer/Auto-draft keep their slots; only the Copy/Clear/Download children move out of the Stack and a sibling mounts after it. Tested (C7).

### 3.4 What changes at the tap on Start / Stop

At Start the page loses the share paragraph (and the description and ModeSwitch with A1), on top of the existing collapse of the whole setup block; at Stop they return. The existing setup collapse already moves the Start/Stop button by several hundred px, so this adds a smaller version of an existing jump. Whether the viewport stays put is browser scroll anchoring; iOS Safari is the doubt. G4.

## 4. `SessionControls` compact specification

Props: the 14 existing, plus `compact` (boolean, default `false`). `SessionControls` computes `const tuck = compact && live;`. `CopilotClient` passes `compact={isMobile}` (its existing `useIsMobile()`); `SessionControls` stays hook-free and stateless (its test bans `useState|useEffect|useRef|useCallback`; `CollapsibleAid` owns the hooks, and a module-scope store is not component state).

Returned shape:

```
<>
  <Stack row wrap  sx.mb = tuck ? 0.5 : 2>
    {Stop | Start}  <StatusPill/>  {clock}  <spacer/>  <Auto-draft/>  {tuck ? null : actions}
  </Stack>
  {tuck ? (
    <Box sx={{ mb: 2 }}>
      <CollapsibleAid label=SESSION_ACTIONS_LABEL choiceStore={sessionActionsCollapse}>
        <Stack row wrap sx=WRAP_ROW_SX>{actions}</Stack>
      </CollapsibleAid>
    </Box>
  ) : null}
</>
```

`actions` = Copy, Clear, Download session log, caption (the literal `aria-describedby={sessionLogHasEvents ? undefined : "live-download-log-reason"}` and `id="live-download-log-reason"` kept verbatim: `SessionControls.extraction.test.js` regexes them).

Header comment of `SessionControls.js` is amended (the test invites amendment, not deletion): state that the tuck's open state lives in a module-scope choice store read by `CollapsibleAid`, not in this component. The stale sentence "No state and no hooks of its own" stays true of the component; add the store sentence.

No new token; `CollapsibleAid` is used as shipped; no `Collapse`, no `order:`.

## 6. Accessibility

- Reading order = DOM order = visual order. The only DOM change is that the three buttons' position is held by a native-button header, at the same place in the row sequence. Nothing is reordered.
- Native `<button type="button">` header with `aria-expanded` + `aria-controls` that resolve in both states (CollapsibleAid's always-mounted panel wrapper); accessible name = the visible label (WCAG 2.5.3), glyph `aria-hidden`.
- Touch: header uses `TOUCH_TARGET_SX` (44 at xs, `auto` from sm), Stop/Auto-draft/pill unchanged, warning dismiss `TOUCH_ICON_SX`. With the trio tucked the Stop button has no adjacent destructive neighbour (error prevention, WCAG 3.3.4 spirit).
- Live regions: none added. `SpeakerBar`'s and `ManualQuestion`'s regions stay mounted-empty-first; the consolidated region, hearing-strip regions and `role="alert"` for silence are untouched. M1/M3/A1 unmount static text and a disabled control only.
- Contrast: new header text is `--text-secondary` (CollapsibleAid, already pinned); no `--text-muted` on new text.
- Hidden content is removed (unmounted), not styled away, so AT and tab order agree.
- Known edge, not new: `Clear` disables itself when the lists empty; if it held focus the browser may drop it (same on desktop today). The header remains the stable focus anchor.
