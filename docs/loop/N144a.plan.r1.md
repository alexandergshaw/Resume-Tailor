## 0. Summary (the binding decisions of this plan)

1. **Where "answer + points" live (the scope question).** They are rendered by `AnswerLines` (`hello-world/app/copilot/AnswerLines.js`, default export `AnswerLines({ lines, expansion })`), never by `AnswerAids`. `AnswerAids` owns only the SECONDARY material that sits under them. The "answer" in this product IS the drafted STAR-labelled points list: `answerLines(cues, points, pageSources)` yields `{ label, cue, point, emphasis, pageSource }`, rendered as one `ul`, one `li` per point, each carrying its cue, its speakable sentence, an optional citation line, and a per-line "More detail" button. There is no separate answer paragraph. **N144a does not touch `AnswerLines`, the panel shells, or any of the four call sites.** (Section 1.)
2. **The accordion wraps exactly three blocks inside `AnswerAids`:** "Words from the posting to work in", "Tech buzzwords", "Example projects (invented)". The resume group (role row + "Project to talk about") stays as it is: always visible, no header. Each of the three starts collapsed at `xs` (< 600px, `useIsMobile()`) and open at `sm`+ (D2).
3. **Shared component `CollapsibleAid`** at `hello-world/app/copilot/CollapsibleAid.js`: independent disclosures (NOT an exclusive accordion: opening one never closes another), native `<button>` header whose accessible name is its static visible label, body UNMOUNTED when collapsed, instant (no transition), no heading element, no live region of its own. State is per section, remembered via `createChoiceStore` (`open | closed | null`; `null` = "use the breakpoint default"), so the default can change later with no migration.
4. **No new token in `app/theme/mobileSx.js`.** `TOUCH_TARGET_SX` already is the whole >=44px requirement, and a landed test pins that module's export list at exactly 11 names ("exports exactly these 11 names, no more, no fewer"): adding a token would red it. The header's remaining styles are one local constant in `CollapsibleAid.js`. (Section 4.)
5. **One new React-free module, `hello-world/lib/copilot/aidDisclosure.js`,** holding the two pure rules (`normalizeAidChoice`, `resolveAidOpen`). It must land in the SAME commit as its consumer: the export-reachability sweep pins an exact count of exports used only by tests, so a lib export with no shipping importer reds it. (Section 7.)
6. **Existing N143/N150 tests stay green by construction, not by coincidence-proof:** jsdom has no `matchMedia`, so `useIsMobile()` is `false` in every existing AnswerAids mount and every group is open. That also means NO existing test can see the mobile branch; the mobile behaviour is covered only by new tests with a `matchMedia` stub (section 7.2).
7. **Five owner-facing items** (section 9): tech-header provenance word, the default breakpoint (`<600` vs `<900`), resume group stays uncollapsible (confirm), desktop look of the header row (confirm after the browser check), and an honest note that "open once on a phone" persists across questions.
8. **Honest limit of this slice.** N144a shortens what sits BELOW the points. It does not shorten what sits ABOVE the answer (the control stack: SessionControls, ManualQuestion, SessionSetup) - that is N144b. Do not read "collapse removes the scroll marathon" off this slice alone; the checklist (section 8) measures the aids region, not time-to-first-bullet.

## 2. UX detail

### 2.1 Interaction model

- **Pattern: independent disclosures, not a mutually-exclusive accordion.** Under live pressure a candidate must be able to open "Example projects" without the points or another aid moving or closing. Opening/closing one section never changes another. (D1 says "accordion"; the visual is an accordion, the semantics are the APG Disclosure pattern x3. This is stated so nobody builds exclusive-open.)
- **Click budget:** answer + points 0 clicks; any one aid 1 tap; all three 3 taps. No "expand all" control (minimize-clicks: it would add a control to save two taps).
- **Header:** one native button per section, full width at `xs` (the whole row is the tap target), left-aligned label with a leading down/right triangle glyph (U+25BE / U+25B8) in an `aria-hidden` span - the exact treatment already used by `ExampleProjectsGroup`, `HistoryItem` and `TranscriptDisclosure`. The accessible name is the visible label only and is STATIC: it does not swap between "Show"/"Hide" wording (state is `aria-expanded`'s job; a name that changes AND an `aria-expanded` double-signals; `TranscriptDisclosure` does swap its wording and is not the model here).
- **Body:** unmounted when collapsed (out of the accessibility tree and the tab order, matching `ExampleProjectsGroup` today). **No transition**: nothing in the app honours `prefers-reduced-motion` (stated in `AnswerAids.js` at the static `Skeleton`), and `Collapse` keeps children mounted by default. Expansion is instant.
- **Focus:** stays on the header after a toggle in both directions (the button persists). Tab order = DOM order = visual order = header, then its body. No arrow-key roving (not required for the Disclosure pattern; each header is its own tab stop - up to 3 added tab stops per card, an accepted cost).
- **Keyboard:** native `<button type="button">` gives Enter and Space for free. jsdom does not synthesise a click from a key press, so Enter/Space is asserted by "it is a real `BUTTON` element" in unit tests and exercised for real in the owner pass (section 8, G10).
- **Pending / failed bodies:** Tech buzzwords pending ("Finding tech terms for this question..."), failed, and Example Row 1/Row 2 warming/failed/pending lines live INSIDE the body, so on a phone they are hidden until expanded. The header is the same in every state. (A "ready" cue on the header is a deferral, section 9.)

### 2.2 The breakpoint-aware default (the rule)

| Stored choice | `isMobile` (< 600px) | effective |
|---|---|---|
| `"open"` | any | open |
| `"closed"` | any | closed |
| `null` (never chosen) | `false` | open |
| `null` | `true` | `defaultOpenOnMobile` (false for all three sections in this chunk) -> closed |

- A tap writes the opposite of the EFFECTIVE state (`effective ? "closed" : "open"`), so the first tap on a collapsed phone section stores `"open"`.
- **Nothing is written on mount.** The stored value stays `null` until a person taps; that is what lets a later release change the mobile default with no migration (the point N143's UX r1 section 10 wrote down for this exact day).
- Why `useIsMobile()` (`down("sm")`, < 600) and not `useIsTablet()` (< 900): it is the same gate `CopilotClient` uses for the live height-lock (`useLiveColumnHeight(live && !isMobile)`). Below 600 the PAGE is the only scroller, so a tall card costs scroll distance; from 600 up the dashboard is its own bounded internal scroller and the half-window dual-screen case (R-142) wants today's open layout. One breakpoint, one story. Landscape phones (> 600 wide) therefore get open aids - flagged as owner item OD-2 and measured in G8.
- Crossing 600px with `null` stored flips the section (rotate a phone, resize a window). Acceptable and expected: the page itself switches layout class at that same width.
- A previously stored value wins everywhere: a person who ever expanded Examples (`"open"`) sees it open on a phone too. This is the stated "remembered" behaviour, with one honest consequence (section 9, N-1).

- No section ever shows a count, a "ready" dot, or any content from its body in the header in this chunk.

### 2.5 Desktop (`sm`+)

The visible change is structural and small: for Posting words and Tech buzzwords the label moves from the 150px `dt` column to a header row above the content (the same shape Examples already has). Net height per section is roughly one header line; the dashboard is a bounded internal scroller at `sm`+, so this does not create a hidden fold. This is a MEASUREMENT item (G7) and owner item OD-3, with a named fallback (render the two single-row groups as a two-column row on `md`+ with the header in the label column - done with grid in DOM order, never CSS `order`).

### 3.1 Files

| File | Kind | Notes |

| `hello-world/app/copilot/AnswerAids.js` | EDIT | builds three stores, replaces `ExampleProjectsGroup`'s hand-rolled header, wraps the two other groups |

### 3.2 Props (checkable)

| Prop | Type | Required | Meaning |
|---|---|---|---|
| `label` | string | yes | Visible text AND accessible name. Static per section. Carries provenance (e.g. "(invented)"). |
| `choiceStore` | a `createChoiceStore` instance | yes | uses `get`, `set`, `subscribe`, `getServerSnapshot`; values `"open" \| "closed" \| null` |
| `defaultOpenOnMobile` | boolean | no, default `false` | effective default when `choice === null` AND `isMobile`. There is deliberately NO `defaultOpenOnDesktop`: "desktop starts open" is structural. |
| `labelledGroup` | boolean | no, default `false` | wrap header + body in `role="group"` with `aria-labelledby` = the header id. Only the Examples section passes it (see 3.5 for why only one). |
| `children` | node | yes | the body; UNMOUNTED while collapsed |

Nothing else (no `id`, no `sx` passthrough, no `title`, no `summary`). The component renders nothing of its own when the caller does not render it; existence rules ("is there anything to show?") stay at the `AnswerAids` call site, exactly as today.

### 3.3 DOM contract

```
<div  [role="group" aria-labelledby={headerId}]  only when labelledGroup>
  <button type="button" id={headerId}
          aria-expanded={effectiveOpen} aria-controls={panelId}>
    <span aria-hidden="true">{glyph}</span>{label}
  </button>
  <div id={panelId}>{effectiveOpen ? children : null}</div>
</div>
```

- The panel wrapper `div` is ALWAYS mounted (empty when collapsed). It has no role, no height and no accessible presence when empty, and it makes `aria-controls` resolve in both states. (Today's Examples header leaves `aria-controls` dangling while collapsed; axe-core 4.11.4 - the copy in `node_modules/axe-core/axe.js`, `ariaValidAttrValueEvaluate` pre-check - tolerates that only because `aria-expanded="false"`. Reading that source is the verification; axe was not run.)
- Header: MUI `Button variant="text" size="small"`, `type="button"`, spreads `TOUCH_TARGET_SX` (imported from `"@/app/theme/mobileSx"`), plus ONE local constant for the rest: left-aligned, `textTransform: none`, `minWidth: 0`, `px: 0`, `color: var(--text-secondary)`, `fontWeight: 700`, `width: { xs: "100%", sm: "auto" }`, a small bottom margin only while open. `variant="text"` draws no border, which also keeps it out of the WCAG 1.4.11 outlined-control sweep (`app/theme/controlBorderContrast.test.js`).
- No heading element (header comment in `AnswerAids.js`: a new heading level under the three parent headings breaks heading order, R-125). No Tooltip (it replaces the control's accessible name - `mui-a11y-traps`). No `aria-label` override (WCAG 2.5.3 Label in Name).
- No `aria-live`, `role="status"`, or `aria-busy` on the header, the panel wrapper or the group wrapper. `aria-busy` stays exactly where it is today: on the inner pending line of Tech buzzwords / Row 2, never on an ancestor of a live region (the ChatPanel suites pin that an `aria-busy` ancestor suppresses announcements).
- No CSS `order`, no `Collapse`, no `display:none`/`hidden` trick: collapse is conditional rendering.
- Reads `useIsMobile()` through the module specifier `"@/app/hooks/useResponsive"` (so the existing `vi.mock("@/app/hooks/useResponsive", ...)` factories in the CopilotClient suites - which export `useIsMobile` and `useIsTablet` - keep applying) and the store through `useSyncExternalStore(choiceStore.subscribe, choiceStore.get, choiceStore.getServerSnapshot)`, exactly as `ExampleProjectsGroup` does now.

### 3.4 `aidDisclosure.js` (the pure rules)

- `normalizeAidChoice(value)` -> `"open"` or `"closed"` for those exact strings, otherwise `null` (today's inline lambda, hoisted so three stores cannot drift).
- `resolveAidOpen({ choice, isMobile, defaultOpenOnMobile })` -> boolean per the table in 2.2. **Object parameter, not positional**: `isMobile` and `defaultOpenOnMobile` are both booleans and a positional swap type-checks and silently inverts the rule on exactly one breakpoint.
- Both are imported by shipping code in the same commit (`normalizeAidChoice` by `AnswerAids.js`, `resolveAidOpen` by `CollapsibleAid.js`), which is what keeps `lib/sourceScan/exportReachability.sweep.test.js` (pinned TR-1 count 423, unused 488) unchanged.

### 3.5 Stores and the role=group decision

- `AnswerAids.js` keeps a private three-line helper that builds each store (`createChoiceStore({ storageKey, defaultValue: null, normalize: normalizeAidChoice, crossWindow: true })` then `.hydrate()`), because **the literal `"copilot-example-projects"` must stay in `AnswerAids.js` source** - `AnswerAids.projectExampleContract.test.js` "persists the collapse through createChoiceStore under the agreed key" greps that file for it. The key strings, not a lib constant, live at the call site.
- Storage encoding is unchanged (plain strings `open`/`closed`), so an existing user's stored `copilot-example-projects` value keeps working with no migration.
- Stores are module-scope and shared by every mounted `AnswerAids` on the page (current card, expanded history items, feed cards, sample answer): one choice per section for the whole surface. This is `examplesCollapse`'s existing behaviour and is stated, not new.
- **Only the Examples section is `role="group"`.** The landed contract test "names the group via a role=group whose accessible name is the header text" uses `el.querySelector('[role="group"]')` - the FIRST match in DOM order - on a mount that has Posting words before Examples. If Posting words were also a `role="group"`, that query would return it, its `aria-labelledby` header would read "Words from the posting to work in", and the landed test would red. Justification beyond the test: Examples' body holds multiple sub-labelled rows (own `dt`s), which is what a group names; the other two bodies are a single block named by their header via `aria-controls`. If the owner/UX prefers uniform groups, the cost is one ledger-authorised edit scoping that query to the Examples header (a planning defect to report, never a silent edit).

## 4. `app/theme/mobileSx.js` - tokens

**Add none.** Verified reasons:

1. `TOUCH_TARGET_SX` = `{ minHeight: { xs: 44, sm: "auto" } }` already is the header requirement (>=44px on phones, natural height from `sm`).
2. `app/theme/mobileSx.test.js` "exports exactly these 11 names, no more, no fewer" pins the export set; "every export deep-equals its literal table" and "every sm branch is one of the module's own permitted 'unchanged' values" pin shape and the `sm` vocabulary (`auto, none, visible, content-box, normal, block, 1.4375em`). A new token needs a ledger-authorised edit of that test. Not warranted for one consumer.
3. The "no-copies sweep" in the same file fails any file that declares its own `const TOUCH_*`, hand-rolls an `xs` floor of 38..48 (`minHeight: { xs: 44`) or the string `"44px"`, or imports the module by a relative specifier. So `CollapsibleAid.js` must `import { TOUCH_TARGET_SX } from "@/app/theme/mobileSx"` and spread it; the header's local constant must not be named `TOUCH_*`.
4. `app/copilot/mobileSx.js` must NOT be created: "the re-export shim is retired" asserts the file is absent.
5. `PHONE_PANE_SX`, `BREAK_LONG_WORDS_SX`, `WRAP_ROW_SX` are untouched; the bodies already use `BREAK_LONG_WORDS_SX`.

Heads-up routed to N144b/c: if a shared collapse-header token is ever wanted, that chunk's plan must include the explicit edit of `mobileSx.test.js` (11 -> 12 names, a new literal-table row, `sm` branch from the permitted set). N144b can instead reuse `CollapsibleAid` for "Session options" with its own store and no token.
