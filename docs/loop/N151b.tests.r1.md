## Instruments that could NOT be verified here (stated plainly)
- **BL-A (live substrate):** no test proves the live DB applied `resume_templates` (the PUT ownership read's
  target) or `template_selections`. Owner/1d must confirm before Step 1, exactly as plan §8 BL-A says. A route
  test over a mocked/in-memory client cannot see schema drift.
- **T8 ON DELETE SET NULL cascade:** the in-memory fake CANNOT prove the DB nulls the pointer on a row delete,
  and this file does NOT claim it does. The cascade LITERAL is pinned by N151a's migration-shape test
  (`templateSelectionsMigrationShape.test.js`, TL-1). What N151b proves at runtime is the SPLIT: (a) the hook
  reconciles `selectedId` to null AFTER a refetch that returns null (useTemplateLibrary "remove → null" test —
  models the cascaded GET), and (b) the resolver never renders a deleted template's bytes regardless of the
  pointer (integration T8-fallback). A real DB that failed to cascade would leave a stale GET `selectedId`,
  which only TL-1 guards.
- **exportReachability sweep:** not run (I added no production export). The implementer must give each new
  module a PRODUCTION importer IN THE SAME WAVE — hook ← page.js, panel ← ApplyingControls.js, the three client
  fns ← useTemplateLibrary.js (the PUT verb is a Next.js entry; the GET field is not an export). Otherwise TR-1
  (423) / ORPHAN (65) / UNWIRED / ALLOWED (14) / UNUSED (488) move and the sweep reds (plan R12/PL-13).
- **page.js wiring + 9b a11y gate:** not exercised. The T6 panel-render test proves ApplyingControls renders the
  panel given the prop, but NOT that page.js mounts `useTemplateLibrary` and threads `templateLibrary` +
  `onTemplatesChanged: templateLibrary.refresh` — that production call site must be checked BY HAND (the
  "harness wires differently from production" trap). R8/R9 encode the a11y contract the 9b gate also covers.
- **In-memory supabase fidelity (T7/T8/R1-integration):** the fake models the store chain idiom
  (`select().eq()…maybeSingle()`, `insert().select().single()`, `upsert()`, `delete()`, storage by path). A
  correct build using a very different builder shape could fail it; the reference run is the proof it is adequate
  for at least one correct build.
