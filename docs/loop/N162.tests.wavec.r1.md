## How each hook GETS the toggle (cited to the arch)

- **LIVE hook `useDraftAnswer` reads the store DIRECTLY** — `readIncludeCodingSolution()`
  at the one capture point, on the line below `getCodeLanguage()` (arch §6.3,

  readIncludeCodingSolution()"). It is NOT an argument. So the live test drives
  the REAL store with `setIncludeCodingSolution(...)` and asserts the hook
  forwards the value the store holds; mocking is unnecessary and a hardcode dies

  PROP** — mirroring how it already takes `codeLanguage` (arch §6.4: `request`

  passes the prop and asserts forwarding; `queue` takes the toggle as its
  trailing positional arg.

This asymmetry matches the existing code: the live hook reads stores
(`getInterviewType`/`getCodeLanguage`); the practice hook receives props.
