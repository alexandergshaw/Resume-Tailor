## matchMedia-stub approach

jsdom implements no `matchMedia`, so `useIsMobile()` is permanently false without a stub and the whole mobile branch is invisible (plan §5/§6). Each jsdom file installs the FormDialog.mobile.test.js stub shape: a `queryMatches(query,width)` that parses the real `(max-width:599.95px)` / `(min-width:…)` MUI builds, and `window.matchMedia = (q) => ({ matches: queryMatches(q, viewportWidth), … })`. MUI memoises the MediaQueryList per hook instance, so the width is set BEFORE each mount and a different width means a fresh mount (C4 and the 375-vs-1200 controls each remount). The `sx` computed cascade (the 44px floor, C11) is read with `atWidth` from `app/theme/computedStyleAtWidth.js`, which is INDEPENDENT of matchMedia — it rewrites `min-width` media rules — so geometry-of-cascade and open/closed state are driven by two different instruments, as the harness header requires.
