# N65 — Estimate a posting's salary from the Ask AI panel — Acceptance Criteria (round 1)

Owner ask, **verbatim** (backlog.yml N65, `docs/backlog.yml:260-270`, owner request 2026-09-27):

> "the ability to estimate a posting's salary when not mentioned, referencing job board sites and similar positions salaries at this company from sites like glass door, etc - from the ask AI panel"

Seat: AC only. No design, no plan, no tests, no code. Every file:line below was re-read this round unless marked **CITED, NOT VERIFIED**.

**Card is NOT paraphrased.** The card is narrower than "estimate a salary" on two axes and I follow the card: (1) **"when not mentioned"** — the estimate exists only for a posting with no stated pay; a posting that already states pay has nothing to estimate. (2) **"from the ask AI panel"** — the trigger is a user action in the Ask AI surface, not the unattended feed. Both bound the feature and are baked into the criteria below. The card's `owed_by` also states plainly: **an owner decision comes first, then a design round** — so this AC binds a design that has not been written, and it flags the two live owner decisions as blockers rather than deciding them.

## 1. Ground established this round (re-read, real file:line)

### 1a. Does a posting already carry a salary field? YES — and it means STATED pay, not an estimate.
- `feed_postings.salary_min` / `salary_max` are `integer` columns (`supabase/migrations/20260609000000_live_feed.sql:18-19`).
- They are populated **at ingestion** from board-exposed structured pay or a parse of the posting's own text: `lib/feed/ingestFeed.js:91-92`, `lib/feed/llmSearch.js:167-168` (`salary_min: salary.min, salary_max: salary.max`).
- **This is a salary the posting itself carries.** It is never an estimate of an absent one.

### 1b. Is the description text parsed for pay anywhere? YES — extraction only.
- `lib/feed/salary.js` is **extraction only** by its own header (`:1-12`): it parses a figure the posting *states* (structured columns, or a `$X–$Y` / "From $X" match in the snippet — `parseSalary`, `:76-98`) and clamps to a sane annual band (`:14-21`). It **never invents an absent figure**. Confirmed by reading the whole file.

### 1c. Is there anywhere in the UI compensation is shown? YES — and it shows NOTHING when pay is absent.
- `app/components/feed/FeedPostingCard.js:13,67-74`: prefers `salary_min/max`, falls back to `parseSalary(description_snippet)`, then `formatSalary(salaryMin, salaryMax)` (`lib/feed/salary.js:151-159`). **When both are null, `formatSalary` returns `""`** — a posting with no stated pay renders no salary at all today. This is the exact gap the owner wants filled.
- Canary: `grep -rniE "estimateSalary|salaryEstimate|estimated.?salary|estimatePay" app/ lib/` → **0 hits**; positive control `grep -rn formatSalary` (non-test) → **3**. **No salary-*estimate* feature exists anywhere.**

### 1d. What is the "Ask AI panel"? A shared chat surface with NO grounding and NO citations today.
- "Ask AI" is one chat surface reused across seven entry points, each pinning a different context payload and opening the same chat (card evidence; verified entry points at `app/components/DocumentPreviewDialog.js:685-695`, `ApplyingControls.js:354-361`, and `askAiAbout` wiring at `DocumentPreviewMount.js:395-396`).
- The panel is backed **solely** by `app/api/chat/route.js`. Read in full this round:
  - It calls `client.models.generateContent` with **only** `{ systemInstruction, contents }` (`:358-364`). **No `config.tools`, no `googleSearch`, no grounding, no citation extraction.** The reply is free-text (`response.text`, `:399-403`).
  - The system prompt **already invites an ungrounded guess**: "…only if the description text is literally empty say something like 'the posting did not include a description; **here is what I can infer from the title/company**'" (`:31`).
  - There is an embedded (no-LLM) path: `wantsEmbedded(body.engine)` → `localChatReply(...)` (`:264-277`).
- **Consequence, load-bearing:** if a user today asks the Ask AI panel "what's the salary?", the Gemini path returns a **bare, ungrounded, uncited, unlabelled number in free prose**. That is precisely the harm this feature must not ship. Referencing job-board sites requires **adding a grounded-search capability the chat route does not have.**

### 1e. The grounded-search + citation machinery that already exists (reuse targets).
- **Real publisher URLs come from the Interactions API, not legacy grounding.** `lib/llm/interactionCitations.js:1-45` extracts `url_citation` annotations carrying a **real publisher `url`** from `client.interactions.create`. The ONLY call site today is `lib/copilot/glossaryWorker.js:206`.
- **The legacy surface is a trap.** `lib/llm/grounding.js:11-20` reads `groundingChunks[].web.uri`, which is a `vertexaisearch.cloud.google.com` **redirect proxy, never the publisher URL** (memory `gemini-grounding-redirects`, verified against that module's own header at `interactionCitations.js:2-10`). A host-based check on it never matches; the redirect token 404s. **A salary "source" that is a vertexaisearch redirect is a dead link labelled with a real domain** — the exact defect N43 fixed for company facts.
- **The render-side URL contract:** `lib/tracking/citationHref.js` re-exports `safeExternalHref` (`lib/url/safeExternalHref.js`, seven falsified rules). **A refused URL renders NO anchor at all** — not `href=""`, not `#`, not an href-less stub (`citationHref.js:26-34`). Reuse this; do not re-implement.
- **Precedent for honest provenance labelling:** `FeedPostingCard.js`'s `sourceProvenance` deliberately returns `""` except for `ai_search`, "so it must not overstate what verification happened" (`:82-83`). Same discipline applies to a salary estimate's label.

### 1f. The activity-log decision ledger (re-read this round).
- `lib/activityLog/activityChannels.js`: the `act` channel is call-site, opt-in (`:57-63`). `DECISION_LEDGER` (`:215-233`) has **two** entries today (`duplicate-check`, `fact-auto-insert`). `recordDecision()` (`lib/activityLog/appActivityLog.js`) enforces a **closed `fields` vocabulary** and normalizes to `DECISION_OUTCOMES = ["acted","skipped","refused","failed","unknown"]` (`:213`). Each entry **MUST include ≥1 outcome other than "acted"** ("an entry that can only ever report success reopens the exact hole the owner hit", `:203-205`). `decisionCoverage.sweep.test.js` `toEqual`s the ledger against a derived scan of every real `recordDecision(` call, **both directions** — a `recordDecision` call with no ledger entry (or vice-versa) turns it RED.
- Privacy precedent: the `fact-auto-insert` entry stores `["reason","count","code"]` and its comment forbids "the fact text, the company, the article title or a byte of the letter itself (N77)" (`:225-231`). The salary decision inherits this: **no estimated number, no company name, no citation URL/title in the log** — the file is downloadable and shared onward.

## 2. Scope

**In scope:** when a user, from the Ask AI panel, asks about (or invokes an affordance for) the pay of a **posting that states no salary**, the app produces a compensation **estimate** derived from a **grounded web search**, presented so that (a) it is unmistakably an estimate, (b) it is a range or an explicit "insufficient data", (c) every source shown is a resolvable publisher link, and (d) the estimate is never shown as, nor written into, a stated-salary field.

**Out of scope (do not absorb; design must not widen; verifier must not file as missing):**
- **Any automatic / per-posting / feed-ingestion estimation.** The trigger is user action in the Ask AI panel only (§ owner's words; OWNER-2 below).
- **Any scraping of Glassdoor or job-board sites directly** (OWNER-1; N49/N51 precedent).
- **Changing `feed_postings.salary_min/max`, the ingestion parse, or `FeedPostingCard`'s stated-salary render.** Those stay meaning "pay the posting states."
- **A new persistence schema** — not mandated here; if design chooses to persist an estimate it must carry its provenance and never populate the stated-salary columns (S11). Storage shape is a 1d/owner call.
- **Negotiation / "what to ask for" / "what this offer is worth to you" advice** (S9).
- **The embedded engine generating a number** (S8).
- The Resend job-alert email, and Ask AI on non-posting subjects (resume/cover-letter/experience contexts) — the estimate applies to a **posting** subject only.

## 3. Owner decisions (BLOCKERS — escalated, not decided here)

**OWNER-1 (grounded-search-only path).** The card's `owed_by` requires an owner decision, "the same shape as N49/N51's: confirm the grounded-search-only path (no direct scraping of Glassdoor or job-board sites) before any design starts." The N49/N51 precedent (boards prohibit automated access; use the existing grounded-search pipeline, never a direct fetch) strongly implies the answer, and every criterion below assumes it — **but the confirmation is the owner's, and design must not start the grounding mechanism until it lands.** *If the answer were "yes, scrape directly", most of §5's citation criteria would change; that is why it blocks.*

**OWNER-2 (spend ceiling).** Even user-initiated, **each estimate is at least one grounded provider call** (an Interactions/search turn — materially more than a plain chat turn, and unlike a plain chat turn it hits the search tool). The owner has set caps elsewhere (20 tailors/user/UTC-day; 4 mails/address/day; 10/account/day; 25 saved searches). **Question for the owner, not decided here:** is there a per-user/day cap on salary estimates, and what is it? A cap changes S8/S10/S14 (a refusal-at-cap outcome) and the 1h/1f budget. *Named as a question per the AC brief; I do not set a number.* Note: this does NOT reintroduce per-posting cost, because the trigger is user-initiated (my ruling R1) — the ceiling is on a human-paced action, which bounds worst-case spend structurally.

*(Not a blocker) The Google Additional-Terms "resolve a Link for display" ambiguity from `gemini-grounding-redirects` is **mooted** by S6: the Interactions surface returns publisher URLs directly and needs no redirect fetch. If design instead used the legacy surface it would reopen the terms question — a further reason S6 is a hard requirement.*

## 4. Rulings I make myself (reversible; stated so design inherits them, not guesses)

- **R1 — User-initiated only.** The estimate is computed only in response to a user action in the Ask AI panel with a posting pinned as the subject. The feed ingestion path (`ingestFeed.js`, `llmSearch.js`, the cron) gains **no** salary-provider call. Basis: owner's words "from the ask AI panel." Bakes into S1/S11.
- **R2 — "When not mentioned" gate.** The estimate path engages only when the pinned posting has no stated pay — i.e. `salary_min`/`salary_max` are null AND `parseSalary(description)` yields nothing. When pay IS stated, the panel surfaces the **stated** figure and does not call the estimator. Basis: owner's words "when not mentioned." Bakes into S1.
- **R3 — Provenance taxonomy.** (a) structured board columns and (b) a parse of the posting text are both **"the posting states it"** (a fact the posting carries); (c) a model figure inferred from grounded web search is **"estimated"**. Only (c) is this feature, and it is labelled and gated distinctly (S2/S4). A figure the app cannot attribute to (a) or (b) is treated as (c) — the **safe direction** (an unlabelled guess must never pass as stated).
- **R4 — Structured, app-controlled render.** The number/range and its citations are produced by app code from the grounded result's **structured fields**, not scraped from or emitted as the model's free prose (S2). Reason: only a structured path can *guarantee* the number carries a resolvable source and the estimate label; free prose cannot, and the chat route today proves it (1d).
- **R5 — Advantage class = Guaranteed** (provenance/refusal), see S13. "Attached to a tracked posting" alone is **Corpus, which the app-vs-chat measurement classes as INHERITED** (persistence is one line), so it does not by itself justify the feature; the earned, removal-testable claim is the provenance guarantee.

## 5. Acceptance criteria

Direction convention: where one error is worse than its opposite, the **safe** outcome is written as the passing one.

- **S1 — Engages only when pay is not stated; never overrides a stated figure.** With a pinned posting that has a stated salary (structured columns non-null, or `parseSalary(description)` non-null), a salary request surfaces the **stated** figure and issues **no** estimator/grounded call. With no stated pay, the estimate path runs. *Failure direction: estimating over a stated salary, or showing an estimate as if stated, is the worse error and must fail the test.*
- **S2 — No number without provenance (structural).** The estimate figure and its citations are rendered by app code from the grounded result's structured citation fields (the `url_citation` walk, `interactionCitations.js`), **not** parsed from or emitted as free model prose. If **zero** citations survive extraction, **no number is shown** — the panel states it could not find sources. *This makes the bare guess impossible, not merely forbidden; it is the removal test's target (S13).*
- **S3 — Range or "insufficient data", never a bare point presented as the salary.** A shown estimate is a **range** (or an explicit "not enough data to estimate"). A single point value presented as "the salary" fails. *Failure direction: a lone hard number reads as data; the range/withhold reads as an estimate.*
- **S4 — Always labelled as an estimate, visually and textually distinct from a stated figure.** The estimate carries an explicit "estimate" label and its basis; a stated salary and an estimate never render with identical affordance/styling. *A test that renders both and finds them indistinguishable fails.*
- **S5 — Citations resolve or do not render as links.** Each source renders as a clickable link **only if** `citationHref`/`safeExternalHref` admits it; a refused URL renders as inert text or is omitted (never `href=""`/`#`/onClick-nav). A `vertexaisearch.cloud.google.com` redirect URI is **never** shown as an openable publisher source. *Instrument feeds one redirect URI and one real publisher URI and asserts only the publisher becomes an anchor.*
- **S6 — Grounding uses the real-publisher-URL surface.** The displayed sources are real publisher hosts obtained from the Interactions surface (`client.interactions.create` → `url_citation.url`), not legacy `generateContent`+`googleSearch` `web.uri` proxies. *Behavioural: no shown source host is `vertexaisearch.cloud.google.com`; the grounded call is proven to have searched (a `google_search_call` step present) before any number is shown — an empty grounding yields a withhold, S14, never a fabricated figure.*
- **S7 — Basis honesty (support vs. membership).** The basis string is derived from the sources actually grounded and states how many. It may say "at {company}" **only if** at least one surviving citation's content is about that company; otherwise it must read generically ("similar roles in this area/market"). *Failure direction: claiming company-specificity the sources do not support is the worse error. Instrument: two fixtures — sources that name the company vs. generic sources — must produce different basis labels; identical labels fail.*
- **S8 — Embedded engine never fabricates a figure.** With `wantsEmbedded(engine)` true, a salary request returns an explicit "a salary estimate needs the AI engine and is unavailable on the embedded engine" message and **no number**. *The offline rule/retrieval path (`localChatReply`) must not emit a compensation figure. Test drives the route with `engine: embedded` and asserts no numeric salary in the reply.*
- **S9 — Presents information with provenance; gives no financial/negotiation advice.** The estimate output's structured content is limited to {range or "insufficient data", basis, breadth/confidence signal, citations, estimate label}. It contains no "ask for", "negotiate", "worth to you", or offer-evaluation content, and the grounded-call instruction constant forbids such advice. *Falsifiable part: the structured block's field set and a prompt-constant assertion. The model's free prose cannot be fully falsified — that residue is a MANUAL/measurement-limited check, said plainly, not asserted as a passing automated test (see S16).* 
- **S10 — The decision is logged, honestly and without PII.** If the feature records a decision, it is registered in `DECISION_LEDGER` with a new `id` (e.g. `salary-estimate`), `outcomes` including at least one non-`acted` value, and a **closed `fields`** set that carries **no** estimated number, company name, citation URL or title (e.g. `["reason","citationCount","basisKind"]` where `basisKind` ∈ {company, comparable, none}). `decisionCoverage.sweep.test.js` passes **both directions**. The withhold (S2/S14) and embedded-refusal (S8) and provider-fail (S14) paths each record their outcome — not only the success path. *Sweep is GREEN today (guard); the "records the withhold/refuse/fail outcomes" obligation is RED (no such recording exists).*
- **S11 — The estimate is never a stated-salary field, and ingestion gains no call.** The estimate is never written into `feed_postings.salary_min/max` (or any field `FeedPostingCard`/downstream reads as stated pay), and no salary-provider call is added to `ingestFeed.js`, `llmSearch.js`, or the tailor cron. *NON-REGRESSION GUARD — green today; guards against an estimate later masquerading as a fact or a per-posting cost sneaking into the unattended feed.*
- **S12 — Reachable from the Ask AI panel without a new wizard (minimize-clicks).** The pinned posting flows into the estimate action (the user never re-picks or re-pastes the posting); no nested-menu-to-dialog path is introduced; a dedicated affordance, if any, runs on first click. *Checkable as a click-path count at 1c and re-judged at 8b; a design that adds a multi-step wizard fails it.*
- **S13 — App-vs-chat REMOVAL test (class: Guaranteed).** One AC goes RED if the provenance guarantee is removed: with the "no number without a resolvable citation, else refuse" gate deleted, the feature must fail — because it then equals the ungrounded prose guess `app/api/chat/route.js` already produces (1d). *Lands red at 4b; 8b re-judges the shipped diff still holds it.*
- **S14 — A degraded result is distinguishable from a real negative.** A provider error, timeout, or empty grounding renders as an explicit "couldn't retrieve salary sources right now" — **never** as "no salary data", a $0/low estimate, or a silently blank result that reads as "this role pays nothing". *Failure direction: a degraded state that looks like a confident negative is the worst error (this repo has shipped that conflation before). Instrument injects a failing/empty grounded call and asserts the "couldn't check" wording, not a number and not an empty stated-salary render.*

*(S15 intentionally folded into S11.)*

- **S16 — Prose-level advice/label bleed is a stated measurement limit.** Whether the model's *free prose* around the structured block sneaks in a bare unlabelled number or advice cannot be fully falsified by an automated test (non-deterministic model output). This is recorded as a manual/adversarial check at 6/8b, not counted as an automated RED-on-HEAD criterion. The structural guarantees S2/S3/S4/S9 are what make the automated bar real; S16 exists so the verifier does not file the prose residue as an untested gap or, worse, assert a green it cannot earn.

## 6. Cumulative-surface note (constraint 6b, for the 8b re-judge)

This **ADDS** a labelled, cited estimate block to the Ask AI response surface (and possibly a one-click "estimate salary" affordance on the pinned-posting context) and **DISPLACES nothing**. The Ask AI surface is shared across seven entry points (§1d) driven by one route; a salary estimate block with a citation list is the densest thing that surface would render. The 8b re-judge should weigh the composite legibility of (a) the chat response area with an estimate block + citations, and (b) whichever posting-context surface gains the trigger — the estimate must not crowd the existing chat affordances, and the citation list must degrade gracefully to inert text (S5) rather than a wall of dead links. Placement is design's call; this note is the cost made visible at spec time.
