## 0. Verdict in six lines

1. **Layout.** Keep the header and the Context bar where they are (the refusal copy names them by location, section 6 row H1). Split everything below the Context bar into a **body** (thread, then the shrinkable review result and attachment strip) and a fixed **composer dock** with exactly two rows: a toolbar `[Review] ... [Answer as me]` above the composer row `[attach][input][Send]`. Footer rows go from 3 (up to 6) to 2 (the embedded note makes it 2 plus one caption line).
2. **Measured payoff, before -> prototype** (headless Chrome, real `ChatPanel` for "before", a scratch prototype of this design for "after"; section 1): dock 150.8 -> 93.8 px (-38%); thread 276 -> 333 px (53% -> 64% of the panel); worst vertical spread between the five composer controls 100.1 -> 41.4 px.
3. **A defect the owner did not list, found while measuring and larger than any aesthetic issue:** with a review result open, the composer and Send are pushed OUTSIDE the panel and clipped (`overflow: hidden`, no scroll can reach them) on the default 380x520 panel, on the 280x320 minimum, and on a 375x812 phone. The design makes that structurally impossible (the result shrinks, the dock cannot).
4. **Honest limit:** the pointer distance from the input to the two flanking controls (attach, Send) does not change (153/162 -> 152/161 px); they flank the input. The distances that do shrink are Review (133 -> 112) and the voice switch (160 -> 103), and the vertical spread. The top-bar controls (Clear, Close, Estimate salary, remove-context) stay ~400+ px from the input by design, because `lib/chat/refusal.js` tells the user those controls are "at the top of the panel".
5. **Invariants:** all twelve on the owner's list are preserved with the mapping in section 6, plus the ones the owner did not list that I found in landed code and tests (rows H1-H4 and section 5.4: refusal-copy location, subject naming, three source-scan guards, the landed no-collapse pin, tab order).
6. **Needs a visible browser / owner:** final visual density, the drag-hint look, the two hairlines above the attachment strip, the 48 px thread floor while a result is open, the paperclip glyph, focus-ring clipping inside the two small scrollers, iOS Safari. Section 8 draws the split.

## 2. The design

### 2.1 One paragraph

Below the header and the Context bar the panel becomes **body + dock**. The **dock** is the only thing that is never allowed to shrink: row 1 is a **toolbar** (`Review <scope>` at the left, `Answer as me` switch at the right, the embedded explanation as a caption directly under it when applicable); row 2 is the **composer** (`[attach] [input] [Send]`). The **body** is a flex column holding the thread (the existing scroll container, with a 48 px floor), and under it two optional, **shrinkable** regions in this order: the **review result** and the **attachment strip**. Result and strip grow upward from the dock, so the controls the user just used never move. The drag hint becomes a non-interactive label centred over the body, adding no layout. Nothing is hidden behind a menu, tooltip or extra click.

### 3.3 Keyboard, focus order, persistence

- DOM order = visual order top to bottom: Clear, Close, Estimate salary, remove-context, per-turn Copy/Resend, result-region controls (download, row toggles, links), chips, **Review**, **Answer as me**, attach, textarea, Send. Before: Review came BEFORE its own result and the chips. The change is the price of keeping DOM order equal to visual order (WCAG 2.4.3); the `Review of this <scope>` region keeps its landmark name, the Review button keeps `aria-describedby`, and the polite "Review finished" cue still fires.
- After activating Review focus stays on it (it never unmounts; the result mounts above it). Escape from anywhere in the panel closes it and restores focus (unchanged handler on the panel root).
- Nothing new persists. The voice setting, engine and `chatSize` already persist elsewhere; the review result stays session-only (unchanged).

### 4.2 Numeric `sx` check (mui-sx-numeric-traps), each number intended

`minHeight: 48` (thread floor) = 48 px (sizing >1 is px). `maxHeight: 120` (strip) = 120 px. `width/minHeight: { xs: 44, sm: 40 }` = px. `flex: "1 1 0"` string. `gap/p/py/px: 0.25-1.5` = spacing multipliers on purpose (2-12 px). `borderRadius: 2.5` = 20 px (multiplier of 8, the bubbles' existing value). `inset: 0` passes through as CSS. **No `visuallyHidden` rewrite**: import `visuallyHidden` from `lib/copilot/answerStatus.js` (units already correct; `visuallyHiddenUnits.sweep.test.js` scans for a fourth copy). No top-level array in `maxHeight` (a top-level array is a breakpoint list; note that `RESULT_SX.chat` already has one, harmless but not a fallback pair).

### 4.3 Breakpoints and dark mode

- Real breakpoints: `xs 0 / sm 600 / md 900`; the panel changes layout once, at `sm` (`useIsMobile`). 600-899 (tablet) renders the desktop panel at `chatSize.width` (380 default), so the desktop numbers cover it. The `xs` keys in `sx` apply at every width (`@media (min-width:0)`); every `xs` value here has an explicit `sm` branch that restates the intended desktop value.
- Dark mode: every added colour is a token. Prototype dark screenshot of S2 (voice ON) checked: switch, label, Review, Send dimmed state, hairlines all legible. The drag label uses `--text-primary` text on `--accent-soft` (10.84:1 dark, 14.36:1 light); `--accent` on `--accent-soft` would be 4.36:1 in dark and is therefore NOT used for text there.

### 4.5 Focus ring and hit targets

Focus ring is the theme's `MuiButtonBase` rule (2 px solid `--accent`, offset 2 px = 4 px outside the border box; `globals.css` 56-61 states the 4 px). Dock `p: 1` (8 px) and strip `py: 0.5` (4 px, exactly the ring) keep rings inside the panel's `overflow: hidden` and the strip's own scroller. **Not verifiable in jsdom**: ring clipping at the result region's inner scroller (pre-existing there) and at the strip's top edge; listed for the visible-browser pass.

Phone targets (all via `atWidth(375, ...)`-readable declared values): Clear, Estimate salary, remove-context (min-width 44), Review, voice label, attach, input root, Send >= 44; Close already 44. Per-turn Copy/Resend (11 px text) stay under 44 and are **out of scope** (filed as follow-up F-1, section 9).

## 5. Structure the plan seat needs (this is the contract; 1b may refine)

### 5.1 Layout contract (all flex; no container units; the guarantee is structural)

```
panel            : flex column, definite height, overflow hidden           (unchanged)
  handle         : absolute                                                (unchanged)
  header         : flex 0 0 auto
  context bar    : flex 0 0 auto (when pinned)
  body           : flex 1 1 0; minHeight 0; display flex column; overflow hidden; position relative
    thread       : flex 1 1 0; minHeight 48; overflowY auto  (existing sx + the two flex keys)
    result region: flex 0 1 auto; minHeight 0; border-top; bg-surface; internal result: maxHeight min(40vh,280px), overflowY auto
```
