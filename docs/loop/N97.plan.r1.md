## 2. Contradictions routed to me — resolved (mechanism choices are mine)

**C1 — `downloadDocxFiles` needs two template inputs, not one.** The résumé and cover `resolveDocumentBlob` calls
(`docx.js:738`, `:753`) each need their own kind's default. **Ruling:** `downloadDocxFiles` gains **two** params,
`formattingTemplate` (résumé, threaded into `:738`) and `coverFormattingTemplate` (cover, threaded into `:753`). Per-scope
callers (`buildDownloadArgs`, Drive) set only the one for their scope; the combined callers (`page.js:2081/2591`) set both.
**Proof:** a combined download with both defaults set produces a résumé carrying the résumé template's marker and a cover
carrying the cover template's marker (4b integration test).

**C2 — the override branch lives in `resolveDocumentBlobBytes`.** The exported `resolveDocumentBlob` (`:628`) only applies
the `spacing` post-pass and delegates to `resolveDocumentBlobBytes` (`:642`). **Ruling:** add `formattingTemplate` to **both**
signatures; the override branch goes at the **top** of `resolveDocumentBlobBytes` (before the verbatim-serve branches at
`:653-657`), so a set default takes precedence over the engine's own finished doc; the wrapper's `spacing` sweep is unchanged
and still runs after. **Proof:** `docx.js:637` shows the wrapper passes its args straight to `resolveDocumentBlobBytes`.

**C3 — the egress set is larger than the design stated; classify every caller.** The design listed only the modal download
and Drive. The canonical AC-4 "next generation downloads" path is the **post-generation auto-download**. **Ruling — which
callers resolve-and-pass a default (all pass `null` when no default is set, so AC-8 holds uniformly):**

| Caller | Class | This chunk |
|---|---|---|
| `page.js:2081` (`handleTailorJob` post-generation download) | current-session generation | **RESOLVE + pass both** (AC-4 canonical) |
| `page.js:2591` (`handleTailorFeedPosting` download) | current-session generation | **RESOLVE + pass both** |
| `useDocumentPreview.js:533` (modal per-scope download) | current-session doc | **RESOLVE + pass (scope's)** |

## 4. Ordered steps (each independently landable, each with its tests green before the next)

Dependency shape: **Step 1** (store + route) is standalone. **Step 2** (override plumbing) is standalone. **Step 3**
(capture) depends on Step 1. **Step 4** (consumption wiring) depends on Steps 1 + 2. Steps 2 and 3 are independent of each

### Step 1 — the store module + the route (DB-adjacent; no schema change)
**Files (new):** `lib/document/defaultTemplateStore.js`, `app/api/templates/default/route.js`.
**Delivers:** AC-6 (isolation), AC-9 (duplicate handled by construction), the write half of AC-1's "no email write".
**Contract — `lib/document/defaultTemplateStore.js`** (all take the AUTHED supabase client; RLS **and** explicit
`.eq("user_id", userId)` on every statement; bucket `"resumes"`; object at the fixed path
`` `${userId}/templates/default-${kind}.docx` ``; `kind ∈ {'resume','cover'}`, never `'email'`):
```js
/** Upload bytes to the fixed per-kind path (upsert:true) FIRST, then upsert the reserved-name row.
 *  Ordering is load-bearing: object precedes row so a row never names a path with no bytes
 *  (storage_path NOT NULL). Reserved name is fixed per kind (1c's exact string), never user-typed,
 *  so the shipped unique (user_id,kind,lower(name)) index makes a second default of a kind impossible
 *  and turns a concurrent double-insert into a caught unique-violation (update the existing), never a
 *  raw error to the user (AC-9). Returns {error} on empty bytes / invalid kind.
 *  @returns {Promise<{ row:{id,name,kind,storage_path,updated_at}, replaced:boolean } | { error:string }>} */
export async function saveDefaultTemplate(supabase, { userId, kind, bytes, fileName }) {}
/** @returns {Promise<{id,name,kind,storage_path,updated_at}|null>} reserved-name row for kind, or null */
export async function getDefaultTemplate(supabase, { userId, kind }) {}
/** @returns {Promise<{ bytes: Uint8Array } | null>} null when no default set or the object is gone */
export async function getDefaultTemplateBytes(supabase, { userId, kind }) {}
/** @returns {Promise<{ ok:true } | { error:string }>} row delete (id+user_id gated) + best-effort storage remove */
export async function clearDefaultTemplate(supabase, { userId, kind }) {}
```
**Contract — `app/api/templates/default/route.js`** (idiom = `saved_searches`: `getUser()`→401→store; **never** derive
`userId` from the request body; NOT `makeCrudHandlers`):
- `GET ?kind=` → `{ hasDefault:boolean, updatedAt?:string }`. 401 if no user.
- `PUT`/`POST` multipart (`file` + `kind`) → validate `.docx` + `kind ∈ {resume,cover}`; **`kind='email'` → 400** (the
  structural guarantee that no path writes an email template — AC-1); `saveDefaultTemplate` → `{ row, replaced }`.
- `DELETE ?kind=` → `clearDefaultTemplate` → `{ ok:true }`.
**Census / reachability:** `defaultTemplateStore`'s four exports are imported by the route **in this step** (prod importer
present). The route file is self-registering (Next.js). ORPHAN 70 / TEST_REFERENCED 368 unchanged for these new exports
because each has an in-step prod importer; re-derive only if a symbol moves.
**Landable + green alone:** store unit tests (mocked supabase) assert upload-precedes-row, `.eq(user_id)` on every
statement, `kind='email'` rejected, `getDefaultTemplateBytes` → null when absent; route tests assert 401, kind validation,
`{row,replaced}` shape. No user-facing surface yet — inert.

### Step 2 — the consumption override plumbing (pure; zero behaviour change)
**Files:** `lib/document/docx.js` (`resolveDocumentBlob` + `resolveDocumentBlobBytes` + `downloadDocxFiles`),
`lib/document/previewBlob.js` (`previewBlobArgs` + `buildPreviewBlob`), `lib/tailor/documentScopes.js` (`buildDownloadArgs`).
**Delivers:** the AC-4 mechanism and the AC-8 guarantee (mechanism only; no caller resolves a default yet).
**Contract additions:**
- `resolveDocumentBlobBytes({ …, formattingTemplate = null })` — **new top branch**, before `:653`:
  `if (formattingTemplate && isDocxResume(formattingTemplate) && (hasText || lines.length)) return buildDocxFromUploadedTemplate(formattingTemplate, text, lines);`
  `resolveDocumentBlob({ …, formattingTemplate = null })` passes it through to `resolveDocumentBlobBytes`; the `spacing`
  post-pass is unchanged. When `formattingTemplate` is null every existing branch is byte-identical to HEAD.
- `downloadDocxFiles({ …, formattingTemplate = null, coverFormattingTemplate = null })` — résumé call (`:738`) gets
  `formattingTemplate`, cover call (`:753`) gets `coverFormattingTemplate` (C1).
- `previewBlobArgs(entry, scope, { …, formattingTemplate })` (stays PURE — receives a resolved `File`, never fetches) and
  `buildPreviewBlob(entry, scope, opts)` pass it straight into the args; `email` still returns null before it matters.
- `buildDownloadArgs({ …, formattingTemplate })` puts it on the returned args under the correct key for its `scope`
  (résumé → `formattingTemplate`, cover → `coverFormattingTemplate`).
**Landable + green alone:** tests assert (a) `formattingTemplate=null` → output byte-identical to HEAD across all callers
(AC-8); (b) a supplied docx `formattingTemplate` → the blob is `buildDocxFromUploadedTemplate(formattingTemplate, …)`
regardless of `edited`/`engineDocxB64` (override precedence). No egress caller passes a non-null value yet.

### Step 3 — capture / promote (the control + the handler + the client glue)
**Files (new):** a small modal child (name 1c's, e.g. `preview/SetDefaultTemplateControl.js`), a client helper (name TBD,
e.g. `lib/document/defaultTemplateClient.js` for `resolveDefaultTemplateFile`). **Files changed:** `DocumentPreviewDialog.js`
(one prop + one JSX block), `DocumentPreviewMount.js` (wire the prop), `useDocumentPreview.js` (the promote handler).
**Delivers:** AC-1 (control present on résumé/cover, ABSENT on email), AC-2 (captures current view), AC-3 (per-engine capture
+ refuse-when-null), AC-7 (kind from active tab), AC-9 (one action, confirm only on replace).
**Contracts:**
- `DocumentPreviewDialog`: new prop `onSetAsDefaultTemplate` mirroring `onDownload` (`:82`); control mounted **only** for
  `DOCX_SCOPES.includes(tab) && available(tab)` (structurally absent on email — AC-1); mounts as a **sibling of
  `DialogActions`** (the slot `DriveResultRegion` occupies, `:872`) or a compact item inside it (`:888`, next to
  `CombineDocumentsControl` `:891`) — 1c's placement call. On click: `commitDraft()` then
  `onSetAsDefaultTemplate?.(tab, activePayload())`. Presentational only — no capture/store logic in the dialog.
- Promote handler in `useDocumentPreview` (mirrors `downloadDocumentPreview`, wired at `DocumentPreviewMount.js:523`):
  ```
  setDefaultTemplateFromPreview(scope, payload):
    entry = tailoringMapRef.current[resumePreview.jobId]
    blob = await buildPreviewBlob(entry, scope, { resumeFile, coverLetterFile })  // NO formattingTemplate → engine-native (AC-2)
    if (!blob) -> refuse honestly, write nothing, set no default                  // AC-3(c): Gemini reloaded / email
    (confirm ONLY if a default already exists for this kind — GET ?kind hasDefault)
    POST /api/templates/default (multipart blob + kind=scope) ; on success -> inline feedback
  ```
  Capture omits `formattingTemplate`, so it always stores the engine-native rendering — the property that keeps the design
  non-circular (re-promote never re-captures the active default) (AC-2 / design §1).
- `resolveDefaultTemplateFile(kind)` (client, RLS-scoped, memoisable per session): downloads the default's docx bytes and
  returns a `File`, or `null` when none. **Mechanism ruling (mine):** because the storage path is deterministic
  (`` `${userId}/templates/default-${kind}.docx` ``, §2), the resolver constructs it from `currentUser.id + kind` and does a
  single browser-client storage download (RLS enforces ownership); a 404/empty ⇒ `null`. The control uses `GET ?kind` only
  for the hasDefault/confirm-on-replace check. Fewer round-trips than a GET-then-download.
**Census:** `resolveDefaultTemplateFile` and the promote handler are imported by `DocumentPreviewMount`/`useDocumentPreview`
in this step; the control is rendered by `DocumentPreviewDialog` in this step. All reachable.
**Landable + green alone:** component test (control reachable by accessible name on résumé/cover, absent on email); handler
tests (captures with no `formattingTemplate`; refuses + zero POST when `buildPreviewBlob` null; kind = active tab; POSTs
multipart). The store from Step 1 is the POST target.
