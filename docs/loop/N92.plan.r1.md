## 2. Contradictions routed to me / mechanism choices I make (brief items 5)

The AC held required behaviour and handed the mechanism to design; design handed a few residuals to the
plan (design §9). My rulings, each with what proves it:

- **P1 - Boundary regex reuse (design §1.2 said "reuse the DEFINITION from summarize.js:36").**
  summarize.js does NOT export the regex (it is inline in `splitSentences`). Exporting it would move the
  export census and touch a file two other features depend on. **RULING:** `factMove.js` RE-DECLARES the
  boundary pattern as its own module constant, copying the tree's literal verbatim (curly quote, per §1.1
  above) with a comment cross-referencing `summarize.js:36`. No new export from summarize.js; no census
  move for the pattern; no modification of summarize.js. AC-A10's named-fixture suite is the real quality
  gate, not literal-equality with summarize.js. *Proves it:* the AC-A10 segmenter unit (fixtures below).
- **P2 - Body/closing boundary detection (design §9 left this to the plan).** `coverLetterResultLines` is a
  flat paragraph array with no closing marker. **RULING:** `planMoveFact` computes default body bounds
  INTERNALLY (a private `bodyBounds(lines)` helper in factMove.js) when `bounds` is omitted, and BOTH
  callers (Control A `moveInsertedFact`, Control C `planAcceptForEntry` nudge) OMIT `bounds` - so they get
  byte-identical body policy for free, no divergence possible, and no extra export. `bodyBounds`:
  `minLine = 1` (exclude greeting at line 0); `maxLine` = the last paragraph before a detected closing
  block. Closing detection scans from the end: a paragraph is "closing" when it matches
  `/^\s*(sincerely|regards|best regards|kind regards|warm regards|best|yours (truly|sincerely)|respectfully|thank you)\b/i`,
  or is a short (<= 40 char) punctuation-light line immediately following such a salutation (the signature/
  name line). If nothing matches, `maxLine = lines.length - 1`. This is a HEURISTIC; a non-matching letter
  still moves within the whole body. *Proves it:* AC-A3's multi-paragraph fixture MUST include greeting +
  body paragraphs + `"Sincerely,"` + a name line, and assert a forward move at the last body sentence is a
  no-op (`reason:"boundary"`), never landing a fact in the closing (unsafe direction).
- **P3 - Span-local excise/insert helpers (design §1.1, LOAD-BEARING).** `factMove.js` gets private
  `exciseSpanLocal(line, offset, textLen)` and `insertSpanLocal(carrier, at, text)` that mirror
  `planRemoveFact:243-251`'s "drop exactly one owned space, prefer the one before, fall back to after"
  rule but STOP before the `:252` line-global normalize. They are NOT exported (tested through
  planMoveFact's round-trip) - keeps the census minimal. **planMoveFact MUST NOT import/reuse
  planRemoveFact.** *Proves it:* AC-A4 round-trip unit with pre-existing double spaces OUTSIDE the span.
- **P4 - AC-A4 byte-identity vs. sanctioned relaxation.** Per AC-A4 and design §9, byte-identity is
  UNPROVEN algebra. **RULING for the implementer (Wave 1):** attempt true span-local byte-identity first;
  if a specific edge (paragraph-first, paragraph-last, cross-paragraph, adjacent-fact) proves infeasible
  on the splice seam, INVOKE the sanctioned relaxation EXPLICITLY - relax AC-A4 to "identical modulo the
  app's existing single-space normalization", have the 4b round-trip test assert the weaker equality, and
  record the written rationale in the implementation notes. **Never silently.** The unsafe outcome (silent
  loss of the candidate's intentional spacing) must be called out either way. This is a decision the
  implementer makes against the RED test, not one I foreclose.
- **P5 - `sentenceBounds` census trajectory (design §1.3).** Exported for AC-A10's direct unit. In Wave 1
  its only in-module use is inside planMoveFact (an internal call, not an import), so it is TEST-REFERENCED
  only -> `TEST_REFERENCED` moves **365 -> 366**. In Wave 3, `smoothTransition.js` imports it in production
  (deriving the three in-scope sentences) -> it becomes production-reachable -> **366 -> 365**. Each step
  re-derives from the sweep's OWN failure output; my predicted deltas are predictions, not verified counts
  (I did not run the graph after imaginary code). See §Export-census discipline.
- **P6 - Control B embedded default (AC §6, one reversible owner call still open).** AC default = disable
  with honest reason. Default is SAFE; I do NOT block Wave 3 on it. Wave 3 implements disable-with-reason

### W1-S1 - `lib/acceptedFacts/factMove.js`: the pure primitive + segmenter (NEW FILE)
Files: `lib/acceptedFacts/factMove.js` (new); tests land in 4b.
Exports (exactly two, per brief): 
- `sentenceBounds(text: string) -> number[]` - the char offsets in the RAW, uncollapsed string where each
  sentence AFTER the first begins. Non-destructive scan (`matchAll` over the re-declared boundary pattern,
  §P1), plus the closed abbreviation denylist (§P1/AC-A10). Never trims, never collapses whitespace.
- `planMoveFact({ lines, records, id, direction, bounds? }) -> { lines, records, edits, changed, reason }`
  with the full contract from design §1.1:
  - `lines: string[]`, `records: Record[]` where
    `Record = { id, text, lineIndex, offset, [url], [title], ...rest }`, `id: string`,
    `direction: "forward"|"backward"`, `bounds?: {minLine,maxLine}` (omitted by both callers, §P2).
  - Returns `edits: {lineIndex, before, after}[]` (up to two: source loses the fact, destination gains
    it; one when within a paragraph), `changed: boolean`, `reason: "boundary"|"stale-locator"|"not-found"|"ok"`.
  - Purity: never mutates inputs; returns the SAME `lines`/`records` refs on any no-op (AC-A1).
  - Atomicity (AC-A11): excise the fact's own span first, segment the CARRIER (paragraph minus fact) with
    `sentenceBounds`, re-insert - the fact's internal `[.!?]` never reach the segmenter.
  - Span-local (AC-A4, §P3/P4): via private `exciseSpanLocal`/`insertSpanLocal`; NO line-global
    `.replace(/\s{2,}/g," ").trim()`; MUST NOT reuse `planRemoveFact`.
  - Survivor invariant (AC-A5/A7): returns the FULL updated `records`; every survivor locates its own text
    at its returned `{lineIndex,offset}`; moved fact appears exactly once; two adjacent facts moved past
    each other both stay valid and reorder correctly.
  - Provenance (AC-A12): each record copied by spread; only `lineIndex`/`offset` change.
  - Stale/hand-edited (AC-A8): pre-move assert
    `lines[lineIndex].slice(offset, offset+text.length) === text`; else no-op `reason:"stale-locator"`,
    never a guessed relocation.
  - Body bounds (§P2/AC-A3): default `bodyBounds(lines)` excludes line 0 and the detected closing block.
Private (NOT exported, tested through planMoveFact): `exciseSpanLocal`, `insertSpanLocal`, `bodyBounds`,
the boundary pattern constant, the abbreviation denylist constant.
Landable/verifiable alone: the pure units (A1, A2-order via segmenter, A3, A4, A5, A7, A8, A10, A11) run
against factMove.js with no UI and no hook.
Export census: `planMoveFact` gains its production importer in W1-S3 (same wave, but a LATER step) - so
between W1-S1 and W1-S3 `planMoveFact` is momentarily orphan/test-ref. **Land W1-S1 and W1-S3 in the same
commit, or the sweep goes red between them.** Alternatively land W1-S1 with the sweep expectation updated
and W1-S3 restoring it - the implementer picks, but the pushed tree must never have a green-faked count.
`sentenceBounds` is test-ref-only this wave -> re-derive `TEST_REFERENCED` 365->366 (§P5).

**Silent-failure mode:** an off-by-one in `sentenceBounds` (a phantom slot mid-abbreviation, e.g. "U.S.
Army" split after "U.S."). This produces a plausible-looking move to the WRONG place with no error - the
letter still reads, the fact just sits mid-sentence. **Caught by:** AC-A10 segmenter unit over the NAMED
fixtures (Ph.D./U.S./e.g./i.e./Dr./Inc., decimals, $50M., quoted/parenthetical periods) asserting each
