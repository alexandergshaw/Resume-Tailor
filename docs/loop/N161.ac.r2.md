## Detection locus (pinned) and the shape of the fix

1. Answer SHAPE is decided by the PROMPT (Gemini) and the embedded drafters — detection must reach both.
2. "Non-coding byte-identical" + the frozen oracles ⇒ the coding branch must be **gated and re-derived
   from `question`** (like `roleTerms(question).length > 0`); a non-coding question takes no new branch
   and the frozen `toBe` holds unchanged.
3. CODE must survive rendering verbatim (newlines + indentation) monospaced — which
   `points`→`deriveAnswerFromPoints`→`answerLines`→`AnswerLines` destroys. So the code travels as a
   **structured response field**, not prose `points`, and renders through a NEW whitespace-preserving,
   **inline-styled** code primitive (B1).

**Recommended structure (design/1b owns the final contract):** a pure `detectCodingChallenge(question)`
module under `lib/copilot/` (sibling of `questionType.js`), NARROWER than `classifyQuestionType`'s
`technical` (D2), re-derived inside the builders, reachable by the embedded drafters and the client
render gate; the worked solution rides a new structured field (e.g. `codingSolution: { approach,
language, code, complexity, edgeCases }`) on the terminal frame only (D4).

## Failure direction (binding)

- **False positive (worse for the shipped answer):** a CODE solution on a behavioral / conceptual
  question corrupts what the candidate reads aloud. Passing direction = "a non-coding question gets the
  UNCHANGED shape"; a mutation broadening detection onto the negative corpus turns a test red.
- **False negative:** a real coding/pseudocode challenge gets the old spoken-points shape; the
  positive-corpus criterion fails red if detection under-fires.
- **Augment-instead-of-replace:** a build that shows BOTH a spoken answer AND a code block violates
  "REPLACE"; AC-11 makes that red.

## Acceptance criteria

Unless noted, detector/prompt/honesty criteria are **jsdom/unit-decidable** against pure modules.
Render criteria use the existing copilot jsdom harness (real component mounted) and — per B1 — assert
only **inline** `element.style.*` (not `getComputedStyle`, which does not apply sx/author classes in
jsdom). "Both surfaces" = live (`useDraftAnswer` → the 4 live render sites) and practice
(`useSampleAnswer` → `SampleAnswer`).

### AC-1 — Deterministic detection, both directions, on a FIXED held-out corpus. **[CORE / RED]**
A pure `detectCodingChallenge(question)` returns **true** for every positive item and **false** for
every negative item. Minimum corpus (extend, never shrink):
- **Positive (MUST detect):** "Write a function to reverse a linked list." / "Implement binary search."
  / "Given an array of integers, return the two indices that sum to the target." / "Code a function
  that checks if a string is a palindrome." / "Give pseudocode for a breadth-first search." / "FizzBuzz
  from 1 to 100." / "Write a SQL query that returns the top 3 earners per department."
- **Negative — alias-to-`technical` teeth (classify `technical`, are NOT coding challenges):** "What is
  a hash map and when would you use one?" (hash) / "Walk me through how HTTPS works." (http) / "How do
  you approach code review?" (code).
- **Negative — general (also must not detect):** "Tell me about a time you failed." / "Describe a
  conflict with a coworker." / "Explain the CAP theorem." / "Why do you want this role?"
- **RED on HEAD:** yes — module absent (grep: no coding detector). Import fails → report INVALID
  until built, not pass.
- **Mutation:** aliasing the detector to `classifyQuestionType(q) === "technical"` must turn this red
  on "hash map" / "HTTPS" / "code review" (the three `technical`-classified negatives). A constant-false
  mutation must turn it red on the positives.

### AC-2 — Non-coding prompt is BYTE-IDENTICAL; coding branch gated, re-derived from `question`. **[CORE / regression guard]**
`buildPointsPrompt` / `buildAnswerPrompt`, for a non-coding question with no résumé/cover letter/pages,
produce output `===` `FROZEN_POINTS_PROMPT_NO_PAGES` / `FROZEN_ANSWER_PROMPT_NO_PAGES`
(`answerPrompts.test.js:86-112`), unchanged. The coding shape lines appear ONLY when
`detectCodingChallenge(question)` is true; the builders take **no new positional argument**.
- **RED on HEAD:** no — regression guard (frozen oracles pass today). Teeth: a naive unconditional
  coding instruction breaks the `toBe`, which this forbids.
- **Trap (B1-enum):** the frozen JSON shape line carries `"type": "behavioral" | "technical" |
  "general"`. The coding signal must **not widen that enum in the non-coding shape line** (do not emit
  `"coding"` there) or every non-coding oracle breaks (D3 recommends a separate field).

### AC-3 — A detected coding question produces a worked-solution SHAPE with all four parts. **[CORE / RED]**
For a detected coding question the assembled prompt instructs, and the response contract carries, a
solution with four parts structurally present: (a) **approach**, (b) **code** (or pseudocode per AC-5),
(c) time/space **complexity**, (d) key **edge cases**. Pinned two ways (mirroring N134/N140): a **NEW
frozen prompt oracle** (`toBe`) for a representative detected coding question, AND a response normaliser
that yields the four structured fields for a conformant model payload and degrades to a safe non-coding
answer (never a half-built object) when it does not.
- **RED on HEAD:** yes — no coding branch in either builder.
- **Mutation:** dropping any one of the four parts (prompt instruction or required response shape) must
  turn this red.

### AC-4 — The CODE renders in an INLINE-styled code block: monospace + preserved whitespace, on every live + practice render site. **[CORE / RED — rendering; B1 instrument fix]**
A coding solution's code string containing newlines and leading indentation renders so newlines and
indentation **survive to the DOM** and in a **monospace** font, via an **inline `style={{ whiteSpace:
"pre" | "pre-wrap", fontFamily: "<monospace stack>" }}` attribute on the code element** — NOT via `sx`,
because jsdom's cascade does not apply emotion/author classes (`CitationDetail.test.js:266-270`). The
test asserts `codeEl.style.whiteSpace` ∈ {`pre`,`pre-wrap`} and `codeEl.style.fontFamily` is a
monospace stack (both resolve in jsdom — "an inline style still wins"). The code is NOT passed through
`deriveAnswerFromPoints` (joins with a space, `answerLocal.js:510`) nor rendered as a plain
`variant="body2"` `<li>` (collapses whitespace, `AnswerLines.js:217`). Holds at **all five
`answerLines`/`AnswerLines` render sites** reachable for a coding answer: live current
(`CopilotDashboard.js:267/444`), live history reveal (`:699/747`), live latest + per-card
(`QuestionFeed.js:85` + `144/205`), practice (`SampleAnswer.js:124/222`).
- **RED on HEAD:** yes — no render path sets an inline `white-space`/monospace for an answer; a jsdom
  test reading `codeEl.style.whiteSpace`/`.fontFamily` finds no such element.
- **Mutation:** routing the code through `answerLines`/plain `<Typography>` (whitespace collapsed), or
  declaring the style via `sx` instead of inline `style` (so `element.style` is empty), must turn this
  red. "Looks right at 320px / no horizontal-scroll overflow" is OUT of jsdom — owner/browser-pane.

### AC-5 — Language selection: the DETERMINISTIC precedence (steps 2–4) over the `codeLanguage` object; pseudocode when unset. **[CORE / RED — scoped]**
For a detected coding question the solution's language follows the owner order. **Step 1** — "a language
the question itself names, incl. an explicit request for pseudocode" — is a **model-prompt instruction**
(free-text reading the model does today, `codeLanguageLines:212`), explicitly **non-unit**; no extractor
or corpus is invented for it. The **unit-decidable** claim is scoped to **steps 2–4**, deterministic
over the `codeLanguage {override, resolved}` object: (2) the user's `override` when set (emit the
**label** via `codeLanguageLabel`, never the stored slug — `codeLanguages.js:106`); else (3) the
posting-`resolved` language when present; else (4) **pseudocode**; and pseudocode when `override` is
`pseudocode` or when nothing is set. This precedence must hold **regardless of
`descriptor.codeBearing`** (D5) — a coding question in a `general` session must still get a language,
not the empty `codeLanguageLines([])` of today.
- **RED on HEAD:** yes — `codeLanguageLines` returns `[]` for a non-`codeBearing` descriptor
  (`answerPrompts.js:200`), and there is no worked-solution branch to attach a language to.
- **Mutation (steps 2–4 only):** emitting the slug (`"csharp"`) instead of the label, defaulting to a
  real language instead of pseudocode when unset, or re-gating on `descriptor.codeBearing`, must turn
  this red.

### AC-6 — Non-coding answers completely unchanged (response + render), all five route branches. **[CORE regression guard; m2]**
For a non-coding question the answer-route response is **key-for-key** today's shape on all five
branches, with no coding field present; the render is the existing `answerLines`/`AnswerLines` prose.
The new coding field is **absent** (not `null`, not `[]`) when the question is not a coding challenge —
mirroring `factSources` (`route.js:907`). The TDD seat must assert the exact key set with a `toEqual`
**per branch** — streaming Gemini AND non-streaming Gemini **answer-mode** AND embedded answer-mode AND
the two points branches — not only the points-mode key-set assertions the existing suite carries
(route.test.js:172-180, 453-461 per `roleTermsFlag.js:5-9`), so "absent-when-not-detected" is guarded
on all five.
- **RED on HEAD:** no — regression guard. Teeth: any change adding a coding key to a non-coding
  response, or altering non-coding `points`/`type`/`cues`, must fail it.

### AC-7 — The honesty/output transforms do NOT mangle or drop the code. **[CORE / structural / RED]**
The code string reaches the render **verbatim** — NOT through `sanitizeTechTermDetail` /
`isFirstPersonClaim` (`techTermDetailHonesty.js`), NOT through `deriveAnswerFromPoints`, NOT through
`answerLines`' STAR/sentence machinery. A code block whose comment contains `I` (e.g. `// I use two
pointers here`) or an imperative line (e.g. `return left + right;`) appears in full, unchanged.
Separately, the recruiter-vocab flags (`roleTermsUnbacked`/`roleTermsClaimed`) must NOT cause the code
or solution to be suppressed/stripped/badged as fabrication (a worked solution is general knowledge,
not a first-person claim — `techTermDetailHonesty.js:5-18` states this inversion for the sibling
feature).
- **RED on HEAD:** yes — today a code-shaped string delivered as `points` is joined/space-collapsed by
  `deriveAnswerFromPoints` and rendered as collapsed prose; a byte-equality test on the code fails.
- **Failure direction:** dangerous = dropping/altering a line of correct code; safe = untouched. A
  mutation filtering the code through any first-person / sentence-splitting transform must turn red.

### AC-8 — The coding solution rides the request→response→state→cache ENTRY in BOTH client hooks. **[CORE / RED — wiring; M2 fix]**
The new coding field is carried through the full client round-trip on both paths so a cache **hit** is
not served without it:
- live `useDraftAnswer`: destructured from the response (alongside `points`/`type`/…, line 430), written
  to the card, written into `answerCacheRef` (503);
- practice `useSampleAnswer`: destructured on both `request` (258) and `queue` (424), written to
  `state`, written to the cache **entry payload** (317, 448) — **exactly like `pageSources`**.
The coding field is an OUTPUT and is **NOT** added to `cachedSampleAnswerFor`/`needsRedraft`'s INPUT
comparison; a language-change redraft is already forced by the existing `codeLanguage` key in that
comparison (reveal path, `useSampleAnswer.js:350, 365-372`). AC-8 pins only that the coding field
**survives a reveal → hide → reveal of a cache HIT** (practice) and a cache-reuse (live).
- **RED on HEAD:** yes — neither hook destructures or caches any coding field.
- **Mutation:** dropping the field from either cache-entry write (so a reveal→hide→reveal loses the
  solution — the exact class `pageSources` was cached to fix) must turn red.

### AC-9 — Live AND practice both reach the coding path, including live HISTORY reveal (scope). **[CORE / RED; M4]**
Both surfaces produce a worked solution for a detected coding question: live via the answer route as
reached by `useDraftAnswer`, and practice via `mode:"answer"` as reached by `useSampleAnswer`. Because
live history/feed reveals re-render a PAST answer from its stored entry
(`CopilotDashboard.js:699`, `QuestionFeed.js:85/144`), the coding field must reach those reveals too —
a revealed past coding answer shows the code block, not collapsed points.
- **RED on HEAD:** yes — no coding path on either surface; history/feed reveals run plain `answerLines`.

### AC-10 — Embedded engine returns NO code block + an honest fallback marker. **[CORE / RED-equivalent; m3 narrowed]**
On the embedded (no-LLM) engine, a detected coding question yields **no code block** and an **honest
fallback marker** (a field/flag the UI renders as "switch to the AI engine for a worked solution", or
equivalent) — never fabricated/invented code presented as a working solution. This is fully
unit-decidable (assert the embedded response carries no code field and carries the fallback marker).
- **RED on HEAD:** vacuous today (no coding path), stated as an honesty/scope fence so the design seat
  does not have the embedded engine fabricate code.
- **Failure direction:** safe = no solution / honest fallback; dangerous = confident wrong code. A
  mutation that has the embedded drafter emit a code block for a detected coding question must turn red.

### AC-11 — For a detected coding question, the ordinary spoken answer is SUPPRESSED (REPLACE, not augment). **[CORE / RED; M3]**
When a coding question is detected, the response/render shows the worked solution **in place of** the
spoken-points/prose answer — the ordinary `points` list (and its derived prose `answer`) is **empty or
absent, and not rendered** beside the code. A build that renders BOTH a spoken/STAR points list AND a
code block for the same detected coding question must turn a test **red**.
- **RED on HEAD:** yes — HEAD always renders `points` via `AnswerLines`; there is no path that
  suppresses them, so a test asserting "no prose points list rendered alongside the code block for a
  detected coding question" cannot pass (there is no code block, and points always render).
- **Mutation:** an augment-instead-of-replace implementation (points list + code block both present)
  must turn this red; so must one that renders the code but ALSO leaves the old spoken answer above it.

## Decisions (D1–D6 settled; recommended defaults confirmed by the coordinator)

- **D1 — Aids beside a coding answer.** Suppress the experience-oriented aids (`resumeAnchor`,
  `projectExample`/`projectExampleLive`, per-point `pageSources` citations, per-bullet expansion) — a
  worked solution is general knowledge, not drawn from the candidate's pages, so attributing it to a
  project page is a false provenance claim (`SampleAnswer.js:44-54`, `answerAids.js:139-150`).
  `buzzwords`/`techTerms` MAY remain (posting vocabulary, not a provenance claim).
- **D2 — Detector contract.** A NEW `detectCodingChallenge(question)`, narrower than
  `classifyQuestionType`'s `technical`; does NOT widen the detect route's 3-value `type`
  (`detect/route.js:19`) nor the answer route's `VALID_TYPES`.
- **D3 — Response field.** A **separate** structured field (e.g. `codingSolution`), not a new
  `type: "coding"` value, so the shared JSON shape line's `type` enum stays byte-identical for
  non-coding (AC-2 / B1-enum).
- **D4 — Streaming.** The structured fields ride the **terminal `done` frame only** (like
  `pageSources`/`factSources`); `answerStream.js`'s `pointsFromPartialJson` anchors on the `points`
  array. Loading UI shows a "drafting solution" state (design owns the UX).
- **D5 — Language under a non-codeBearing session.** The coding branch sources its language
  **independently of `descriptor.codeBearing`** (AC-5), reusing the `codeLanguage {override,resolved}`
  object and precedence but gating on `detectCodingChallenge`.
- **D6 — Embedded engine.** Honest fallback (no fabricated code) — pinned by AC-10.

## Explicitly OUT of scope

- **Whether the model's CODE is correct / idiomatic / optimal** — runtime, Gemini-env; the AC pins the
  four parts present + render intact, not algorithm correctness.
- **The detector's real-world RECALL on live machine-transcribed questions** — owner/runtime; the
  fixed corpus (AC-1) bounds behaviour.
- **Code-block geometry on a phone (≥44px, horizontal-scroll overflow, "looks right at 320px")** —
  jsdom has no layout and `getComputedStyle` is zero-power for sx; browser-pane/owner (`copilot-mobile`).
- **Language step 1 (question names a language / pseudocode)** — a model-prompt instruction, explicitly
  non-unit (M1); no extractor invented.
- **A new interview-type / changes to `interviewTypes.js` / `classifyQuestionType` / the detect route's
  3-value contract** (D2).
- **Audio synthesis of the code answer.**
