## 1. Shape of the change (one sentence)

Add one `localStorage`-backed boolean preference (new store file, engine.js pattern), read it in two
existing places — the client request shaper (`chatbot.js`, where `engine` is already read) and the chat
server route (`route.js`, where `SYSTEM_PROMPT` is already assigned) — and render one labeled Switch in
`ChatPanel`. No migration, no new route, no new egress, no new module outside `app/settings/`.

## 2. Seam A — the toggle store (new file) — AC-3

**New file:** `hello-world/app/settings/answerAsMe.js` (NOT added to `engine.js`: this is a voice
preference, not an engine; keeping it separate preserves engine.js's byte-for-byte OFF guarantee for
AC-4 and keeps the AC-8 census narrow). Mirrors engine.js exactly; booleans instead of an enum.

```
// This is the make-wrong-safe core of AC-3: unknown/empty/garbage resolves OFF, never ON.
export function normalizeAnswerAsMe(value): boolean      // returns value === "true"

export function readAnswerAsMe(): boolean
  // typeof localStorage === "undefined"  -> DEFAULT_ANSWER_AS_ME (false)  [SSR / node]
  // try localStorage.getItem(KEY) -> normalizeAnswerAsMe(...)
  // catch -> DEFAULT_ANSWER_AS_ME (false)

export function subscribe(callback): () => void          // Set<listener>, returns unsubscribe

export function setAnswerAsMe(next: boolean): void
  // localStorage.setItem(KEY, next ? "true" : "false") in try/catch (storage may be unavailable)
  // ALWAYS notifies listeners (even when storage throws) — mirrors engine.js setEngine

export function useAnswerAsMe(): { answerAsMe: boolean, setAnswerAsMe }
  // useSyncExternalStore(subscribe, readAnswerAsMe, () => DEFAULT_ANSWER_AS_ME)
  // the 3rd arg (server snapshot) is the OFF default, so SSR hydration never flashes ON
```

**Load-bearing property / diff-check:** the only ON value is the literal `"true"`; `normalizeAnswerAsMe`
returns `value === "true"`. A reviewer applies to a diff: *does the empty/garbage/SSR path return
`DEFAULT_ANSWER_AS_ME` and is `DEFAULT_ANSWER_AS_ME === false`?* If any branch can return `true` on an
unreadable store, AC-3's safe-OFF is broken. (engine.js's analogue is `normalizeEngine` returning
`DEFAULT_ENGINE`; same structure.)

**Store unit test (AC-3), mirrors `engine.test.js`:** install fake `globalThis.localStorage`; assert
write ON→read ON; empty→false; garbage (`"1"`, `"yes"`, `"TRUE"`)→false; `delete globalThis.localStorage`
(SSR)→false; `setAnswerAsMe` notifies even when storage throws; subscribe/unsubscribe counts.
**Mutation control:** change the default/normalize so empty→`true` ⇒ the empty-store test goes red.

Why a store and not session-only React state: AC-3 floor is session persistence; the engine-store pattern
also survives reload (precedent: `"tailorEngine"` engine.js:10, `"chatSize"` useChat.js:124-141), is the
pattern the AC names, and lets both `ChatPanel` (UX) and `chatbot.js` (request shaper) read one source of
truth across the layout boundary — exactly why engine.js lives where it does (engine.js:5-8 comment).

the store does not touch. The client fetch-spy diff (two payloads, equal except `answerAsMe`) is the
mechanical check.

## 4. Seam C — the server persona-framing switch — AC-5 (server half), AC-6 (HARD SAFETY)

**This is the load-bearing seam. Spend the care here.**

**4.1 Read the flag.** `route.js`, in the `POST` body-parse block at **route.js:210-219**, add beside the
other guarded reads:

```
const answerAsMe = body?.answerAsMe === true;   // strict: only boolean true is ON; any other value -> OFF (safe default)
```

Strict `=== true` so a malformed/absent/truthy-string value from a direct caller cannot turn the persona
on — the server re-applies the same safe-OFF default as the store. (Mirrors the defensive `typeof===string`
reads already on `tab`/`section` at :218-219.)

**4.2 The indivisible directive constant.** Add ONE module-level constant next to `SYSTEM_PROMPT`
(route.js:23-36). The first-person directive and the no-fabrication clause are **a single `.join(" ")`
constant** — not two constants concatenated at the call site — so there is no code path that emits
first-person voice without the no-fabrication clause. This is the AC-6 make-wrong-impossible structure:

```
// N102 AC-6: first-person voice and the no-fabrication guard are ONE string.
// They cannot be decoupled without editing this single constant, which reddens
// the bundled test (route.promptInjection) that asserts BOTH substrings together.
const ANSWER_AS_ME_DIRECTIVE = [
  // --- first-person-as-the-user voice (AC-5) ---
  "The user has turned on 'answer as me'. Write your reply in the FIRST PERSON AS THE USER: " +
  "produce a message, answer, or response the user could send or say verbatim as themselves, " +
  "not advice of the form 'you could say'. Do not address the user in the second person; speak as them.",
  // --- no-fabrication guard, BUNDLED INDIVISIBLY (AC-6) ---
  "Draft ONLY from facts given in this conversation and the user's provided documents " +
  "(the pinned subject, their uploaded resume, attached files, and applications already in scope). " +
  "NEVER invent experience, credentials, employers, job titles, dates, metrics, or any biographical " +
  "fact about the user that was not provided. If a needed fact is missing, leave a clearly marked " +
  "placeholder or ask for it — never fabricate it.",
].join(" ");
```

(Exact wording is the implementer's to finalize for live quality — AC-10/ENV — but the TWO clauses and
their bundling into one constant are the contract. The salary clause at route.js:31,35 stays untouched;
this is additive.)

**4.3 The switch at the assignment site.** Replace the single line at **route.js:335**
(`const systemInstruction = SYSTEM_PROMPT;`) with:

```
const systemInstruction = answerAsMe
  ? `${SYSTEM_PROMPT} ${ANSWER_AS_ME_DIRECTIVE}`
  : SYSTEM_PROMPT;
```

**OFF byte-identity (AC-4 baseline half):** when `answerAsMe` is false the right-hand side is
`SYSTEM_PROMPT` — the *same constant reference*, no concatenation, no template literal — so the string
handed to `config.systemInstruction` (route.js:366) is byte-for-byte today's. This is why the ternary
returns `SYSTEM_PROMPT` bare on the OFF arm rather than `\`${SYSTEM_PROMPT}\`` (a template literal would be
value-equal but is an unnecessary new allocation; keep the identity obvious to the reviewer).

**ON difference (AC-4 discriminating half, AC-5 server):** the ON arm appends the directive, so the wire
`systemInstruction` differs. Everything else on the wire — `contents`, caps, inline parts, wrapped context
— is produced by code that never reads `answerAsMe`, so AC-7's server-wire diff is "equal except the
appended directive."

**Load-bearing properties / diff-checks:**
- *AC-6 bundling:* `ANSWER_AS_ME_DIRECTIVE` is one constant containing both clauses. Reviewer check on a
  diff: *is the first-person text and the no-fabrication text in the SAME constant, and is that constant the
  only thing the ON arm appends?* If a later edit splits them into two constants or makes the no-fab clause
  conditional, the bundled test (both substrings asserted together) goes red, and the mutation control
  (delete the no-fab sentence from the constant) proves the test has power.
- *AC-4 OFF identity:* the OFF arm is the bare `SYSTEM_PROMPT` identifier. Reviewer check: *does the OFF arm
  reference `SYSTEM_PROMPT` with no wrapping?* Any wrapping is a (benign but) flagged change; the baseline
  test asserts the OFF wire equals the committed `SYSTEM_PROMPT` constant.

**Instrument (AC-5/AC-6 server):** `route.promptInjection.test.js` `callWire(body)` with
`payload({ answerAsMe: true })` → `systemInstructionOf(wire)` contains a first-person substring AND a
no-fabrication substring (both asserted in one test). With `answerAsMe` omitted/false →
`systemInstructionOf(wire) === SYSTEM_PROMPT` (import the constant, do not hard-code the prose). Mutation
control: remove the no-fab sentence from `ANSWER_AS_ME_DIRECTIVE` ⇒ the ON test goes red.

## 5. Seam D — embedded honest-degrade — AC-9

**Structural guarantee (strongest form):** the embedded server branch at route.js:268-281 calls
`localChatReply({ messages, resumeText, applications, pinnedContext, attachedFiles, fetchedUrls })` —
whose signature (localAssistant.js:501-508) has **no voice/persona parameter**. It is therefore
*structurally incapable* of consuming `answerAsMe`: the flag cannot change embedded output no matter what
the payload carries. AC-9's "localChatReply output is unchanged by the flag" is true by construction, not
by a runtime guard that a later edit could remove.

**Diff-check:** *does the `localChatReply(...)` call site pass `answerAsMe` or any voice arg?* It must not,
and the function has no param to receive it. The AC-9 unit test asserts `localChatReply` output is
identical whether or not an as-me signal is present in the input (it takes none).

**Client flag on embedded:** the client reads `readAnswerAsMe()` unconditionally (Seam B) regardless of
engine. On embedded the flag may ride the wire as `true` (stale from a prior Gemini session) but the
server embedded branch provably ignores it (above). We deliberately do NOT couple the client read to the
engine in `chatbot.js` — that would add engine logic to the request shaper for no behavioural gain and
widen the AC-8 census. The honest-degrade is a UX concern (Seam E), not a wire concern.

**UX degrade (the honest part) — see §6.4:** when `isEmbedded`, the Switch is rendered **disabled**, its
ON-accent treatment is **suppressed** (it must not read as "on / drafting as you" while embedded), and a
brief inline note says the feature applies to the AI engine. No reply bubble ever shows a "drafted as you"
indicator on the embedded path. This closes the AC-9 misrepresentation door: the user can never see
generic coaching prose presented as their own first-person draft.

## 6. Experience design — the thin UX — AC-1, AC-2, AC-9

**6.1 Control choice: MUI `Switch` with an associated visible label.** A `Switch` is `role="switch"` with
native `aria-checked` — AC-2's "programmatically indicated ON" for free — and its thumb position is an
unambiguous visible ON cue. One click/tap or Space toggles it (AC-1 one-action, keyboard-operable). This
is the honest "clearly indicated when ON" control; preferred over a bare `aria-pressed` button because the
switch metaphor reads as a persistent mode, which is what this is.

**6.2 Accessible name — the MUI a11y trap (memory: mui-a11y-traps).** The name comes from a visible text
label associated with the input, e.g. a `FormControlLabel` with `control={<Switch .../>}` and
`label="Answer as me"`, OR `inputProps={{ "aria-label": "Answer as me" }}`. **Do NOT wrap the Switch in a
`Tooltip` as the source of its name** — MUI `Tooltip` sets the child's accessible description/label and
would steal or shadow the real name. If a longer explanation is wanted, put it in adjacent helper text or
a Tooltip on a *separate* info affordance, never as the Switch's only name. The AC-1 instrument queries
`getByRole("switch", { name: /answer as me/i })`; that must resolve.

**6.3 Placement: a thin row directly above the composer input row.** Insert one `Box` row between the
attach-error/drag-hint block (ChatPanel.js:651-660) and the `+File / TextField / Send` row
(ChatPanel.js:661). Rationale:
- It sits where the user is about to type, answering "how will my message be answered?" in context
  (minimize-clicks: no menu, no dialog, visible by default).
- It **displaces nothing** — the header actions row (214) is cramped with Clear/Close on mobile; the
  composer area has vertical room and already stacks optional rows (attachments, errors, drag hint).
- Reuses the existing visual vocabulary (small control, `var(--text-secondary)`, same sx scale as the
  `+File` button).

**6.4 States (all three, pinned):**

| engine | Switch state | visible treatment | note |
|--------|--------------|-------------------|------|
| gemini / external (AI) OFF | unchecked, enabled | default | none (OFF is the quiet default) |
| gemini / external (AI) ON | checked, enabled | accent thumb/track (MUI default checked) + label reads as active | optional: short "Replies are written in your voice" helper |
| embedded | **disabled**, accent suppressed | greyed, not showing an ON treatment even if stored value is `true` | brief inline note: "Answer as me applies to the AI engine — switch to Gemini in the top bar." |

**6.5 Wiring.** `ChatPanel` already imports `useEngine` (ChatPanel.js:12) and computes
`isEmbedded` (ChatPanel.js:64). Add `import { useAnswerAsMe } from "../settings/answerAsMe";` and, beside
the `useEngine()` call (ChatPanel.js:63), `const { answerAsMe, setAnswerAsMe } = useAnswerAsMe();`. The
Switch: `checked={answerAsMe && !isEmbedded}` (so the ON accent is suppressed while embedded),
`disabled={isEmbedded}`, `onChange={(e) => setAnswerAsMe(e.target.checked)}`. **No new prop is threaded
from page.js** — the store is read directly in `ChatPanel`, exactly as the engine is, so page.js is
untouched (contrast N103 which needed a `chatReviewDocument` prop; N102 needs none).

**6.6 No new live region (AC / minimize-clicks).** The Switch's own `aria-checked` is the announcement; do
NOT add a `role="status"`/`aria-live` region for the toggle (the panel already has two polite regions —
the error region and the review cue — and a third racing announcement is the exact hazard documented at
chatbot.js:770-774). The brief explicitly forbids a new `role=status`.

**6.7 Line budget.** ChatPanel is **746** lines; the global cap is **1000** (loop-implementer.md:20;
no ChatPanel-specific ceiling test exists — grep for ceiling/line-limit found only the global 1000 and
page.js's `<=3015`). The Switch row + hook read is ~18-22 lines → ~768, far under 1000. The AC's
"composite surface" note (N102.ac §3) is a legibility flag for the 8b re-judge, **not** a hard ceiling;
no extraction is required. If 8b wants the panel leaner, the escape hatch is a tiny
`AnswerAsMeToggle.js` sibling component — noted, not required now.

**6.8 jsdom instrument (AC-1/AC-2/AC-9):** render `ChatPanel` under the existing `ChatPanel.*.test.js`
harness. AC-1: `getByRole("switch", {name:/answer as me/i})`, fire click and keydown(Space), assert
`setAnswerAsMe` effect / checked flips. AC-2: assert `aria-checked` and a visible treatment differ ON vs
OFF. AC-9: render with the engine store set to `"embedded"` → the switch is `disabled`, shows no ON accent
(even with the stored value `true`), and no "drafted as you" text appears.
