## 1. Module home + boundaries

**Home: a new neutral namespace `lib/review/`.** The three consumers (N103 adversarial-review button, N104 weakness summary, N105 step-6) live in three unrelated areas; the primitive belongs to none of them. It is NOT `lib/llm/ideal/` (that is N105-specific; N103/N104 are not "ideal" flows) and NOT `lib/resume/` (it analyzes multi-draft documents + posting + corpus, not a résumé-text blob). A fresh top-level `lib/review/` keeps the pure core free of any consumer's transitive graph.

**Module map (all additive, all net-new):**

| Module | Purity | Responsibility | Exports |
|--------|--------|----------------|---------|
| `lib/review/reviewDocuments.js` | **PURE** | The single public analyzer. Orchestrates: builds the span index, runs the mechanical floor, applies the reference-selection layer, invokes the injected judge (if any), funnels **every** flag through the containment validator, sorts to a stable total order, computes `coverage`. | `reviewDocuments` (THE one analyzer, AC-16) |
| `lib/review/contract.js` | **PURE** | The single source of the vocabulary + the shape validators. Holds the 7-member `CATEGORY` enum, the `ORIGIN` enum, `LLM_CATEGORIES` / `FLOOR_CATEGORIES` sets, `assertContainedFlag(flag, index)` (AC-1), `assertWellFormed(result)` (AC-15), `computeCoverage(...)` (§5). Not an analyzer — constants + validators. | enums, sets, validators (NOT an analyzer) |
| `lib/review/mechanicalDetectors.js` | **PURE** | The six deterministic detectors, each with its OWN named vocabulary (§3). Imports reuse primitives (N2/N3/N4). | `detectMissingKeyword`, `detectRepetition`, `detectUnverifiableMetric`, `detectVagueUnsupported`, `detectConsistencySkeleton`, `detectAuthoritySkeleton` |
| `lib/review/referenceSelect.js` | **PURE** | The AC-2 authority-reference selection layer (independently testable). | `selectAuthorityReference(draft, realMaterial)` |
| `lib/review/geminiJudge.js` | **IMPURE (network)** — **SECOND SLICE** | The Gemini-backed judge factory: the ONLY module that touches the network. Built the judge the route injects. Its call-shape/grounding is 3b/plan (I4). Does NOT exist in the first slice (employer-plausibility DEPTH is second slice); the first slice ships the pure core + the seam contract + tests that inject a fake judge. | `makeGeminiJudge(client)` (second slice) |

**Why `contract.js` is separate, not over-abstraction (checker: "what has one caller").** It has three callers that MUST agree or the system breaks: the core emits against the enum, `mechanicalDetectors` + `geminiJudge` build flags against the enum, and the tests assert against it. One source of the 7-enum is exactly what AC-15/AC-16 require (no vocabulary drift across modules). `mechanicalDetectors.js` importing `contract.js` and `reviewDocuments.js` importing both is a DAG, not a cycle (contract depends on nothing in `lib/review/`).

**Why detectors are split from the orchestrator.** Six detectors, each with a distinct vocabulary and failure direction, plus the containment chokepoint and coverage logic, do not belong in one file: a single god-module would (a) make per-detector mutation testing (step 9) read across unrelated logic, and (b) bury the AC-1 containment validator — the single most safety-critical chokepoint — inside detection noise. **Alternative considered:** one `lib/review/reviewDocuments.js` holding everything (like `critique.js`'s single file). Rejected: `critique.js` is 114 lines with one bullet-level check; N106 is six categories × two polarities of vocabulary + a validator chokepoint + a coverage honesty coupling + an injected seam. The chokepoint and the seam each earn visibility.

**What this deliberately does NOT abstract yet.** (a) No per-category plug-in registry — six named detector functions called explicitly; a registry is premature until a 7th category is actually added. (b) No caching/memoization — the core is a pure function of its arguments and callers invoke it once per review. (c) No shared "term vocabulary" util extracted from `critiqueLocal.js` — see §11 (the reuse decision names this as a plan call, not a structure one, to avoid editing a copilot file outside N106's allowed set).

## 2. The public contract — full signatures

`reviewDocuments` is `async` (it `await`s the injected judge when present); on the no-judge path it performs **no IO** and resolves synchronously-computed data. Determinism (AC-11) and purity (AC-12) are claimed for the no-judge path and for any fixed-fake-judge path; a live LLM judge is non-deterministic by nature and the AC scopes AC-11 to the no-LLM path.

```
async reviewDocuments(input, options = {}) => Promise<ReviewResult>

input: {
  drafts: Draft[],                                   // 1 or more
  posting: { requirements: Requirement[] },
  realMaterial: { spans: RealSpan[] } | null,        // null unless some draft.authorityReference === "user-material"
}
Draft:       { kind: string,                         // e.g. "hypothetical" | "applicationReady"; opaque to the core, used only as a key
               spans: Span[],
               authorityReference: "user-material" | "internal-consistency" }
Span:        { id: string, text: string, section?: string, contextKey?: string }   // id is APP-MINTED; the core never mints one
RealSpan:    { id: string, text: string, contextKey?: string }
Requirement: { id: string, text: string }

options: {
  judge?: Judge,          // ABSENT ⇒ mechanical-only path (engineMode:"mechanical-only"). PRESENT ⇒ full path.
}
Judge: async (judgeRequest) => { flags: Flag[], evaluatedCategories: Category[] }

ReviewResult: {
  flags: Flag[],                                     // stable total order (§8)
  unresolvedQualifications: [{ requirementId, text }],
  coverage: { evaluatedCategories: Category[],       // sorted, ⊆ the 7-enum
              engineMode: "full" | "mechanical-only",
              complete: boolean },
}
Flag: {
  draftKind: string,                                 // === some input draft.kind
  spanId: string,                                    // scalar; ∈ drafts[draftKind].spans[].id  (AC-1)
  category: Category,                                // ∈ the 7-member enum
  evidenceRef?: { origin: "posting" | "real-material" | "draft",
                  draftKind?,                        // present IFF origin === "draft"
                  spanId },                          // scalar; ∈ the named origin's id-set
  message: string,
}
Category ∈ { missing-keyword, vague-unsupported, repetition, unverifiable-metric,
             employer-plausibility, consistency, unsupported-authority }
```

`judgeRequest` (what the core HANDS the judge — §4): the raw `input` PLUS a core-computed `referencePlan` so the judge never re-derives AC-2 and is physically scoped away from `realMaterial` on internal-consistency drafts.

```
judgeRequest: {
  drafts: [{ kind, spans, authorityReference,
             authorityReferenceSpans: Span[],        // core-computed: realMaterial.spans for user-material; [] for internal-consistency
             referenceMode: "real-material" | "internal-coherence" }],
  posting, realMaterial,
}
```

### 3.2 The floor/LLM split

- **Always mechanical, full contract depth (no LLM):** `missing-keyword`, `repetition`, `unverifiable-metric`, `vague-unsupported`. These four are the only categories that enter `coverage.evaluatedCategories` on the embedded path.
- **Mechanical SKELETON always runs, but NOT at full contract depth:** the date/title contradiction half of `consistency`, and the deterministic reference-split + date/title coherence of `unsupported-authority`. These skeletons CAN emit flags on the embedded path (AC-8/AC-9/AC-13 require it) — **emitting a flag in a category is NOT the same as evaluating that category to full depth**, so `consistency`/`unsupported-authority` are ABSENT from `coverage.evaluatedCategories` on embedded even when they produce a flag.
- **LLM-only (the judge supplies DEPTH):** `employer-plausibility` entirely, and the semantic depth of `unsupported-authority` and `consistency`. A category enters `evaluatedCategories` at full depth ONLY when the judge reports it (§5).

This is the exact honesty coupling the AC pins (AC §0 line 50, AC-3 I2, AC-8/AC-10): the embedded path is genuinely PARTIAL and says so, while still returning its useful mechanical findings.

## 4. The injected-judgment seam (I5) — shape, invocation, re-validation

**The seam is a function injected through `options.judge`**, not a value computed elsewhere, because the reference-selection responsibility (AC-2) stays INSIDE the core — the judge must receive already-reference-scoped context, which only the core can build. The route decides embedded-vs-full by whether it injects a judge; the core never reads `process.env` or calls `wantsEmbedded` (N5) — that keeps the core pure (AC-12) and makes `engineMode` a function of the seam, not of hidden env.

**Invocation sequence inside `reviewDocuments` (full path):**
1. Build the span index and run the mechanical floor (§3) → `mechanicalFlags`.
2. Compute `referencePlan` via `selectAuthorityReference` per draft (§7); attach `authorityReferenceSpans`/`referenceMode` to each draft to form `judgeRequest`.
3. `const judgeResult = await options.judge(judgeRequest)`.
4. **Re-validate every judge flag** through the SAME `assertContainedFlag` chokepoint (§6): a judge flag whose `spanId`/`evidenceRef.spanId` is not an input id is DROPPED (fail-safe). The judge is a trusted-but-fallible injected dependency (a live model); AC-1 must hold regardless of what it returns.
5. Restrict `judgeResult.evaluatedCategories` to `LLM_CATEGORIES ∩ reported` (the judge cannot claim a floor category — floor coverage is the core's own) → feeds `computeCoverage` (§5).
6. Merge `mechanicalFlags ++ validatedJudgeFlags`, dedupe exact duplicates, sort (§8).

**Determinism boundary with the LLM (AC-11 / I4).** The core imposes NO call-shape on the judge; the judge is a plain async function. So the judge implementation (`geminiJudge.js`, second slice) is free to honor the N105 research constraints — a CHAIN not one composite call, and `responseSchema` XOR `urlContext` mutually exclusive on gemini-2.5-flash (`gemini-tools-nesting`, `gemini-grounding-redirects`, N105 research A11/F-2). None of that leaks into the pure core. Tests inject a FIXED fake judge; that path is fully deterministic and is what the AC-3 `complete:true` positive control and the AC-12 seam-mapping test drive.

**Honesty at the seam (residual, → I5/I6 plan input).** The core trusts `judgeResult.evaluatedCategories` within the LLM subset — it cannot re-derive whether semantic depth actually ran. The forbidden direction is overclaim (AC-3). Therefore the judge contract carries an obligation the plan must encode in `geminiJudge.js`: **a category is reported in `evaluatedCategories` only on a successful, parse-complete LLM response for it** (ties to N105 research F-5, the missing `finishReason` check) — never on merely attempting the call. The core cannot enforce this; it is the judge's half of the honesty coupling and is named here so the consumer chunk does not ship a judge that overclaims.

## 5. The `coverage` population rule (I6) — pinned exactly

`computeCoverage({ hasJudge, judgeEvaluatedCategories })` in `contract.js`:

```
FLOOR_CATEGORIES = { missing-keyword, repetition, unverifiable-metric, vague-unsupported }   // 4
LLM_CATEGORIES   = { employer-plausibility, consistency, unsupported-authority }              // 3  (full-depth homes)

evaluatedCategories = sort( FLOOR_CATEGORIES  ∪  (hasJudge ? (judgeEvaluatedCategories ∩ LLM_CATEGORIES) : ∅) )
engineMode          = hasJudge ? "full" : "mechanical-only"
complete            = isSuperset(set(evaluatedCategories), the 7-enum)        // the SINGLE source of truth for complete
```

Consequences, each matching an AC clause:
- **Embedded (no judge):** `evaluatedCategories = the 4 floor`; `engineMode = "mechanical-only"`; `complete = false` (4 ⊉ 7). Always. (AC-3 I2.)
- **`engineMode === "mechanical-only" ⟹ complete === false`** holds by construction: without a judge, `evaluatedCategories` can never reach the 3 LLM categories, so it can never be a superset of 7. (AC-15 honesty coupling, second conjunct.)
- **`complete === (evaluatedCategories ⊇ 7-enum)`** is literally the definition line (AC-15, first conjunct). `complete:true` is REACHABLE only when a judge reports all 3 LLM categories — the AC-3 positive control drives exactly that with a fixed fake judge. (So the field is not dead/always-false.)
- **Overclaim is impossible via the core:** `complete` is DERIVED from `evaluatedCategories`, never passed in or set by a detector/judge. A judge cannot set `complete:true`; it can only report categories, which must include all 3 LLM ones for `complete` to become true. The forbidden fabrication-shipping direction (AC-3/AC-15 "failure direction") has no code path in the core.

**Checkable on a diff:** `complete` is assigned exactly once, by `isSuperset(...)` inside `computeCoverage`; grep shows no other assignment to `coverage.complete` and no `complete:` literal in any detector or in the judge-merge path. Mutant: replace `isSuperset` with `true` → the embedded floor-clean negative (AC-3) and the AC-15 coupling sweep both red.

## 6. Span ownership & the containment chokepoint (AC-1) — impossible, not forbidden

**The app mints span ids; the reviewer never re-chunks and mints no id.** The core builds, once, an index from the input:

```
index = {
  draftSpanIds:  Map<draftKind, Set<spanId>>,     // from drafts[*].spans[*].id
  postingIds:    Set<requirementId>,              // from posting.requirements[*].id
  realMaterialIds: Set<spanId>,                   // from realMaterial?.spans[*].id  (empty set when null)
}
```

**Every flag — mechanical AND judge-supplied — passes through the single chokepoint `assertContainedFlag(flag, index)` before it can enter the output array.** The validator asserts: `spanId` is a scalar string (never an array/union) and `∈ index.draftSpanIds.get(flag.draftKind)`; and if `evidenceRef` is present, `evidenceRef.spanId ∈` the id-set of `evidenceRef.origin` (posting ⇒ `postingIds`; real-material ⇒ `realMaterialIds`; draft ⇒ `draftSpanIds.get(evidenceRef.draftKind)`), and `evidenceRef.draftKind` is present IFF `origin === "draft"`. **A flag that fails is DROPPED, not emitted** (fail-safe: no fabricated/union id can reach a consumer).

**Why "impossible" (rule 2).** Two structural facts, each diff-checkable:
1. The ONLY writer to the output `flags` array is a single `emit(flag)` that calls `assertContainedFlag` first and returns early on failure. Diff-check: grep `lib/review/` for `flags.push` / spread into the result — the only occurrence is inside `emit`; no detector or the judge-merge pushes directly.
2. No `spanId` is ever CONSTRUCTED by the core — detectors read `.id` off an input span object and pass it through. Diff-check: grep `lib/review/` for string-concatenation into a span id (`+ "+" +`, template literals combining two ids, `.join(`); zero matches. The union-id stub (`"s1+s2"`, AC-1 Stub S) therefore cannot be produced by conformant code and is caught by (1) if a detector tries.

**Cross-draft `evidenceRef` (AC-9):** a `consistency` flag on draft D1 sets `spanId` = one offending span in D1 and `evidenceRef = {origin:"draft", draftKind:D2.kind, spanId:<one span in D2>}`. Both resolve through the chokepoint against their respective draft id-sets. One span vs one span — never a union (traps-spec grounding rule).

## 7. Per-draft authority reference selection (AC-2) + `realMaterial` null (AC-13)

**`selectAuthorityReference(draft, realMaterial)` is a pure, independently-testable layer** (`lib/review/referenceSelect.js`) — the AC-2 "deterministic reference selection" that is testable even though the plausibility JUDGMENT within the selected reference may later be LLM-augmented.

```
selectAuthorityReference(draft, realMaterial) => { mode, referenceSpans }
  draft.authorityReference === "user-material"       ⇒ { mode:"real-material",      referenceSpans: realMaterial?.spans ?? [] }
  draft.authorityReference === "internal-consistency"⇒ { mode:"internal-coherence", referenceSpans: draft.spans }
```

- `user-material` ⇒ judged against `realMaterial`. `internal-consistency` ⇒ judged against the draft's OWN spans (posting-plausibility + internal coherence), **never** `realMaterial`.
- This is what makes AC-2 structural even through the judge seam (§4): `judgeRequest` carries each draft's `authorityReferenceSpans` from THIS function, so an internal-consistency draft is physically handed `referenceSpans = draft.spans` for authority — `realMaterial` is never in its authority scope. A coherent-but-strong internal-consistency claim yields zero `unsupported-authority` flags, invariant to `realMaterial` (AC-2 Fixture H, Runs A/B identical).

**`realMaterial` null handling (AC-13), decided here (default per AC I3 = fail-closed-by-flagging):**
- **(a) No `user-material` draft present:** `realMaterial` MAY be null; the authority layer for the (internal-consistency) drafts uses their own spans; the core runs normally, no throw. The null `realMaterial` yields an EMPTY `realMaterialIds` set (§6), so any stray real-material evidenceRef would be dropped, never crash.
- **(b) A `user-material` draft present WITH `realMaterial` null (precondition violation):** `referenceSpans = []`. `detectAuthoritySkeleton` fails closed: every authority/support-requiring claim span on that draft is flagged `unsupported-authority` (no `evidenceRef`, since there is no real-material span to cite; the `message` states no candidate material was available). `coverage.complete` stays `false`. The result is NEVER `flags:[]` with `coverage.complete:true` — the forbidden "all supported" reading. (The refuse-with-signal alternative is admissible per AC I3 but the default is flag-maximally; the invariant + direction are fixed here, the FORM is I3.)

**Diff-check (AC-2 mutant):** an impl where `selectAuthorityReference` returns `real-material` for an internal-consistency draft makes Fixture H differ between Runs A and B → red. (AC-13 mutant): an impl that returns `flags:[]`/`complete:true` for case (b) reds the AC-13 fixture.

## 8. Determinism & stable total order (AC-11)

The core sorts the final `flags` array by a **content key**, never by input array position:

```
sortKey(flag) = [ flag.draftKind, flag.spanId, flag.category,
                  flag.evidenceRef ? stableStringify(flag.evidenceRef) : "",
                  flag.message ]                 // final tiebreak → TOTAL order
```

`unresolvedQualifications` sorts by `requirementId`; `coverage.evaluatedCategories` sorts by the enum's own fixed order. `stableStringify` serializes object keys in a fixed order so equal content always yields equal strings.

- **Repeat-call equality:** `reviewDocuments(I)` twice is deep-equal on the no-judge path (pure function of inputs, no clock/random — §9).
- **Shuffle invariance:** the sort key is derived from CONTENT (`draftKind`/`spanId`/`category`/…), so shuffling `drafts[*].spans` order yields a deep-equal result. The AC-11 instrument drives the AC-3 multi-defect draft (≥4 flags across distinct spans) to make the shuffle non-vacuous.
- **Diff-check / mutant:** an impl emitting in span-iteration order (or from a `Set`/object-key order) reds the shuffle test ONLY because the fixture guarantees ≥2 flags whose content order ≠ input-span order. Grep: the result assembly ends in a `.sort(bySortKey)`; no early `return flags` bypasses it.

## 9. Purity boundary (AC-12)

- `reviewDocuments.js`, `contract.js`, `mechanicalDetectors.js`, `referenceSelect.js` form a dependency graph that imports **only** pure siblings + the reuse primitives (`WEAK_OPENERS`, `extractKeywords`, `headerDateSpan`, and — if chosen — `profileSkills`/`containsTerm` via §11). None imports `geminiClient`, `fetch`, `fs`, or reads `process.env`/`Date.now`/`Math.random`.
- The ONLY network toucher is `geminiJudge.js` (second slice), reached solely through `options.judge`. The core never imports it.
- **Diff-checks (AC-12 instrument):** (1) a `fetch` spy records ZERO calls when `reviewDocuments(input)` runs with no judge, with a recording POSITIVE control proving the spy fires (traps-spec egress rule).
