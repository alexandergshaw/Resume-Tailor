## Purpose and checked boundary

Persist the ORIGINAL uploaded .docx used by a Gemini generation, separately from its generated content/finished document and separately from the mutable active default. On reload, historical selection, preview, local download, Drive save and N89 fact insertion must use that generation's original when it has no faithful generated docx. A server-docx generation continues to use its server document. No replacement of stored old versions with today's template; no empty/plain-doc fallback.

The accepted N97 contract supplies C2/C4/C5/C6/C7. Observable closure: two Gemini versions generated using uploads A/B, selected in a fresh context with no uploaded File, rebuild with their own A/B styles and their own content; promote from either persists that version's original bytes, and N89 fact insertion after reload succeeds with the saved original source. Missing legacy sources remain honest refusals. A/B activation/capture corrections and this persistence chain belong in one final N97 verification batch, avoiding duplicate whole-suite gates.

## One immutable attachment store, no schema change

New `lib/document/generatedTemplateStore.js` uses the existing private `resumes` bucket and existing generated row identity. Path is exactly `${authenticatedUserId}/templates/generated/${kind}/${versionId}.docx`, kind resume|cover. Inputs never include an arbitrary path. UUID versionId validation and closed kind mapping select `generated_resumes` or `generated_cover_letters`. Before BOTH upload and download, confirm authenticated session getUser matches supplied userId (or derive it), then select id with `.eq(id,versionId).eq(user_id,userId)` using the caller's authenticated client. Reject missing/foreign/wrong-kind row before any storage call. No service-role client, no signed public URL, no user identity accepted from a browser request body, no table creation.

Exports:

- `saveGeneratedTemplate(supabase,{userId,kind,versionId,file})` -> `{ok:true}` or `{ok:false,code}`. Non-empty structurally valid .docx only, upload raw original bytes with DOCX_MIME and upsert:false. Own generated row must already exist. Never store rebuilt/filled output under this path. No arbitrary overwrites or delete-and-replace retry; duplicate key is a failure unless equality is independently established. New generated row IDs normally avoid collision.
- `fetchGeneratedTemplate(supabase,{kind,versionId})` -> `{file:File}` or `{file:null,code}`; derive user from getUser, validate owned row, fetch deterministic path, validate nonempty readable docx. Never throw to UI. Code values distinguish missing-original, unauthorized, invalid-source, unavailable. No PII in diagnostic codes.

Use JSZip for .docx validity (required [Content_Types].xml and word/document.xml), not extension/MIME alone. File decoding, storage errors, malformed zip and arrayBuffer rejection produce a controlled failure. The helper may import pure byte/validation utilities, but must not import docx.js (would create a cycle once docx imports it). Lazy browser client creation belongs in the consuming adapter; store accepts injected authed client for tests.

No resumes bucket RLS policy SQL was found by rg `storage.objects|foldername|resumes.*policy|policy.*resumes` over local SQL. Existing uploads provide precedents for user-prefix paths, not proof of live permission. The N64/N151 migrations define template TABLE RLS only. The generated table base CREATEs are not in this repository; existing id/user_id queries are the app contract but live table shape is unproven. This plan introduces no migration or policy relaxation. Live operator still owes read-only schema/bucket/policy inspection and separately authorized real two-user access tests; static/fake passing results cannot claim live enforcement. Namespace denial returns unavailable and visible durability failure, never broadened access.

## Data-flow changes

Add optional `sourceTemplateFile` to each supplied resume/coverLetter object in persistGeneratedDocuments. Only Gemini caller branches pass it; server/native callers and N151 remain unchanged. SaveGenerated* keep their current string-ID return contract. The shared persist helper, after obtaining an ID, invokes saveGeneratedTemplate and returns additive per-scope `templatePersistence` status alongside existing IDs. No success if an expected snapshot failed, but preserve the saved generated content and application pointers: this is explicit partial durability, not an atomic rollback claim. Caller displays `The document is available now, but its original template could not be saved for later sessions.` through the existing persistence error/notice seam. Keep errors specific to the touched scope. No additionalContext/source_resume_path overloading.

Each generated scope entry receives an immutable in-session original binding `{file,kind,runToken,versionId:null}` tied to that run and scope (resumeSourceTemplateFile / coverSourceTemplateFile may carry this binding), and a generated-row `sourceTemplateVersionId` reference after persistence (resumeTemplateVersionId / coverTemplateVersionId). The generated ID does not prove snapshot success; keep templatePersistence status separately. When that same run succeeds in inserting its row, associate its binding with that exact versionId even if snapshot upload fails. The binding remains usable in-session on partial failure; no field claims reload durability unless upload succeeded. The run reference is captured before await; do not read a mutable global upload at completion. On regeneration clear that scope's old version identity immediately. When a background persistence result returns, update identity and binding versionId only if that scope still has the same run token/reference; older results must not affect current display. Per-scope ownership avoids cover-only revisions clearing resume identity. IDs are existing row IDs, not library template IDs; use distinct property names.

rehydratedEntryFromApp sets resumeTemplateVersionId from gen.id and coverTemplateVersionId from cover.id, and clears both in-session source File fields. selectDocumentVersion applies that scope's version.id and clears that scope's File; no stale engine/global-file fallback. Legacy rows have IDs but no object: missing-original is expected and must refuse without a plain doc. documentVersions.js query already includes IDs; no new column/query shape needed.

Add optional `sourceTemplate:{kind,versionId}` to resolveDocumentBlob and source File parameter scoped to the run. Preserve active formattingTemplate override semantics for existing current-session egress. Below faithful engine docxB64/docxPath branches, use the owned persisted original when a version reference exists; if it is absent/unreadable, permit only the exact entry-bound original whose kind AND versionId match the requested source and whose runToken matches the current scope run. If that binding is absent/mismatched return null, never fall through to the current global upload. An unauthorized/foreign-row resolution refuses even if supplied binding metadata claims a match; a binding cannot bypass ownership. For pre-persistence local entries with no version ID, require binding kind/runToken to match the current scope. The generic current uploadedTemplate option is not an entry-bound binding. If no version ref exists, use only the kind/runToken-matched entry-bound source File for new Gemini entries. Existing legacy callers with no new metadata keep existing uploadedTemplate semantics, except known restored entry metadata deliberately fences wrong fallback. Do not fetch snapshots when faithful engine bytes suffice. Template file is used to rebuild CURRENT lines/text with existing buildDocxFromUploadedTemplate; it is never served verbatim as the generated output.

previewBlobArgs passes conditional new source metadata and entry-bound source File for its scope. IO builder/docx resolver performs the actual fetch. buildDownloadArgs forwards `sourceTemplate` for resume, `coverSourceTemplate` for cover; downloadDocxFiles maps each to its own resolveDocumentBlob call. createDocumentDownloaders historical saved-row branches attach selected generated ID and kind; TrackingCard/TrackingTab direct saved-row calls pass own row ID where necessary. No active default introduced to these historical paths. Drive save and hash use the same previewBlobArgs, so their bytes and freshness hash agree without new Drive API behavior.

Accepted A/B promotion helper becomes source-aware: faithful server docx capture stays unchanged; Gemini original resolves the owned version snapshot when present, then the exact kind/version/run-matched binding on missing/unavailable snapshot; a pre-persistence entry uses its exact kind/run-matched binding. Foreign-row/unauthorized resolution refuses rather than trusting client binding metadata. A restored snapshot fetch must be awaited and errors written to per-scope flags. No current global engine toggle or currently selected library ID decides the entry's provenance. If no engine bytes and no valid bound/persisted original, refuse with no POST. Capture C2 asserts original bytes, while C4 rebuild asserts current generated text; these are separate oracles.

N89: in useCompanyResearch.resolveCoverEngineBytes, preserve engine b64/path first; when absent resolve that entry's original snapshot/bound File and build a faithful cover docx from entry lines using the common rebuild seam. Return those bytes into the EXISTING splice path, so the existing accept upload/RPC already persists finished post-insertion bytes. Use per-entry async resolution before accept/auto gates; do not merely change global `canRebuild` to true on an ID. Resolved real bytes discharge the guard, missing fetch retains refusal, and no empty bytes reach applyCoverDocxEdits. For legacy fresh-session Shape B, retain existing line-only strategy where original in-session File is known; do not substitute arbitrary newly uploaded Files for an explicit persisted version. remove/move and privacy log fields remain unchanged.

## Independent oracles and deliberate controls

- Real A/B ZIP fixtures differ in font and paragraph alignment; generated content C/D differs from placeholder content. Save helper byte equality proves original upload, while rebuilt document XML proves A+C or B+D after fresh-context restore. Two kinds use different fixtures; a scope swap must fail.
- Persist an actual generated row through fake-client integration; discard every in-memory File/cache/default; load linked app, open preview, switch version, download and Drive save. Each public flow uses immutable version metadata. Then mutate current global File/default/library selection: historical original resolution stays A/B. Retain accepted current-session active override behavior in its own tests; do not confuse that override with recovered original.
- New Gemini generation, resume-only/cover-only/both, revise and focus change, queued manual background completion, URL, job and interactive feed each pass their actual original File. Simulate two runs finishing out of order and ensure IDs/File references stay with their own run. Server-docx/N151/admin/manual upload controls omit snapshot and preserve behavior.
- Test POST promotion from restored Gemini original -> fresh GET bytes -> subsequent generated output styles/text. Snapshot existence alone is insufficient. N89 accept and auto-insert in fresh context with no File resolve real original, change lines, persist generated docx, and then rehydrate again. Missing/corrupt snapshot returns refusal BEFORE RPC/splice/write and never reports success.
- Partial-source availability oracle: generate with original A, succeed row insertion, force snapshot upload failure, then assert the notice says reload durability failed while preview, local download, Drive save and revise still work with the exact bound A File. Replace global upload with B; output remains A. Discard every binding/File/cache, reload the same row, and assert honest refusal. Wrong-kind, wrong-version and old-run bindings all refuse. Complete a newer run before an older failed upload returns; its warning/ID/binding must not overwrite the newer scope. Recovery retry uses a new generation or independently proven equal existing bytes, never overwrite. Mutation suppressing same-run binding fallback must fail this oracle.
- Two accounts with same-shaped IDs, wrong kind, foreign row, malformed UUID/path-like ID, unauthenticated getUser, missing row, upload duplicate, rejected upload/download/arrayBuffer, zero-length and non-docx zip. Assert no foreign storage call, no original overwrite, no empty/plain output, no misleading durable-success status. Failure of upload preserves already generated content but marks exact scope partial durability.
- Mutations: skip original snapshot upload; replace bytes with filled document; use today's mutable `${user}/resume`; remove owner predicate; drop kind namespace; carry prior version ID; remove a generation caller's File argument; let older completion update newer scope; widen N89 guard without real fetch; let missing snapshot fall through to today's upload. Each relevant family must fail a focused test, with actual mutated bytes confirmed, harmless control and restored control. Mutations isolated, no shared concurrent edit. Unknown live permission is not a test pass.
