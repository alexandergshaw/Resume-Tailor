## Architecture and dependency waves

Wave A is the minimal independently deliverable correction: save the reserved row through the existing store, then setSelection(userId, kind, row.id) through the existing selection store. POST reports success only after both succeed. On activation failure report an actionable failure: a reserved row may have been saved but the previous active choice remains; do not claim rollback or an atomic transaction. Preserve library rows and other kinds. No schema change is required. Independently review this wave before consuming it.

Wave B corrects Gemini capture using the original per-scope File when available, with the existing engine-native capture for server-docx entries. Engine classification must use actual entry provenance/available source, not the current global engine toggle (which can change after generation). For legacy ambiguous entries do not silently label a filled blob as the original upload. Existing saved generated docx is a faithful document source, but is not evidence that the original Gemini template was persisted.

Wave C is N89 Part 2, dependent on a separately checked implementation brief after complete caller discovery. Recommended no-schema design: persist the original File to the existing private resumes bucket at an immutable deterministic per-generated-version path `${userId}/templates/generated/${kind}/${versionId}.docx`, with upsert false; derive this path only from an owned generated row ID and authenticated user. This is an attachment convention for existing generation records, not a rival template/default table. Do not add snapshots to the user's library automatically. Resolve snapshots by version identity, never by mutable current default or `${userId}/resume`. Snapshot upload failures leave generation usable in-session but visibly mark reload durability unavailable. Never overwrite older snapshots; never reuse another scope's or version's snapshot. No live-schema assumption or migration is introduced. Existing storage policy must be inspected before implementation; if its path constraints reject this namespace, stop this wave for a checked design amendment instead of weakening policy.

The persisted original must reach every rebuild consumer through one shared resolver, with precedence faithful generated docx -> original immutable template -> in-session original for the same generation -> honest refusal. An active default is a future-generation formatting override, not a historical original-template recovery source. The candidate must distinguish capture/recovery from future default selection.
