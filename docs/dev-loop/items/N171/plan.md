## Layout and interaction design

Panel: use local responsive CSS grid with minmax(0,...) columns at a breakpoint that leaves review controls comfortable; below that breakpoint use one column. Suggested desktop ratio approximately1.4fr/1fr, bounded overall width around1280, gap24px and responsive padding. Both grid children require minWidth0. A locally scoped conversation card contains header/short purpose, transcript/empty state and composer. Header tools contain Start new proposal and a proper labelled MUI saved-search picker with wrapping. Preserve their existing reset handlers and disabled conditions. Keep account sign-in state unchanged. Do not add nested full-page scroll traps or sticky positioning that obscures keyboard focus.

Chat: comfortable minimum reading area, bounded scroll transcript, role labels, distinct subtle assistant/user surfaces using existing palette/background/divider/action tokens; no hardcoded global colors. Empty starters may say “Remote platform roles”, “Check every 2 hours”, “Tailor my resume only”; labels/content must not imply sending or enabling anything. Starters stay local to FeedConfigChat, set message state only, respect busy/disabled and focus composer through a ref/event rather than a network effect. Display starters in empty state; do not invent conversation turns. Keep existing2000-character bound and send handler contract, status/error/omitted-context announcements. Avoid duplicate log/live announcements or decorative accessible noise.

Review: local card header with proposal name/status and succinct description; clear subheadings/dividers. Keep JobFilterControls imported and all current field adapters/setters intact. Scoped wrapper sx may add spacing to its direct root controls; inspect actual rendered DOM before choosing selectors and do not change shared control source. Use local MUI FormControl/InputLabel/Select/MenuItem or equivalent existing MUI TextField-select for Documents and saved-search selection, with unique accessible labels and responsive widths; preserve existing option values and onChange null conversion. Keep CadenceControl unchanged in a spaced section. Preserve email switch, scheduling caveat, schema-error action path and no-auto-enable copy. Save footer remains visible/reachable and respects exact current disabled/saved/choice rules.

No browser persistence is introduced. No custom font/network/SDK installation or global styling. As-built UX/accessibility review is triggered by new visual structure/control replacements; security/data specialist is not newly triggered because semantics and data boundaries are frozen, but verifier must stop if diff changes those boundaries.
