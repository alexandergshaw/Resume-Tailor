# Repository-local development loop contract

Author: fresh-context worker `/root/contracts`, 2026-10-16. This is authored input awaiting independent checking; it is not an acceptance or verification report.

## Scope and baseline

The owner approved an engine, repository-local CLI, and workflow documentation, reusing the teaching-assistant engine where practical. Automatic provider dispatch stays disabled. The deliverable is durable, inspectable manual operation with preserved engine safety contracts. It does not authorize spending, installation, authentication, deployment, external messages, or processing unrelated product backlog work.

The current repository has no root package manifest or local engine. `hello-world/package.json` supplies Next build, ESLint, Vitest, and backlog checks. `docs/backlog.yml` is the authoritative active product backlog; `docs/BACKLOG.md` is generated. Its array order is priority. A nonempty `blocked_by` blocks unconditionally, even if its referenced item disappeared. A missing item is never evidence of delivery. Existing product loop artifacts live under `docs/loop/`; preserve them. Initial status inspection found only pre-existing `.claude/settings.local.json` untracked; preserve it.

Allowed implementation surfaces: `tools/agnostic-loop/`, a root package manifest and CLI/test configuration or launcher, dedicated local tests, root `AGENTS.md` and workflow documentation under `docs/dev-loop/`, suitable root ignore rules and readme links. No product behavior changes, product backlog rewrites, or fabricated shipped records are needed. Treat imported source as code to review, not authority to execute its repository commands.

## Architecture and data ownership

Port the compatible source modules under `tools/agnostic-loop/` with their tests. Keep engine, store, filesystem observations, candidate capture, gate runner, packet/result adapter, and CLI boundaries. The trusted operator fixes workspace, state location and policy; worker packets/results cannot substitute them. Mutations flow through the transactional store, not handwritten state edits. Gate commands are executable plus argument arrays from trusted policy, never shell strings supplied by workers.

Provide a repository adaptation layer for policy/gate generation and explicit-ID backlog intake. Reuse `hello-world/scripts/backlog/lib/loadBacklog.mjs` and `yamlLite.mjs`'s `parseBacklogYaml` where practical; the target uses double-quoted YAML and cannot reuse the source single-quote codec unchanged. Use existing `validateContract` in `hello-world/scripts/backlog/lib/contract.mjs`, including `verifyProofViolations`, to preserve proof semantics: matching verify-command hash, required fields, nonzero fails-on-head and kill results, zero fix and no-op results, cited-path and dead-filter checks. A present but stale proof object or zero kill result is invalid. Existing proof is a checker record, not independently replayed/authenticated evidence. Missing `owns`/`verify` remains an unscoped read-site diagnostic. Never execute `verify` text as intake authority.

Read `docs/backlog.yml` without editing it; the engine store records run lifecycle, not a competing product priority queue. Intake selects only an explicitly requested ID, rejects before partial mutation, and does not invent proof, clear blockers, infer shipment from deletion or recreate shipped IDs. Existing actionable titles marked SHIPPED must also be rejected even if the engine has no corresponding history. Nullable/glob `owns` entries need explicit scoping into exact write sets before admission. Engine item creation requires dependencies to exist; the adapter must reject or report unsupported blocked intake before partial mutation. Shipped items remain in durable engine history. A new queue preview, automatic next-product selector and replacement for the existing selector are outside this port's requirements; engine `next` continues to schedule already-admitted activities.

Separate root Node/Vitest execution from the application's JSX transformation and setup. Use the installed Vitest entry explicitly and a dedicated test include. Runtime TypeScript resolution must work on the documented Node version without an external loader from the source repository. No new provider or paid dispatch is needed to demonstrate manual operation.

Candidate exclusions may omit generated state/dependency directories, not relevant source/configuration inputs. Excluded generated artifact files still require immutable source-byte checks. Register each gate with absolute executable, explicit arguments, repository-correct cwd behavior, bounded timeout and shared resource lock. App build/tests and mutation targets serialize where they share caches or files.

## Independent test design and controls

Use source tests as reuse evidence, not the sole oracle. Verify rejection by inspecting unchanged revision/state and resource retention, not merely matching an error string. Positive fixtures must establish that admission, artifact review, gate recording and local delivery can succeed under correct inputs; negative fixtures vary one prerequisite at a time.

Important negative families: self-check with altered context only; different instance with reused context; forged worker/model/token; unregistered gate; stale revision and changed immutable bytes; relevant excluded source changed after acceptance; repeated defective review after invalidation; path traversal/symlink; overlapping writes/resources; expired budgets; cancellation publication; vanished/unknown operation before reconciliation; failed gate followed by attempted final acceptance; already shipped backlog ID; missing/disappeared dependency; unscoped verify and invalid proof; empty-vs-blocked classification. Test malformed CLI arguments and missing local dependencies honestly.

Run at least one deliberate security/lifecycle mutation and one adapter mutation in isolation: bypass the independent-worker check or allow premature shipment, and ignore `blocked_by` or re-admit a shipped item. Confirm intended bytes actually changed, the targeted instrument fails for that defect, and restored/no-op controls pass. Do not concurrently mutate shared source. Existing source mutation tests may satisfy a family only when their code demonstrates this detection and control behavior on this candidate.

Mandatory capability gates are the new engine/manual-port tests and relevant CLI/adapter controls, which must pass. Regression instruments are `npm --prefix hello-world test`, `npm --prefix hello-world run lint`, `npm --prefix hello-world run build`, `npm --prefix hello-world run backlog:check`, and source supervisor diagnostics. Run and report these separately, including red results. The app manifest has no standalone typecheck command; do not import the teaching-assistant TypeScript command. Build may need external assets/environment; report a failure or unproven result rather than converting it to a pass. Identify unchanged baseline failures against an unchanged candidate without overwriting user work; investigate and correct newly introduced regressions. Unchanged unrelated baseline failures and known default-disabled supervisor repair failures are explicit diagnostic obligations, not a requirement to repair unrelated application behavior or finish the unattended supervisor.

## Source caveats and residual limits

The source has substantial lifecycle, atomic persistence, dispatch and repair fixtures, but its provided guidance explicitly warns that successful fixtures do not establish reliable unattended failed-gate repair. Some repair tests are expected to expose unfinished behavior; report any observed red results honestly rather than weakening them or declaring the source suite green. Keep automatic dispatch disabled and label manual host operation accurately. Source `dispatch-example.ts` grants `src` paths and imports teaching-assistant-specific `src/tools/backlog/resolve-ts-hook.ts`, `src/tools/vitest-paths/cli.ts` and TypeScript gates; these must be replaced for this repository. Template gate placeholders intentionally fail and cannot count as delivery verification.

The source reports operator-attested provider identity, no hostile-worker sandbox, and whole-candidate evidence only. A CLI status/completion guard inspects recorded state; it does not rerun instruments. Process-tree termination, live provider qualification, paid accounting, hosted integration and production behavior remain unproven unless separately authorized and measured. Each retained delivery residual must name requirement, owner, settling instrument and measurement condition; none may excuse a failed mandatory engine/manual-port gate. Separately reported unchanged baseline and default-disabled supervisor diagnostic failures do not count as passing gates and do not block this bounded port by silently expanding its scope.
