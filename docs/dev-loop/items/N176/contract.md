## Scope and current alternative

Owner requests a NEW top-level tab, sibling of Interview Copilot, supporting all twelve activities in the supplied phone-screen process. Use label **Interview Preparation**, mainTab value `preparation`, adjacent to Copilot. N176 has no match in docs or tools searched, including authoritative backlog; root must confirm uniqueness at admission. Existing Tracking prep packs provide four sections, Copilot supplies live/practice capture, but there is no durable twelve-step preparation workspace. A static checklist or a link to Copilot alone does not satisfy this request.

Concrete advantage over direct chat: select a tracked application once; load its actual submitted documents and existing sourced prep; derive and retain a linked role-evidence map, reusable examples, timed answer review and repair targets, printable reference and follow-up draft in one per-application workspace. Changing one input regenerates only on command, preserves edits, and marks generated material stale rather than silently presenting old output as current. Local deterministic tools operate without a model key. Existing research remains explicitly user initiated and its source/failure states remain visible.

All twelve activities are in scope. No invented career facts, compensation, company events or interviewer biographies. Missing inputs become explicit gaps/questions. No automatic email/send, calendar booking, recording, device permissions, cloud syncing or new provider integration. No changes to Copilot capture/practice internals, prep-pack route/schema, auth, accepted-facts editor, resume export or automatic dispatch grants. Browser-local storage is disclosed, not described as account/device syncing.

## Persistence and lifecycle contract

New key prefix `interview-preparation:v1:` + encoded userId + ':' + encoded applicationId, with fixed `manual` application key. Logged-out local draft is a separate `guest` key; never copy automatically between guest/account. Root prop userId change remounts account boundary (React key), selecting application remounts workspace boundary. Saved selection is itself account scoped. No secret/token values in storage. UI states browser-local, stays on this device/browser, and can export workspace JSON. Do not reuse `copilot-prep-context` as an output store or overwrite user's original context.

Hydration must read before any save; do not overwrite stored draft with blank initial state. Record version, updatedAt, inputs, artifacts with input basis, source snapshots, attempts. Validate objects/types/size and cap input/attempt/archive lengths; refuse too-large import/export if import included (import is not required). Storage write failure sets visible unsaved status while current edits remain; retry save/export. Corrupt JSON is not silently overwritten on mount; show reset/recovery choice, explicit reset confirmation. No destructive app/database cleanup needed for browser-local disposable live fixture; remove only exact test workspace key through app reset after verification, not unrelated local state.

Generated artifacts capture explicit normalized input basis. Changing job/resume/research/logistics marks affected outputs stale; retain user edits, regeneration requires button and preview or separate generated draft so it cannot overwrite user content silently. User can accept suggested draft or keep old version. Requests and snapshot adoption bind current account/application generation; completion from previous selection must not save into new key. A response also captures input revision: edits during the request must not be overwritten; offer the captured-input result separately or mark stale. Timer/attempt state is local, stops cleanly on unmount; no background microphone/provider task.
