## Scope and baseline

Owner request: “the preview and edit modal could use a ux/ui overhaul.” N178 is a bounded reversible visual/navigation change. Current DocumentPreviewDialog.js puts document tabs, focus/framing, scan/research/AI, versions/highlights, Preview/Edit and spacing into one wrapping top bar. Fixed filename/editor/result rows above and revise/template rows below compete with a small md document viewport. Primary activity and optional regeneration controls have equal visual rank. Existing paper typography/export fidelity must remain unchanged.

Advantage: immediately visible document and Preview/Edit navigation plus collapsed, labeled secondary tools remove the need to search a wrapped toolbar and reserve substantially more initial document space. Unlike copying into direct LLM chat, the same existing editable document, saved filename, version and delivery actions remain attached to the posting. No new AI/editing capability is claimed. Pure presentation/navigation creates no new data path: diagnostic exception applies; retain existing loading, saving, per-scope error/notice, copy and Drive feedback exactly. Disclosure state is local ephemeral UI state only.

Exclusions: N177 formatting feature in isolatedcopy; new formatting commands; document parsing/HTML/export/clipboard algorithms; model generation; auth; Drive; APIs; persistence semantics; new automatic requests; deployment; backlog changes. No data or service contract changes.

## Design and implementation contract

Use an lg dialog on desktop (~1120px maximum), near-viewport height with rounded desktop paper and fullScreen mobile via existing useIsMobile. Use MUI9 `slotProps.paper.sx` for paper height/minHeight/overflow (local installed Dialog.d.ts confirms slotProps and maxWidth). Title becomes two typographic levels: stable “Tailored documents” heading and muted wrapping company/job context. Close stays obvious; retain existing mobile Close accessible name and footer Close.

First navigation row is only document Tabs (scrollable with automatic scroll buttons using installed Tabs API); second compact workspace row contains the existing Preview/Edit ToggleButtonGroup, email explanation when relevant, and a labeled “Document tools” disclosure. Preview/Edit never goes into disclosure. The mode group gets an accessible group label. Preserve the original visible labels and all scope gating.

Extract current secondary control JSX into PreviewDocumentTools.js, retaining prop inputs/closures and original guards: focus/framing, scan posting, cover research, Ask AI, versions/highlight and spacing. Group under short visible headings “Tailoring”, “History”, “Layout” as appropriate, with flex wrapping and clear section dividers. Use a native button with aria-expanded/aria-controls plus a named region, or installed MUI Accordion/Summary/Details (local Accordion.d.ts confirms expanded/onChange/slotProps); do not use deprecated transition or PaperProps APIs. Keep secondary children mounted while collapsed so selecting tabs/disclosing does not restart effects, clear template selection or trigger requests; collapsed content must be hidden and untabbable. Initial/reopen state collapsed. No new persistent settings. Existing components remain owners of their behavior.

Use one flexing scrollable DialogContent workspace (minHeight:0) below compact navigation. Move lengthy optional top bands, company references, ReviseStrip and TemplateControlsRow into this scrollable area rather than fixed-height outer rows; their original conditional expressions and relative content order survive. FileNameRow stays near the document, EditorToolbar immediately above editor only in edit. Canvas uses existing pageSx content typography unchanged, with improved surrounding neutral gutter/padding and sufficient small-screen width. Never place document/footer controls inside disclosure or collapse live feedback. The footer and unconditional DriveResultRegion -> CopyFeedbackStrip -> DialogActions order stay outside the workspace. Preserve exact DialogActions child components and button census; only sx changes there. TemplateControlsRow remains outside DialogActions. Do not add any action button to the actionbar.

At narrow sizes, use stacked title/context, full-width horizontally scrolling tabs, mode/tools row wrapping deliberately, and minimum-zero flexible containers. Footer uses smaller gaps/padding and wrapping without changing markup/control roles. Very long titles/filenames/controls wrap or truncate with existing full accessible text. Expanded tools live in workspace scrolling; a very short window must still allow scrolling to document and footer, rather than a fixed panel consuming the full canvas.
