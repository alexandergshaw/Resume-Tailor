## Structure and lifecycle contract

CameraQuestionSource accepts the same onSubmit, disabled and button/confirmation semantics as typed input, plus contextKey. Forms are siblings, never nested. Camera edit value and announcement are separate from typed value/announcement. Only strict onSubmit(...) === true announces success and clears camera draft. Rejection retains it. Normalize for Add using existing normalizeManualQuestion, but prevent undisclosed truncation: editor shows length against1200 and disables Add while raw normalized text exceeds1200. OCR may return up to12000 characters, shown editable with explicit select/shorten guidance; server rejects larger output as unreadable rather than silently selecting a question.

Start calls getUserMedia({video:{facingMode:{ideal:"environment"}},audio:false}) only after explicit action. Own only returned tracks; never reuse or stop practice/STT stream. Read original unmirrored pixels. Video has accessible label, muted and playsInline. Capture requires readyState>=2 and positive videoWidth/Height; scale preserving aspect ratio to max1600x1200 and at most1920000 pixels, export PNG, reject empty/oversize Blob. One capture produces one fetch; disable duplicate capture while reading. No timer/poll loop. Keep preview until close/context invalidation; tracks remain clearly indicated while active.

Maintain operation generation token in a ref. Every Start/close/context change/unmount invalidates prior acquisition and read callbacks. A late acquisition must stop all its own returned tracks without repainting. A late read cannot update review/error/announcement or submit. Abort fetch on invalidation as a bandwidth optimization, never as proof of server OCR termination. Release owned tracks, clear srcObject and handlers, and discard image buffers after request. Track ended gives understandable stopped-camera status and invalidates pending work. Retry reacquires only explicitly.

Both hooks add render-safe monotonic cameraSessionEpoch state, functional increment at each Start AND Stop entry before any await, and return it. Do not substitute Date.now or activeSessionId or status alone: practice Stop currently awaits teardown before idle; same-clock restarts must still differ. Clients derive context from epoch, selected posting identity, selected profile/format/interview type as relevant and mode. Exact primitive selection must inspect actual local state names; no serializing full sensitive objects. Camera child keyed/reset by this context, never whole ManualQuestion (preserve typed draft). Mode unmount fences callbacks. These epochs do not claim to fix unrelated existing audio races.

## Authenticated route/resource contract

Node route receives raw image/png request body, avoiding multipart parser allocation before size checks. Authenticate with existing getAuth/unauthorized BEFORE reading body, validating image or invoking OCR. Reuse module-scope createRateLimiter/identify/rateLimitHeaders:10 attempts per600000ms per authenticated identity, including denied attempts; clearly a per-instance limiter, not fleet-wide. Apply before expensive work.

Allow only image/png (optional parameters parsed safely); reject unsupported415. Maximum body2097152 bytes; optional Content-Length early rejection is additional, never sole enforcement. Stream request.body, count chunks and cancel reader on crossing limit; reject413 without OCR. Handle empty/malformed reader400. Validate PNG signature and first IHDR chunk length13/type; read width/height as unsigned big endian; require each>=1, width<=1600,height<=1200, product<=1920000 before OCR. Reject invalid header/dimensions422. Header checks are bounds, not a complete PNG decoder; Tesseract decode errors return sanitized422 and no text. No arbitrary URL fetching, SVG, JPEG, WebP, base64 or metadata processing.

Reuse only screenshotOcr.ocrImage(buffer), never readScreenshotOffline, posting-from-image route, Gemini, search, extractPostingMeta or terminateOcrWorker. One module-scope in-flight camera OCR slot per instance, acquired only after validation; overlapping valid request503 with Retry-After. Run one OCR promise. Response watchdog20000ms returns504 with retry guidance but DOES NOT release slot until actual underlying OCR promise settles. Clear timer/release exactly once on underlying resolve/reject; catch late rejection. A hung shared worker leaves this route busy until process recovery, explicitly a fail-closed availability limitation. Never terminate shared worker or claim process cancellation; other OCR users retain ownership. This slot does not serialize other routes using the shared worker and is not global distributed concurrency. Existing shared OCR/language package may fall back to CDN, disclosed before capture. runtime maxDuration60 is hosting bound, not termination proof.

Response success {text} only, trim string; empty output422, output>12000chars422 with recapture/select-smaller-area guidance. No frame persistence, console/frame/body logging or downstream answers in route. Existing answer engine is invoked only by explicit successful Add through existing sink. Auth/error/busy/timeout messages remain sanitized.
