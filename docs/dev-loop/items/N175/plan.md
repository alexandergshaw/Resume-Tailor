## Request, baseline and advantage

Owner reports that missing EMAIL_FROM prevents enabling auto-tailoring and asks why. Coordinator assumption: remove this accidental prerequisite while retaining separate explicit email opt-in and explicit unattended-work confirmation. Advantage: a user can generate matching documents into the review queue without configuring an unrelated delivery service, rather than manually asking an LLM to tailor every match.

Observed baseline: FeedAutomationCard.js computes unavailable = !emailConfigured, disables the auto-tailor switch and says it cannot be turned on until email is configured. The email switch itself is not availability-gated. FeedAutomationPanel.js reads /api/alerts/status and pessimistically retains false on pending/error. FeedAutomation.wiring.test.js AC-E5 explicitly enforces that inverted ownership. Server PUT /api/saved-searches/[id] sanitizes and writes separate flags without an email-config gate. page.js setSavedSearchAutoTailor writes only supplied fields. Cron processUser independently selects auto searches, tailors and inserts an in-app notification before best-effort opted-in mail; mail pause/kill switches do not gate tailoring. Therefore no server production change or schema migration is needed.
