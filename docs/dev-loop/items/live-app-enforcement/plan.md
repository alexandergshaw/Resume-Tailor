# Mandatory live-app enforcement contract — proposed for independent check

Author: native worker /root/live_engine_contract. Scope: engine/transport completion control and bounded documentation, plus host measurement of the existing N174 feature. No provider dispatch, deployment, login, installation or product feature change is authorized. Historical records remain historical; they cannot satisfy the new completion requirement by their status alone.

## Criteria and practical advantage

L1. A production item cannot advance to shipped without a current, independently accepted same-item live-verification report. Missing, failed, partial, unknown-deployment or stale reports reject with a live-verification diagnostic. Instrument: engine negative/positive tests and isolated completion-guard mutation. This closes the current gap where a final report plus offline gates can establish shipped without browser observation.

L2. Reports bind the exact full Candidate (including policy/environment/tool hashes), actual canonical live URL, observation interval, report author, deployed revision identity and candidate-containment evidence, expected/observed user-flow steps, sanitized immutable evidence references and cleanup outcome. Unknown identities and pending/failed steps can be retained as diagnostic artifacts but cannot pass. Engine-only changes require a live smoke check explicitly labelled separate from engine correctness. Instrument: schema/event/immutable-import and candidate-drift tests.

L3. Acceptance uses the existing independent checker protocol, requiring both distinct worker instance and fresh context from the report author, and independence from implementation authors. Report import and observed-event admission bind exact JSON bytes, not caller-supplied context alone. Referenced evidence is imported immutable data, checked on store load. Instrument: changed payload, changed blob, missing attachment, wrong author/item and self-review negative tests.

L4. All completion entry points fail closed for historical shipped states lacking evidence: engine shipped transition, manual handoff/root handoff, and supervisor nextActions. No fixture/test flag, CLI option, missing optional field, owner residual or old status bypasses the requirement. Offline fixtures can simulate valid records to test protocol; they never establish real browser truth. Instrument: historical shipped tests, public CLI tests, scheduler tests.

L5. Repository publication remains independently checkable before deployment. Git-only loop:delivery continues proving exact clean main/remote identity, labels its proof repository-only and does not claim live completion. Root handoff combines local/live acceptance and Git delivery. This avoids a circular dependency: source must be pushed before an automatic deployment can contain it. No deployment command is introduced.

L6. Root exercises N174 in the authorized live app after confirming candidate containment: discoverable suggested name, manual edit preserved through another reply, blank-name failure and recovery, explicit save/reopen persistence, and disposal of only newly created bounded test rows. Record URL/time/deployed identity/steps/results/evidence/cleanup and independent evidence check. Existing authorized signed-in session only. Missing deployment/access/authority leaves this obligation pending; no fixture substitute.

## Architecture and lifecycle

Reuse the immutable artifact lifecycle. Add LiveVerificationReport plus an optional liveVerificationReports map to legacy schema-version-1 state/context. Missing legacy map normalizes to empty; it is never evidence. Introduce live-verification.record with assignment/artifact/report. Observe immutable JSON bytes using the same mechanism as verification.record/final.record. Extend store reference validation to this map and every referenced evidence artifact/blob. Require an admitted verifier assignment on activity kind live-verification, same-item report artifact, exact author/assignment identity, current candidate, bounded timing and allowed evidence ownership. Keep existing clean review.record as the sole acceptance path; a record event is not independent acceptance.

Report proposal: schemaVersion 1; candidate; worker; mode affected-flow|smoke; url; started; finished; deployedRevision (nonempty immutable identity); candidateBinding (method and evidence references); steps array (name, expected, observed, status passed|failed|pending, evidence references); cleanup (status complete|not-needed|pending, details/evidence); limitations. No boolean assertion alone substitutes for candidateBinding evidence. At least one nonempty passing browser step, one evidence object and nonempty deployment binding are required for accepted completion. Unknown revision must be represented for pending artifacts, but is never eligible. Exact field names can be chosen by implementer without changing these obligations.

Use canonical URL https://resume-tailor-tan-psi.vercel.app/ as a trusted repository constant; comparison must reject localhost, credentials, query redirects, other origins and fragment-only substitutes. A report may name an affected same-origin route in a separate field; that is not a replacement authority. No optional disable policy. The generic engine is now mandatory-live by default; offline demos supply synthetic report records and explicitly label their output protocol-only. If generic configurable deployment targets are desired later, require a separately reviewed trusted-policy design; do not add an unbounded report-selected target now.

Add one reusable live-verification completion assessor (pure, no browser automation), used by shipped/final checks and historical completion callers. It selects current accepted same-item report artifact, validates evidence/current bytes/candidate and independent recorded review. Production store-backed handoff must obtain fresh store.context and compare current candidate; a raw status snapshot alone cannot prove freshness. Evidence freshness must not disappear because an item already says shipped. Do not automatically mutate historical states to shipped or silently invalidate their history. Reports or artifact versions invalidated by existing invalidation stop qualifying.

Do not necessarily gate regression-passed/final assembly on deployment: local verified source can be assembled and published pending live measurement. Gate shipped and overall completion; final reports may explicitly include pending live status and later refreshed independently reviewed report. If a final report schema gains a live reference, allow missing on historical reports but never infer pass. This ordering prevents requiring live deployment before the source is pushed.

Engine attestation limitation: schemas/hashes/independent recorded identities cannot prove that a human actually opened a browser or that external screenshots are truthful. The authorized host must capture actual browser observations and a separate checker judges their limits. Explicitly disclose this; do not describe a JSON validator as browser truth or cryptographic deployment verification.

## Verification plan and controls

Baseline current shipped transition accepts accepted final without live record; manual-handoff and nextActions trust shipped alone. Preserve a minimal baseline reproduction as a test asserting the new rejection, not a false historical pass. Independent test designer should use an engine-ready fixture with offline gates and accepted final and omit only live evidence, then add valid synthetic report plus distinct checker as positive control. Test stale full candidate (including environment/policy/tool), wrong item, missing/unknown deployment identity, alternate URL/localhost, no browser steps, failure/pending step, cleanup pending, absent/tampered attachments, raw payload versus immutable bytes, self-check, invalidated/superseded report, old shipped state and snapshot/context drift. Prove isolated mutation of the live completion guard makes the negative test fail and restore exact bytes. Use no mutation on shared source.

Mandatory npm.cmd run loop:test. Separate npm.cmd run loop:test:dispatch as offline diagnostics. Registered engine/test/lint/build/backlog gates apply according to coordinator's exact source scope, with source reuse allowed only after current input identity proof. Serialize workspace/cache gates. Root owns live app actions and bounded data cleanup; verifier independently reviews sanitized observations. Final report independently checked. Commit scoped source on main, push normally, run npm.cmd run loop:delivery and record exact remote identity. Repository publication and live verification reported separately if deployment lags.

Assignment/time bounds remain coordinator-owned. The implementation must report contradictions before silently weakening an obligation.
