### R-380 | area: text-phrasing | parallel-safe: yes | automatable: yes

**Summary:** `pickDistinct` (`hello-world/lib/text/phrasing.js`) used to retry on index collision inside an unbounded `while` loop that advanced a single hash value with an LCG step (`h = imul(h, 0x01000193) + 1`). Hull-Dobell's third condition (`4 | m ⇒ 4 | a-1`, for modulus `m = 2^32`) fails for that multiplier: reduced mod 4 the recurrence is `h → 3h+1`, which reaches only 2 of the 4 residues from any starting value. So whenever `options.length` was divisible by 4, the loop could only ever reach `length/2` distinct indices and then spun forever once every reachable slot was already filled — and because `n` defaults to `options.length`, the plain call `pickDistinct(seed, options)` on such a list could never terminate. This was a LATENT hazard, not a production outage: every one of the ten `/copilot` "Speak as" role banks in `lib/copilot/roleSituations.js` holds exactly 5 situations (5 % 4 ≠ 0, so always safe), and the only other caller, `lib/chat/localAssistant.js`'s `salaryGuidance`, draws `pickDistinct(seed, SALARY_TIPS, 2)` from a 4-entry array — length 4's reachable ceiling is exactly 2, so that call sat exactly on the safe edge with zero margin. Every seed the running app has ever used therefore terminated. The exposure was growth: `roleSituationBank.contract.test.js` only asserts `situationsFor(role).length >= 5`, so a content author adding situations to a bank (or tips to the list) up to 8, 12, 16 or 20 entries would silently hang `POST /api/copilot/role-situation` (or the salary-tips branch of the embedded chat assistant) forever, on an otherwise fully green suite, with no change to `phrasing.js` itself. `pickDistinct` is now a seeded partial Fisher-Yates shuffle whose outer loop is a bounded `for` running exactly `count` times, so termination is a property of the loop's shape and no longer depends on the hash function's reachability at all.

**Steps:**
1. From `hello-world`, run `npx vitest run lib/text/phrasing.test.js --no-file-parallelism`.
2. From `hello-world`, run `npx vitest run lib/copilot/roleSituations.contract.test.js --no-file-parallelism`.
3. From `hello-world`, run `npx vitest run lib/chat/localAssistant.test.js --no-file-parallelism`.
4. Read the MECHANISM comment above `pickDistinct` in `hello-world/lib/text/phrasing.js` and confirm the draw loop is a bounded `for (let i = 0; i < count; i += 1)` against the current tail size, never a retrying `while`.

**Expected:** All three files pass, with no test hanging at any swept list length 1..20 — including the lengths divisible by 4 (4, 8, 12, 16, 20) where the old generator was defective — for both production call shapes: `lib/copilot/roleSituations.js`'s `pickDistinct(role, situations, situations.length)` (the "default-n", full-permutation ask) and `lib/chat/localAssistant.js`'s `pickDistinct(seed, SALARY_TIPS, 2)`. The fix changes observable behavior, not just termination: `nextRoleSituation`'s seeded order now differs from the bank's declaration order for all 10 role banks (R-233 requires at least 5 of 10 to differ; all 10 now do), and `salaryGuidance`'s 2-of-4 draw now reaches all 12 possible ordered pairs of tips across seeds, where the old generator's per-seed mod-4 orbit could reach only 4 of them. `pickDistinct`'s clamp (`Math.max(0, Math.min(n, list.length))`) returns `[]` for any `n <= 0` and the full list for `n > list.length`, in both cases without looping at all.
