**MERGE, NEVER REPLACE — the write that silently kills a working connection.** `driveTokens.js` subscribes to google-auth-library's `'tokens'` event, which `lib/gmail/gmailClient.js` does **not** — a repo-wide sweep for `.on(` finds zero listeners outside this wave, so Gmail's transparently-refreshed tokens are simply discarded. Persisting them is the whole point of the module, and it is also where the trap is: **a refresh response carries no `refresh_token`.** A write that replaces the stored record therefore wipes the long-lived credential and converts a working connection into one that dies at the next access-token expiry — with no error at the moment of damage, and the failure arriving an hour later as a spurious "reconnect". `refresh_token` gets a stricter guard than every other field for exactly this reason: present-and-non-empty, or not written. Verified two ways — at the call boundary (the save never sends `refreshToken` for a refresh-shaped source) **and** end to end through the real store module (the stored value survives) — with a positive control proving a genuinely NEW refresh token still does overwrite, so the guard cannot degrade into "never write it".

**THE JOIN THAT DID NOT EXIST.** `driveSaveBatch` emitted `summary` as a plain formatted string; `DriveResultRegion` expected a `{kind,…}` descriptor and switched on `.kind`. There was no adapter, no document naming one, and **both sides were green**, because neither had ever met the other. The obvious wiring — pass `summary` into `leadingLine` — fell through `resolveLeadingLine`'s `default: return null`: the leading line **vanished**, the rows still rendered, the strip still looked plausible, and nothing threw or warned. Fixed at the SOURCE: the producer now emits the descriptor and the string field is gone from the return object entirely, rather than adding an adapter, which would have been a third place the shape is known and a second, wrongly-shaped way to wire the same fact. The guarding test feeds the REAL producer's REAL output into the REAL consumer — **a hand-built fixture is precisely what hid this for a whole wave.** Mutation: make `buildLeadingLine` return pre-formatted strings again → the join tests go red.

**THE PROMPT THAT DID NOT REMOUNT — and the fix that passed for the wrong case.** `DriveOverwriteDialog` was rendered with no React `key`, so a second conflict reconciled into the same node: the mount effect never re-ran, focus was never re-taken, the heading silently flipped from *"'X' has changed…"* to *"Both Docs have changed…"*, the button labels went plural, and the destructive callbacks swapped underneath a user who had already read and was about to act on the first prompt. Nothing is written without a click, so it fails safe — but the click the user makes is no longer the one they decided on. **The first fix keyed on `prompt.id ?? JSON.stringify(prompt.docNames)` and its test drove conflict A → B with DIFFERENT documents, so it passed.** The same Doc conflicting twice — the likeliest repeat, since an undecided prompt plus a retry names the same file — produces a byte-identical key. Probed with the previous prompt blurred first so re-focus could not be mistaken for "focus never left": `same node? true | focus re-taken? false`, with B's overwrite handler firing. It is now keyed on a caller-independent activation counter that increments whenever `prompt` becomes a new non-null object, regardless of what it names. **The lesson worth more than the fix: a content-derived key is correct only when the content differs, which is exactly the case the test chose.** A test that drives A → B must be asked whether it drove the A → A' that matters.

**FOCUS ON UNMOUNT, AND WHY `useLayoutEffect` IS LOAD-BEARING.** The prompt now restores focus to whatever held it before the mount-time `.focus()`. It must be a LAYOUT effect: React runs a layout effect's cleanup synchronously while tearing down the fiber, **before** the DOM node is detached, so `document.activeElement` there is still meaningful. A passive `useEffect` cleanup runs after the browser has already reset focus to `<body>`, by which point the check could never fire — it would be dead code that reads like a fix. The cleanup closes over the NODE in a local, not `containerRef.current`, because the ref may already be cleared by then; and it restores only if focus is still inside the prompt, so a user who tabbed away is not yanked back.

**THE LIVE REGIONS — and the measurement technique, which is half the finding.** `DocumentPreviewDialog.js` had **zero** live regions before this wave. The trap they walk into: **two consecutive IDENTICAL announcement strings produce NO DOM mutation** — React bails on the unchanged state and the screen-reader user hears nothing. The polite region is protected structurally, because every action announces at save START as well as at completion, so two identical outcomes are never adjacent. **The assertive region was not**: a failure → retry → identical failure sequence produced **0 alert mutations**, measured, not reasoned about. Fixed twice over: the start sentence now carries `{polite, alert}` as ONE object, so clearing the alert is inseparable from announcing a start; and `DriveResultRegion` takes that object as a single `announcement` prop and **THROWS** on a missing or malformed one rather than defaulting to `""`. The default was the real defect — it made "field absent" and "explicitly cleared" indistinguishable at the region, which is why a mutation that deleted the `alert` field entirely left the region's own MutationObserver test GREEN while five `driveMessages` unit tests died. **Record the technique:** bank MutationObserver records from the observer CALLBACK and merge `takeRecords()` at read time; `takeRecords()` alone is unreliable under `await act()` and makes a working region read as broken. Attach the observer AFTER the first message is already rendered, or the free `"" → first message` mutation makes any implementation look healthy. And a paired control matters: the pre-fix caller shape still measures 0, which is what proves the probe is measuring the fix rather than measuring nothing. **A zero-width nonce must NOT be used to defeat the bail** — it was tried in this repo and leaked U+200B into copied text.
